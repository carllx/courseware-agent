# 内容深度与字数防卫协议 (Content Depth & Recovery Protocol)

> **导语**：本协议整合了原 `rule_best_practices.md`、`rule_saturation.md` 和 `rule_drp.md`。它是确保脚本字数达标、知识有密度的唯一真实来源 (SSOT)。

---

## 阶段一：写作前 — 知识饱和度与素材预算

> **LLM 不会算字数，必须依赖外部机制和查缺补漏。**

### 1.1 饱和度底线 
每讲授一个**独立认知目标**，必须具备以下要素（否则禁止写作，先去搜索打底）：
- **精确定义**
- **人文锚点**（案例/故事/生活类推）—— 缺失则强制触发 `narrative_archaeologist` 搜索。
- **正反对照**
- **跨学科桥接**——预算 ≥ 2500字的模块缺失该项则强制搜索。
- **独立案例密度**：模块预算 ≥ 3000 字必须 ≥ 2 个案例；≥ 4500 字必须 ≥ 3 个。

### 1.2 素材预算评估 (Material Budget)
开写前估算可用素材（每段教材原文字数×1.2 + 每条外部网络案例 300字）。
如果估算出素材总字数覆盖率 **< 70%**，**绝对禁止强行进入写作**。必须在写作前优先执行 DRP-L2 网络调研。

### 1.3 搜索预算 (Search Budget)

为防止 Token 雪崩，按模块数声明以下网络请求预算上限（超过预算则退避至 tracking.md）：

| 阶段 | search_web 上限 | read_url 上限 | 说明 |
|:-----|:--------------:|:------------:|:-----|
| 知识检索 (Phase 1) | max(8, 模块数×3) | max(6, 模块数×2) | 按模块数动态缩放 |
| 每模块 DRP 补救 | 5 次 | 3 次 | 单模块补救上限 (ADR-029) |
| 全模块 DRP 总计 | max(15, 模块数×4) | max(10, 模块数×3) | 全脚本补救总额 |

## 阶段二：写作中 — 分段验证 (Segment-by-Segment)

写作必须执行 **“模块骨架 (60%) → 跑 `validate_script_length.py --segment-check` → 读缺口 (deficit) → 精准补足”** 的闭环，绝不允许一口气写完全文再测字数。

### 缺口补救口径指南
| 缺口量级 | 精准补救策略（不要写假套话） |
|:---|:---|
| **< 300 字** | 在现有段落加因果解释和技术细节 |
| **300-800 字** | 新增一个 `[CASE STUDY]` 案例或 `[LIFE CONNECT]` 日常类比 |
| **800-1500 字** | 补充一个完整的正反对照段落（含具体负面后果） + 新增配套 VISUAL |
| **> 1500 字** | 结构级跳崖，检查教学大纲/要求中是否漏提了重大子话题 |

### 2.5 写作中即时密度校验 (Inline Density Check)

> **来源**：`rule_script_clarity.md` §3 信息推进节奏。本节将 §4 阶段四的 IAR 检查前移到写作过程中。

每完成一个 `###` 块，立即执行以下 3 项：

1. **一句话压缩审查**：对每个自然段压缩为 1 句话（≤ 25 字）。
   - 相邻段压缩结果语义重叠 > 80% → 标记 `[PARAPHRASE]` → 合并或删除后者
   - 段内出现「总之/换句话说/也就是说」且可删除 → 删除该句

2. **推进节奏审查**：将每段分类为 A(推进)/S(支撑)/R(冗余)。
   - 冗余段(R) ≤ 1 段/块
   - 连续支撑段(S) ≤ 2 段
   - 首段必须为推进段(A)
   - 末段必须为推进段(A)或 `[TEACHING MOMENT]`

3. **骨架链审查**：提取当前模块所有 H3+H4 标题串联为骨架链。
   - 存在语义重叠的标题对 → 合并或重命名
   - 骨架链不能构成逻辑递进 → 重排或补充标题

> 此三项检查是 §4 IAR 的**前置版本**——在写作阶段即阻截水份，而非等到写完后再回头删减。

## 阶段三：不足回退协议 (Deficit Recovery Protocol - DRP)

当审计或写作检查发现某模块实际字数 **< 预算 80%**，强制按顺序触发以下补救机制，严禁跳级：

### DRP-L1: 教材细节提取
直接针对已有知识库，提取尚未引用的实验数据、反面案例。

### DRP-L1.5: 跨学科维度充实
针对字数逼近达标但深度不足的模块（通常缺口在 500字内），通过 `narrative_archaeologist` 获取哲学、社会学或认知实验支撑。

### DRP-L2: 深度网络调研 (3-Pass Search)
如果 `[STORY TIME]` 为零，让 `narrative_archaeologist` 执行三轮网络深挖（中国本土案例/发展历史/失败教训），采用的搜索素材必须通过 `archive_web.py` 存盘。

### DRP-L3: 结构扩展
知识全数耗尽时，去审视并扩展原始大纲漏掉的平行知识树。

### 🛑 熔断机制 (Circuit Breaker)
1. DRP (L1-L3) 全链路**最多执行 2 轮**。
2. 若第 2 轮完毕依然字数不足 80%，在脚本注释中打上 `<!-- STATUS: blocked -- DRP_EXHAUSTED -->` 并放弃在这个模块注水，继续写下一个模块。

## 阶段四：写作后 — 信息密度反向校验

> **核心原则**：字数达标只是**必要条件**，信息密度达标才是**充分条件**。

### 4.1 信息推进率 (Information Advancement Rate — IAR)

对每个 `##` 模块执行段落级诊断：将每个自然段（以空行分隔）标记为以下三种类型之一：

| 类型 | 定义 | 颜色 |
|:---|:---|:---|
| **推进段 (A)** | 引入新概念/新证据/新案例/新情感冲击 | 🟢 |
| **支撑段 (S)** | 对已引入概念的展开、举例说明、正反对照 | 🟡 |
| **冗余段 (R)** | 换角度重述已有结论 / 总结已知信息 / 过渡套话 | 🔴 |

**IAR = (A + S) / (A + S + R)**

| IAR 值 | 判定 | 处理 |
|:---|:---|:---|
| ≥ 0.85 | ✅ 合格 | 通过 |
| 0.70 - 0.85 | ⚠️ 偏松 | 标记冗余段，建议精简 |
| < 0.70 | ❌ 注水 | **禁止标记 done，强制删减冗余段后重新验证** |

### 4.2 信息密度红线

以下模式触发**自动注水警报**：
1. 同一模块内，连续 2 段以上的"支撑段 (S)"之间没有"推进段 (A)"
2. 模块末尾存在 ≥ 200 字的纯总结/过渡段（非 `[TEACHING MOMENT]` 标签内容）
3. 同一认知目标出现在 ≥ 3 个自然段中，且未引入新维度

## 反模式与严禁行为 ❌

1. ❌ **Agent 自己说 "这段修改后大约增加了 400 字"**：绝对不信，必须调用 `--segment-check` 验证。
2. ❌ **使用 "让我们来看看" 或 "接下来我们学习" 凑字数**：会导致退化（Dilution）报警。
3. ❌ **一气呵成后再用 DRP**：历史证明后期挽救无效，必须分段（Segment）执行闭环验证。
4. ❌ **IAR < 0.70 的模块标记为 done**：信息密度不足与字数不足同等严重。
5. ❌ **连续 ≥ 2 段支撑段(S)之间无推进段(A)**：信息停滞，必须重组或删减。
