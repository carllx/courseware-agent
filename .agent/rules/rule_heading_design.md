# 规则：标题设计协议 (Heading Design Protocol)

> **核心原则**：标题不是目录索引，而是讲者的**提词器**与学生的**记忆锚点**。

## TL;DR

H3 用「四字定性 + 冒号 + 断言陈述句」，直接说出该段落的核心结论。H4 用「四字动宾 + 冒号 + 平行化释义」，给讲者行为暗示。同级 H4 保持字数±2字对齐。禁止名词标签式标题。

---

## §1 理论基础（三层模型）

本规则融合三种经过验证的高绩效演示方法论：

| 模型 | 解决的痛点 | 核心手法 |
|:---|:---|:---|
| **断言-证据** (Assertion-Evidence) | 名词标签让讲者上台"重构句子"导致卡壳 | H3 必须是**完整的判断句**，读题即定调 |
| **动词驱动** (Action-Driven Cues) | 静止名词缺乏"能量感"，讲者不知"接下来做什么" | H4 冒号前四字短语必须以**动词/动宾结构**开头 |
| **平行韵律** (Parallelism & Chunking) | 长短不一的标题增加视读的认知负荷 | 同级 H4 的冒号后释义部分字数差 ≤ 2 字 |

---

## §2 H3（模块级标题）设计规则

**格式**：`### N.X 四字定性词：结论性断言陈述句`

### 2.1 "四字定性词"

冒号前的四个字用于**情感定调与信号分类**，帮助讲者瞬间进入该模块的语调状态。

| 语调 | 适用场景 | 示例 |
|:---|:---|:---|
| 诊断/揭示 | 问题暴露、现象描述 | 现状断言、恶果显现 |
| 分析/追因 | 根因分析、溯源推理 | 溯源诊断、结构解剖 |
| 主张/倡导 | 提出解决方案、价值呼唤 | 伦理主张、范式倡导 |
| 实战/落地 | 工具导入、动手环节 | 实战引擎、技法锻造 |

### 2.2 "断言陈述句"

冒号后必须是**一句完整的判断**，满足以下条件：
- ✅ 包含主语和谓语，能独立成句
- ✅ 直接表达该模块的核心结论（即使只读标题也能把握要点）
- ✅ 具备演讲开场的"定调"能力——讲者读出标题即可自然过渡到正文
- ❌ 禁止名词堆叠（如"认知摩擦与行为模型概述"）
- ❌ 禁止模糊限定（如"关于 XX 的一些思考"）

**示例对比**：

| ❌ 名词标签式（旧） | ✅ 断言式（新） |
|:---|:---|
| 系统性代价：从物理直觉受挫到社会排斥 | 恶果显现：数字化的鲁莽正在造成系统排斥 |
| 根因溯源：导致体验坍塌的四大结构性缺陷 | 溯源诊断：体验坍塌源于组织内部的结构性缺陷 |
| 回归人本：主张包容与克制的设计伦理 | 伦理主张：回归以人为本的包容与数字克制 |

## §3 H4（子节标题）设计规则

**格式**：`#### N.X.Y 四字动宾：平行化释义短语`

### 3.1 "四字动宾"

冒号前四个字必须以**动词或动宾结构**开头，为讲者提供即时行为暗示（Action Cue）。

| 效果 | 动词前置示例 | 可替换的弱名词原型 |
|:---|:---|:---|
| 行为激活 | 粗暴打断、强迫适配 | 粗鲁霸权、机器思维 |
| 因果揭示 | 诱发摩擦、酿成伤害 | 认知摩擦、致命重构 |
| 方案导入 | 引入过渡、抵抗繁殖 | 过渡设计、按钮问题 |
| 诊断命名 | 错置优先、隐形隔离 | 优先级错位、代码思维 |

### 3.2 "平行化释义"

冒号后的释义短语须满足：
- 同一 H3 下所有 H4 的释义部分字数差 **≤ 2 字**
- 语法结构尽量统一（如全部采用"动宾 + 的 + 名词"或"介词 + 名词 + 动词"）
- 读出来具有**节奏对仗感**，便于讲者流畅报菜名

**示例（1.1 下四个 H4 的对齐）**：

| # | 四字动宾 | 释义（8字±1） |
|:---|:---|:---|
| 1.1.1 | 粗暴打断 | 无视语境的情感诱导 |
| 1.1.2 | 强迫适配 | 要求人类用机器思维 |
| 1.1.3 | 邋遢失忆 | 推卸责任的高危界面 |
| 1.1.4 | 苦力转嫁 | 让人类充当数据劳工 |

## §4 金字塔逻辑与 H3 排布

H3 的排列顺序**推荐遵循**叙事递进的逻辑结构（如 SCQA 金字塔），尤其在 ≥8 分钟的教学模块中：

```
1. S (Situation)  — 现状/现象 → "断言式标题：揭开问题表象"
2. C (Complication)— 冲突/根因 → "诊断式标题：揭示结构性缺陷"
3. Q→A (Question→Answer) — 恶果/代价 → "证据式标题：展示系统性后果"
4. A (Answer)      — 方案/伦理 → "主张式标题：呼唤行动与变革"
```

> [!TIP]
> 短模块（<8 分钟）或纯技术参数讲解无需强制套用完整的叙事递进弧线，可直接以论证递进或并列结构组织 H3。详见 `script_format/SKILL.md` §5.1 第一层（叙事启动层）。

> **收敛原则**：一个 `##` 模块下的 H3 数量建议 ≤ 5。如果超过 5，应考虑是否有 H3 可以降级为 H4 并归入更高层的逻辑域。

---

## §5 禁止行为

- ❌ 使用纯名词标签作为 H3 标题（如 `### 认知摩擦`）
- ❌ H4 冒号前使用超过 5 字的短语（失去快速扫描优势）
- ❌ 同一 H3 下的 H4 释义字数差 > 4 字（破坏平行节奏）
- ❌ H3 断言句中使用"关于""浅谈""概述"等弱化词
- ❌ 标题中出现完整英文短语作为主体（英文术语应括注在中文断言之后）

---

## §6 审查检查表

写完或修改标题后，逐项自检：

| # | 检查项 | 标准 |
|:---|:---|:---|
| H1 | H3 是否为完整断言句 | 包含主语+谓语，能独立成句 |
| H2 | H3 冒号前是否为四字定性词 | 属于§2.1列举的语调类别 |
| H3 | H4 冒号前是否以动词/动宾开头 | 具备行为暗示功能 |
| H4 | 同H3下各H4释义字数差 | ≤ 2 字（理想），≤ 4 字（容忍） |
| H5 | H3 排列是否遵循叙事递进（推荐） | 如 S → C → Q/A → A，或其他逻辑递进 |
| H6 | 碎片测试 | 只读所有 H3+H4 能否还原 80% 的叙事主线 |

## §5 标题编号统一 (Heading Numbering Convention)

> **原属**：`rule_heading_numbering.md`（已合并至此）

### ✅ 正确格式
```markdown
### 1.1 感知通道与带宽
### 1.2 前注意力加工
### 2.1 格式塔原则概述
```

### ❌ 禁止格式
```markdown
### 一、感知通道与带宽        ← 中文数字
### 0.1 前注意力加工            ← 0.x 前缀
### 第一节 格式塔原则概述       ← "第X节" 格式
### A. 感知通道                 ← 字母编号
```

### 编号规则
1. 每个 `##` (H2) 模块内的 `###` (H3) 标题从 `1` 开始递增
2. 二级编号使用点号分隔：`1.1`、`1.2`、`2.1`
3. **同一周次内不同模块的编号体系独立**——M01 从 1.x 开始，M02 也从 1.x 开始
4. H4 (`####`) 标题不强制编号，但如使用编号则必须遵循相同格式

### 豁免
- 模块标题本身（`## Module X: 标题`）不受此规则约束
- 引用块内部（`> [CASE STUDY]` 等标签块内的子标题）不受约束
- 用户通过 `<!-- HEADING_OVERRIDE -->` 注释显式标记的标题可豁免
