# 规则：知识前提感知 (Prerequisite Awareness)

> **核心原则**：「学生此刻知道什么，比你想教什么更重要。」——每一个术语、每一层细节的出现时机，必须严格匹配学生在**当前教学进度**下的实际认知水位。如果一个概念在学生的知识地图上还是空白，你就不能像跟同行聊天一样把它随口甩出来。

> **理论基础**：Vygotsky 最近发展区（ZPD）要求教学内容始终位于学生"已知"与"可知"的交界带；认知负荷理论（Sweller）要求避免一次性引入过多陌生元素导致工作记忆崩溃。

## TL;DR

引用任何专业术语前，先问：「学生到了这一页，学过这个词吗？」没学过 → 要么用日常语言替代，要么先用一句话桥接定义。禁止在"预告/导览"段落中堆砌后续周次才会讲解的技术细节。

## §1 知识水位判定协议

### 1.1 三层知识分类

在撰写任何脚本段落时，所有引用的概念/术语/细节必须被归入以下三层之一：

| 层级 | 定义 | 示例（信息可视化 W01 M00 为例） | 处置方式 |
|:---|:---|:---|:---|
| **L1 已知层** | 学生在本段落之前的教学流程中已经被正式讲解过的概念 | "图表"、"数据"（通识词汇） | ✅ 可直接使用，无需铺垫 |
| **L2 可感知层** | 学生虽未正式学过，但凭日常经验可以直觉理解的概念 | "折线图"、"柱状图"、"配色" | ✅ 可直接使用，可选择性加简短说明 |
| **L3 未知层** | 学生在当前进度下完全没有接触过的专业术语或技术细节 | "前注意处理机制"、"格式塔法则"、"知觉均匀性"、"离散色带"、"二元映射矩阵" | ⚠️ 受限使用，必须执行 §1.2 处置 |

### 1.2 L3 术语处置策略

当需要在文本中出现 L3 术语时，**必须且只能**选择以下策略之一：

| 策略 | 适用场景 | 示范 |
|:---|:---|:---|
| **A. 日常语言替代** | 预告/导览/过渡段中提及后续内容 | ❌ "学习前注意处理机制" → ✅ "了解大脑最本能的视觉习惯" |
| **B. 一句话桥接** | 正文中首次引入该术语 | ❌ "格式塔法则在排版中的统治地位" → ✅ "一组被称为格式塔法则的心理学规律——简单说，就是大脑天生会把视觉元素自动归组的本能" |
| **C. 类比锚定** | 术语本身是本段教学目标 | ❌ "知觉均匀性的离散色带" → ✅ "就像音阶上每个音符之间的距离是均匀的，好的色带上每一格颜色的差异也应该让人感觉是等距的" |
| **D. 延迟推出** | 细节不是当前段落的教学目标 | 直接删除该术语，留待后续模块正式讲解时引入 |

### 1.3 "预告型段落"的特殊约束

在课程导览、章节概述、模块预告等**路线图性质**的段落中，约束更加严格：

- ❌ 禁止展开 L3 术语的技术细节（学生连概念都没建立，细节只会制造混乱）
- ✅ 只描述学生**将获得的能力或体验**，而非将学到的术语清单
- ✅ 用**问题驱动**代替术语罗列：与其说"我们将学习 X 机制"，不如说"我们会弄清楚为什么 Y 现象会发生"

**正例**：
> 你们会了解到大脑最本能的**视觉习惯**，弄清楚到底是什么规律决定了一张图表能不能让人在零点几秒内毫不费力地看懂。

**反例**：
> 你们会极其细致地学到人类视网膜的"前注意处理机制"，了解格式塔法则在图表排版中犹如重力法则一般的统治地位，弄清楚为什么要死死避免使用刺眼的彩虹色表而必须换用具有知觉均匀性的离散色带。

## §2 知识前提扫描流程

### 2.1 写作时扫描（/write Phase 2）

在撰写每个 `###` 块时，执行以下前置检查：

1. **列出本段将出现的所有专业术语**（含英文缩写）
2. **逐一检查每个术语的知识水位**：
   - 向上回溯当前脚本文件中该术语是否已被正式定义
   - 检查当前模块前的已完成模块是否已讲解过（参考 `course.yaml` 的 steps 结构）
   - 检查该术语是否属于 L2 日常可感知层
3. **对所有 L3 术语执行 §1.2 处置**
4. **单段 L3 术语限额**：同一自然段内首次出现的 L3 术语 ≤ 2 个（超出时必须拆段或延迟）

### 2.2 审计时扫描（/audit Part B）

在 Part B Deep Listen 阶段，增加以下检查维度：

- **术语突袭检测**：标记任何在 30 字内连续出现 ≥ 3 个 L3 术语的段落为 `[VOCAB_OVERLOAD]`
- **铺垫断裂检测**：标记任何 L3 术语在其**首次出现位置**之前 300 字内缺少定义/桥接/类比的情况为 `[PREREQUISITE_GAP]`

## §3 跨模块知识累积追踪

### 3.1 模块进度意识

撰写 Module N 的脚本时，Agent 必须意识到学生仅掌握 Module 0 至 Module N-1 已正式讲授的知识。具体操作：

- 如果引用了后续模块的内容 → 必须使用策略 A（日常语言替代）或策略 D（延迟推出）
- 如果引用了本模块前面部分已讲解的概念 → 可直接使用（L1）

### 3.2 跨周次引用

引用非当前周次的概念时，采用**遗忘衰减模型**（基于 Ebbinghaus 遗忘曲线的简化工程版本）替代简单的"已教/未教"二分法：

| 距上次正式讲授的周数 (ΔW) | 分类 | 处置方式 |
|:---:|:---|:---|
| ΔW = 0（本周内跨模块引用） | L1 已知层 | 可直接使用，无需铺垫 |
| ΔW = 1-2（上周/上上周） | L1 已知层 | 核心概念可直接使用；边缘概念加一句极简回顾（"还记得第 X 周的 Y 吗？"） |
| ΔW = 3-4（3-4 周前） | L2 可感知层 | 必须用一句话重新激活定义（"我们在第 X 周学过的 Y——也就是 [一句话定义]"） |
| ΔW ≥ 5（5 周以上） | L3 未知层 | 视同首次出现，执行 §1.2 完整处置策略 |
| W(N+1) 及以后（未教授） | L3 未知层 | 严格执行 §1.2 |

> [!IMPORTANT]
> **为何不用"周次号"武断判定？** 专长反转效应（Expertise Reversal Effect, Kalyuga et al., 2003）指出，对已掌握概念的过度解释反而会增加外在负荷。但我们的课件是静态媒介，无法实时检测学生掌握程度。因此采用"距离衰减"作为折衷方案：距离越远，遗忘概率越高，铺垫力度越大。
>
> **约束**：此模型仅适用于静态课件场景。如果未来接入自适应学习系统（可实时检测学生掌握度），应替换为数据驱动的动态判定。

## §3.3 逻辑层知识不对称检测 (Logic-Level Asymmetry)

> **理论基础**：Shulman PCK（教学内容知识）指出，专家的知识诅咒不仅体现在术语使用上，更体现在"跳过了自己学习时经历过但已遗忘的中间推理步骤"。这种隐蔽的逻辑跳跃比术语障碍更难被发现，也更容易导致学生"听完后感觉每个字都认识但串不起来"。

### 3.3.1 因果桥检测

当脚本从**理论 A 过渡到理论 B**时（尤其是声称二者具有上下游、因果、互补关系的场景），检查：

| 检查项 | 合格标准 | 违规标记 |
|:---|:---|:---|
| 是否有显式的因果桥接语 | 存在"之所以 B 成立，是因为 A 揭示了…"或等效推理句 | `[LOGIC_LEAP]` 🔴 |
| 理论关系是否仅为断言 | 不能仅靠"如果说 A 是 X，那么 B 就是 Y"式类比代替推理 | `[LOGIC_LEAP]` 🔴 |
| 学生是否已内化理论 A | 理论 A 必须在本段之前被充分讲解（≥ 1 个案例 + 1 个定义） | `[PREMATURE_BRIDGE]` 🟡 |

**处置策略**：补充 1-2 句"逻辑桥接语"，用学生已理解的概念搭建台阶。

**示例**（以 M03 为基准）：

```
❌ "如果说 Norman 的鸿沟理论是诊断症状的听诊器，那么 Cooper 的模型论就是揭示病因的解剖刀。"
   → 问题：用类比替代了推理。学生不知道"为什么鸿沟是症状而模型是病根"。
   → 标记：[LOGIC_LEAP]

✅ "Norman 告诉我们'血流在哪断了'——用户卡在执行或评估环节。但为什么会断？
    Cooper 追问了一个更深层的问题：造成这些断裂的根源，是工程师构建的系统
    和用户脑中的世界根本就不在同一个频道上。"
   → 修正：先复述 A 的结论，再用"但为什么"承接，显式推理出 B 的必要性。
```

### 3.3.2 审计时逻辑层扫描

在 `/audit` Part B-7 PCK 知识不对称诊断中，执行以下检查：

- **理论叠加检测**：在同一 `##` 模块中出现 ≥ 2 个独立理论框架（如 Norman + Cooper + Craik）时，检查每对相邻理论之间是否存在显式因果桥
- 缺失者标记 `[LOGIC_LEAP]`，严重度 🔴

## §3.4.3 正文段落级"秒懂"检测（写作时强制）

> **理论基础**：Pinker 知识诅咒 + Oppenheimer 加工流畅度——Agent（和专家教师）天然无法判断"什么对新手来说是难的"，因此必须通过外部结构化产出来暴露盲点。

在 `/write` Phase 2 的 Phase C 中，Agent 必须为每个模块输出 **Clarity Ledger**（清晰度台账）——将所有加粗锚词翻译为 DMA 学生秒懂的白话版本。

**Clarity Ledger 是模块 `done` 标记的前置条件**，与字数验证、视觉密度检查同等权重。

此外，`validate_script_length.py` 的 `detect_dilution()` 函数中新增了 `ABSTRACTION_MARKERS` 词表自动检测（v3），对"数据节点"、"算法吞吐"、"二元映射"等 DMA 学生无法具象化的技术隐喻进行物理拦截，输出 `[ABSTRACT]` 标签。

详见 `write_phase2_compose.md` Phase C 费曼画板探针部分。

## §4 禁止行为

- ❌ 在预告/导览段落中罗列 ≥ 3 个学生从未接触过的专业术语
- ❌ 在同一自然段内堆砌 ≥ 3 个首次出现的 L3 术语而不提供任何日常语言桥接
- ❌ 假设学生"应该知道"某个未被正式讲授的专业概念（即便该概念在其他课程中可能涉及）
- ❌ 为了炫耀学术深度而在非教学目标段落中强行引入 L3 术语
- ❌ 用"我们后面会详细讲"作为跳过铺垫的借口——如果提到了，就必须给出至少一句可感知的定义
- ❌ 在两个理论框架之间仅用类比式断言代替显式因果推理（§3.3）
- ❌ 使用学生低概率经验域的类比而不提供经验桥接（§3.4）
