# 规则：视觉块空间放置约束 (Visual Block Placement Guard)

> **核心原则**：逐字稿是"幻灯片驱动的演讲流"。两个 `[VISUAL]` 块之间必须存在实质性叙事文本，否则教师将在台上连续切换两张 PPT 而无言可说，切断演讲的呼吸节律。

## TL;DR

- 相邻 VISUAL 块之间至少 **80 字**叙事文本
- 插入前必须执行**上下碰撞检测**
- 密度饱和区禁止强插，应放弃或合并

---

## §1 最小叙事间距 (Minimum Narrative Gap)

任意两个相邻的 `> [VISUAL]` 块之间，必须存在 ≥ 80 字的非标签、非注释的教师叙事文本（Speech）。

**计算方法**：从上方 VISUAL 块的最后一行（`> **Text**: ...`）到下方 VISUAL 块的第一行（`> [VISUAL]`）之间，统计纯文本字符数（排除空行、HTML 注释、其他标签块如 `[CASE STUDY]`、`[TEACHING MOMENT]` 等）。

| 间距 | 判定 | 处置 |
|:---|:---|:---|
| ≥ 80 字 | ✅ 合格 | 允许插入 |
| 40-79 字 | ⚠️ 警告 | 允许但需在诊断报告中标注理由 |
| < 40 字 | 🔴 禁止 | 不得插入，必须选择 §3 的处置策略 |

## §2 插入前碰撞检测 (Pre-Insert Collision Check)

在确定插入点后、执行文件编辑**之前**，Agent 必须完成以下三步扫描：

1. **向上扫描**：从插入点向上搜索最近的 `> [VISUAL]` 块，记录其结束行号和间距字数
2. **向下扫描**：从插入点向下搜索最近的 `> [VISUAL]` 块，记录其起始行号和间距字数
3. **双向评估**：上方间距和下方间距必须**同时**满足 §1 的最小间距要求

> [!IMPORTANT]
> 碰撞检测结果必须在诊断报告（`mXX_visual_gap_report`）中以"防堆叠碰撞检测"节的形式显式输出，确保人类审核者可追溯。

## §3 密度饱和处置策略

当碰撞检测判定为 🔴 禁止时，Agent 应按以下优先级选择处置策略：

1. **放弃插入（Abort）**：判定该区域视觉密度已饱和，无需额外图示。在诊断报告中标注"密度饱和，跳过"。
2. **合并替换（Merge）**：如果新图比现有图更贴合教学意图，可**替换**（而非追加）现有 VISUAL 块。需在报告中说明替换理由。
3. **重定位（Relocate）**：将新图移至同一小节内满足间距要求的其他位置（如章节标题之后、段落起始处）。需在报告中说明重定位理由。

## §4 审计检查点

`/audit` 执行时，对脚本中所有相邻 VISUAL 块对进行扫描：

1. 是否存在间距 < 80 字的 VISUAL 块对 → 🔴 标记为堆叠违规
2. 是否存在间距 < 40 字的 VISUAL 块对 → 🔴 强制修复（优先级：Critical）

## 问题溯源记录

**发现于**：2026-05-09，交互产品开发 W03 视觉审查任务。
**现象**：Agent 在补全视觉缺口时，将新 VISUAL 块插入到已有 VISUAL 块的紧邻上方/下方，导致两张 PPT 背靠背出现，教师无言可说。
**根因**：规范体系覆盖了视觉块的内容（WHAT: `rule_visual_generation.md`）、格式（HOW: `script-format` §3）、密度（WHEN: `script-format` §6），但完全缺失空间放置（WHERE）维度的约束。
