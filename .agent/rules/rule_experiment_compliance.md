# 规则：实验规则硬性合规 (Experiment Compliance)

**定义**：本规则旨在彻底剥离“平时练习(Practice)”与“正式大实验(Experiment)”的边界，并明确所有涉及 `course.yaml` 的 `experiments` 数组的合法排布。

## 1. 实验与练习的边界 (Practice vs. Experiment)

*   **平时练习 (Practice)**：随堂练习或课后小作业，由 `/design_practice` 工作流处理，输出为 `practice.yaml` 和 `practice_guide.md`，**不需要**写正式的实验报告。
*   **正式大实验 (Experiment)**：大型综合实验，由 `/design_experiment` 工作流处理，必须走生成“实验指导书”与“实验报告_学生模板”的流程，**必须**要求学生提交正式的实验报告。
*   **禁忌**：禁止在表述上将“作业”混淆为“大实验”，作业属于 Practice 的范畴。

## 2. 实验步骤与要点占位约束 (Step Enforcement)

在执行 `/design_experiment` 生成实验指导书与实验报告模板时，强制遵守以下映射与阻断规则：
1. **实验指导书**必须包含明确且详细的“步骤与要点”示范（Step-by-step demonstrations）。
2. **实验报告模板**中必须为指导书中的每一步骤提供一一对应的“实验内容”占位符，引导学生填写执行过程与截图。

**🚨 强制源头拦截与数据补全：**
- **源头拦截**：在生成或提示教师填写 `exp_{id}.yaml` 时，**必须强制要求提供 `steps` (步骤拆解)、`method_theory` (实验方法/原理) 及其对应的 `guide_text` (指导书正文)**。决不允许静默跳过或留空。
- **历史数据补全**：若你发现历史旧数据中存在部分实验缺失 `steps`（例如仅有空的步骤数组），请务必利用大语言模型的能力结合课程内容进行**草案补写**，或明确中断流程要求人类用户提供内容，**然后再执行教务生成脚本**，以免触发底层级报错。

## 3. 实验文档结构与格式铁律 (Docx & Output Rules)

结合教务最新 `Spec_Experiment.md` 规范，生成的实验指导书与实验报告模板必须遵循以下硬性结构：

1. **节标题格式**：
   - 实验 1-3：`实验一/二/三 XXXX`（必须使用中文序数 + 实验名称）。
   - 实验 4（期末综合项目）：`综合项目 XXXX`（固定前缀，**禁止使用“实验四”**）。
2. **正文区块构成**：
   - 必须包含四节正文：一、实验目的 (`objectives`)；二、实验设备与环境 (`equipment`)；三、实验要求 (`requirements`)；四、实验步骤与要点 (`methods`)。
   - **全面取消思考题**：不再保留原先的“六、思考题”模块。相关反思与总结统一体现在报告封面附加的“五、实验结果分析”中。
3. **分发模式字段保护（留白协议）**：
   - 实验报告模板是分发给学生填写的，在输出时程序只预填：项目名称、学院名称、专业班级、授课教师、日期、地点以及前三节正文。
   - **必须强制留白**：学生学号、学生姓名、同组人员、第四节“实验内容（步骤）”以及第五节“实验结果分析”。这些字段必须赋值为空，绝不允许从大纲上下文中意外读取并预填。

## 3. 实验数量与类型排布矩阵

基于教务的硬性规定，所有课程的正式实验（`course.yaml` 的 `experiments[]` 字段）只能使用 **设计性** 和 **综合性** 这两种枚举类型。不接受验证性、演示性等其余类型。

不同**实践总学时 (practice hours)** 对应的排布矩阵如下，所有新增与审查操作必须精准对齐此数量，不能多也不能少：

### 40 实践学时课程铁律
*   **总次数**：必须恰好 **3 次**正式实验。
*   **排布顺序**：
    1. 实验1：设计性
    2. 实验2：设计性
    3. 实验3：综合性（必须是期末最后的大实验）

### 60 实践学时课程铁律
*   **总次数**：必须恰好 **4 次**正式实验。
*   **排布顺序**：
    1. 实验1：设计性
    2. 实验2：设计性
    3. 实验3：设计性
    4. 实验4：综合性（必须是期末最后的大实验）

### 敏捷迭代与微型 Sprint 的降维打包 (Agile Packaging Strategy)
针对《交互产品开发》、《信息可视化》等现代产品开发课程，如果课程设计包含了 5 个或以上的微型敏捷迭代（Sprint）：
**绝对禁止**打破 3 个或 4 个大实验的数量限制。Agent 必须将这些微型迭代合并、打包为上述规定的 3 或 4 个大模块。例如，将“JTBD 挖掘”与“用户画像”打包为【实验一】，以此来适应底层死板的 Schema 矩阵。

## 4. 触发机制与兜底检查

1. 当执行 `/audit` 或 `/audit_courseyaml` 时，需根据对应规则（F6, F17）核对 `experiments` 数组是否违背了 40/60 学时矩阵。
2. 不论任何学时配置，**综合性实验只能有且仅有 1 个，并且必须排在实验数组的最后面。**
