# 规则：脉络清晰度与反注水 (Script Clarity & Anti-Padding)

> **核心原则**：「不要"背"稿，要"理"稿」——脚本必须具备**一扫即知脉络**的结构透明度。如果演讲者无法在 30 秒内从脚本中提取出模块的论证骨架，说明脚本的结构表达力是失败的。
>
> **理论基础**：认知负荷理论（Sweller）要求将外在负荷(Extraneous Load)在写作阶段即被消除；Miller (1956) 工作记忆分块理论（Chunking，"The Magical Number Seven, Plus or Minus Two"）要求将信息组织为 4±1 个认知单元（Cowan, 2001 修订）；线索依赖记忆(Cue-dependent Memory)要求每段有且仅有一个「灵魂锚词」触发回忆。

## TL;DR (预检阶段专用)

每段只做一件事。相邻段压缩后语义重叠 > 80% = 违规。每 `###` 块首段和末段必须是推进段(A)。H3/H4 标题串联后必须构成无死环的逻辑骨架链。

## §1 脉络骨架测试 (Skeleton Scanability Test)

> **来源**：认知分块与关键词锚定法（研究报告 §方法3）的工程化落地。

### 1.1 骨架链提取规则

对每个 `##` 模块，提取所有 `###` 和 `####` 标题 → 串联为一行骨架链。

**骨架链格式**：
```
### 1.1 [标题] → ### 1.2 [标题] → #### 1.2.1 [标题] → ### 1.3 [标题]
```

### 1.2 骨架自洽性检查

骨架链必须满足以下条件：

1. **逻辑递进**：相邻节点之间存在明确的逻辑关系（因果/递进/转折/并列），不能出现「说完 A 突然跳到毫无关联的 B」
2. **无死环**：如果两个标题可以被压缩为同一句话（即它们描述的是同一件事的不同措辞），后者必须被删除或与前者合并
3. **冷热叙事角色可分配**：至少能将一个节点标记为 C🔥（冲突/痛点）、至少一个标记为 A🧊（结论/解答）

### 1.2.1 分块密度约束 (Chunking Density)

> **理论基础**：Miller (1956) "The Magical Number Seven" — 工作记忆一次可处理的独立信息块为 4±1 个（Cowan, 2001 修订）。

对每个 `##` 模块，统计 `###` (H3) 的数量：
- **≤ 5 个** → ✅ 合格（在工作记忆容量范围内）
- **6-7 个** → ⚠️ 建议合并或降级部分 H3 为 H4
- **≥ 8 个** → ❌ 强制重组（学生无法在脑中同时保持 ≥8 个并列顶层概念，必须引入层级化分组）

> **注意**：此约束基于 Miller/Cowan 的工作记忆分块理论，而非 Hick 定律（Hick 定律适用于选择反应时间场景，不直接适用于知识理解场景）。

### 1.3 写作时自检

写完每个 `##` 模块后，执行以下自检：
1. 提取骨架链
2. 删除所有正文，只看标题——能否还原论证走向？
3. 如果不能 → 标题需要重写（参见 `rule_heading_design.md`）
4. 检查 H3 数量是否符合 §1.2.1 分块密度约束

### 1.5 正文级主线检查 (Body-Level Mainline Check)

即使 H3 标题序列本身递进合理，正文内容仍可能偏离主线。对每个 `###` 块：

1. 提取该 H3 的骨架支撑点（标题所承诺要论证的内容）
2. 扫描正文中的完整论述段落（≥3 句）
3. 如果某段论述与该 H3 的骨架支撑点**无直接关联** → `[TANGENT_INSERTION]` 🟡

> **处置**：将旁支段落移至其语义归属的 H3 下，或降级为 `[DID YOU KNOW]` 标签块。

## §2 一段一事规则 (One Paragraph, One Job)

> **来源**：反换角度重复（narrative_standards_guide §7.5）的强化执行版。

### 2.1 修订模式保留红线 (Revision Preservation Floor)

> **适用场景**：当 Agent 对**已有的**逐字稿执行修订（术语替换、冗余合并、降维重写等），而非从零撰写时。
>
> **设计理据**：LLM 面对"精简/简化"指令时存在结构性偏差——倾向于从零重写而非原地编辑，极易将"脱水去重"误操作为"脱骨去肉"，导致教学叙事正文被大面积删除。

**强制约束**：
- 修改后的正文字数 **≥ 原始正文字数的 75%**（正文 = 非标签块、非注释、非标题的纯叙事文本）
- **禁止**使用 `write_to_file(Overwrite=true)` 覆盖已有脚本整文件。必须使用 `replace_file_content` 或 `multi_replace_file_content` 进行原地编辑
- 修改完成后**必须**执行字数对比验证并向用户报告保留率
- 所有 `> [VISUAL]`、`> [ACTIVITY]` 等结构标签块的数量 **≥ 修改前的数量**（只允许增加，不允许减少）

### 2.2 一句话压缩测试

对每个自然段执行「一句话压缩测试」——将该段核心信息压缩为 1 句话（≤ 25 字）。

### 2.3 重叠检测

**相邻段检测**：如果相邻两段的压缩句语义重叠 > 80%，执行以下判定：
- 两段能否用**不同的 H4 标题**命名？如果可以 → 保留，但必须添加差异化的 H4 标题标明维度
- 如果无法起出差异化标题（需要「费力辨认」维度差异）→ 后者为冗余段，**合并至前者或删除**

**同段内检测**：如果段内出现以下信号词，且删除该句后不影响信息完整性 → **删除该句**：
- 「总之」「换句话说」「也就是说」「简单来讲」「归根结底」

### 2.4 段落职能唯一性

每个自然段必须承担且仅承担以下职能之一——禁止混搭：

| 职能 | 标志 | 错误示例 |
|:---|:---|:---|
| **引入新概念** | 首次出现术语/定义 | 在定义段内夹杂未经铺垫的案例细节 |
| **展开案例** | 人名/时间/地点/数据 | 在案例段内插入抽象理论总结 |
| **论证支撑** | 因为/所以/证据表明 | 在论证段内混入新的独立案例 |
| **过渡衔接** | 独立成段，30-60 字 | 将过渡句嵌入上一段末尾 |
| **教学金句** | `[TEACHING MOMENT]` | 在金句段后继续展开论述 |

### 2.5 极简骨架模板 (Lean Skeleton Template)

> **适用场景**：当模块的主要听众为非工程背景学生（如 DMA 专业）时，每个核心知识点应严格遵循以下三步骨架，防止"绕弯子"式的冗长论述。参见 `rule_dma_course_design.md` §1.3 语感基调宣言。

**「一招鲜」三步法**：

| 步骤 | 长度上限 | 内容 | 示例（Tidy Data 概念） |
|:---|:---|:---|:---|
| ① **一句白话定义** | ≤ 40 字 | 用生活语言一句话说清楚是什么 | "整洁数据就是：每列只放一种信息，每行只记一条记录。" |
| ② **一个生活化案例** | ≤ 150 字 | 一个 DMA 学生秒懂的日常隐喻或真实故事 | "想象你整理衣柜：上衣挂上层、裤子挂下层、袜子放抽屉。混着堆就找不到。" |
| ③ **一张锚定图** | 1 个 [VISUAL] 块 | 配一张图固化认知 | 对应的 Slide 展示整理前后的对比 |

**约束**：
- 同一概念在全文中**只展开一次**（§2.2 重叠检测的增强版）
- 如果发现同一概念出现了第二次展开 → 后者必须被删除或合并至首次出现处
- 三步之外的补充信息（如历史背景、哲学延展）仅在 `[DID YOU KNOW]` 或 `[PHILOSOPHY]` 标签内展开，**不进入正文骨架**

## §4 结构断字校验 (Structural Paragraphing)

> **来源**：冷热叙事引擎（研究报告 §方法1）——冷热切换点就是天然的记忆分界线（Von Restorff 效应）。

### 4.1 冷热边界即段落边界

当叙事温度发生转换时（从🧊冷到🔥热，或反之），**必须断段**（插入空行）。温度转换信号：
- 🧊→🔥：从精确定义/结论切换到案例/故事/痛点
- 🔥→🧊：从情感冲击切换到教学金句/技术结论
- 任一方向的切换处不得合并为同一段

### 4.2 视觉锚点即断字锚

每个 `> [VISUAL]` 块**前后必须有段落间隔**（空行）。`[VISUAL]` 块之后的首段必须包含指示性词汇锚定画面（如图/左侧/屏幕上），不得紧跟与画面无关的论述。

### 4.3 禁止行为

-   ❌ 在同一自然段内完成「引入定义 + 展开案例 + 给出结论」的全套流程——这是压缩，不是简练
-   ❌ `###` 块以「我们刚才讲了…/回顾一下…」开头——前一块的内容已经讲完，读者不需要被提醒
-   ❌ 连续 3 个 `###` 块内部结构完全相同（如全部是「定义→案例→结论」三段式）——结构雷同导致认知疲劳，应变换节奏
