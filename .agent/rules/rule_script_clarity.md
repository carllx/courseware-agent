# 规则：脉络清晰度与反注水 (Script Clarity & Anti-Padding)

> **核心原则**：「不要"背"稿，要"理"稿」——脚本必须具备**一扫即知脉络**的结构透明度。如果演讲者无法在 30 秒内从脚本中提取出模块的论证骨架，说明脚本的结构表达力是失败的。
>
> **理论基础**：认知负荷理论（Sweller）要求将外在负荷(Extraneous Load)在写作阶段即被消除；线索依赖记忆(Cue-dependent Memory)要求每段有且仅有一个「灵魂锚词」触发回忆。

## TL;DR (预检阶段专用)

每段只做一件事。相邻段压缩后语义重叠 > 80% = 违规。每 `###` 块首段和末段必须是推进段(A)。H3/H4 标题串联后必须构成无死环的逻辑骨架链。

## §1 脉络骨架测试 (Skeleton Scanability Test)

> **来源**：认知分块与关键词锚定法（研究报告 §方法3）的工程化落地。

### 1.1 骨架链提取规则

对每个 `##` 模块，提取所有 `###` 和 `####` 标题 → 串联为一行骨架链。

**骨架链格式**：
```
### 1.1 [标题] → ### 1.2 [标题] → #### 1.2.1 [标题] → ### 1.3 [标题]
```

### 1.2 骨架自洽性检查

骨架链必须满足以下条件：

1. **逻辑递进**：相邻节点之间存在明确的逻辑关系（因果/递进/转折/并列），不能出现「说完 A 突然跳到毫无关联的 B」
2. **无死环**：如果两个标题可以被压缩为同一句话（即它们描述的是同一件事的不同措辞），后者必须被删除或与前者合并
3. **冷热叙事角色可分配**：至少能将一个节点标记为 C🔥（冲突/痛点）、至少一个标记为 A🧊（结论/解答）

### 1.3 写作时自检

写完每个 `##` 模块后，执行以下自检：
1. 提取骨架链
2. 删除所有正文，只看标题——能否还原论证走向？
3. 如果不能 → 标题需要重写（参见 `rule_heading_design.md`）

## §2 一段一事规则 (One Paragraph, One Job)

> **来源**：反换角度重复（narrative_standards_guide §7.5）的强化执行版。

### 2.1 一句话压缩测试

对每个自然段执行「一句话压缩测试」——将该段核心信息压缩为 1 句话（≤ 25 字）。

### 2.2 重叠检测

**相邻段检测**：如果相邻两段的压缩句语义重叠 > 80%，执行以下判定：
- 两段能否用**不同的 H4 标题**命名？如果可以 → 保留，但必须添加差异化的 H4 标题标明维度
- 如果无法起出差异化标题（需要「费力辨认」维度差异）→ 后者为冗余段，**合并至前者或删除**

**同段内检测**：如果段内出现以下信号词，且删除该句后不影响信息完整性 → **删除该句**：
- 「总之」「换句话说」「也就是说」「简单来讲」「归根结底」

### 2.3 段落职能唯一性

每个自然段必须承担且仅承担以下职能之一——禁止混搭：

| 职能 | 标志 | 错误示例 |
|:---|:---|:---|
| **引入新概念** | 首次出现术语/定义 | 在定义段内夹杂未经铺垫的案例细节 |
| **展开案例** | 人名/时间/地点/数据 | 在案例段内插入抽象理论总结 |
| **论证支撑** | 因为/所以/证据表明 | 在论证段内混入新的独立案例 |
| **过渡衔接** | 独立成段，30-60 字 | 将过渡句嵌入上一段末尾 |
| **教学金句** | `[TEACHING MOMENT]` | 在金句段后继续展开论述 |

## §2.5 修辞通胀检测 (Rhetorical Inflation Check)

> **来源**：M00 课程导览复盘——IAR 在段落粒度有效但无法拦截句子粒度的修辞膨胀。

### 2.5.1 定义

当同一句话可以用 ≤ 50% 的字数表达相同信息量时，该句存在**修辞通胀**。

### 2.5.2 检测信号

| 信号类型 | 触发条件 | 示例 |
|:---|:---|:---|
| **形容词堆砌** | 连续 ≥ 3 个形容词/副词修饰同一名词或动词 | "极其华丽赛博的动效" → "赛博风动效" |
| **程度词叠加** | "极其/极度/毫无保留/彻底/死死/绝对" 同一段出现 ≥ 3 次 | "绝对不需要…死死记住…极度苛刻地" |
| **军事/战争隐喻过载** | 同一 `###` 块内 ≥ 3 个战争/末日比喻 | "核爆/万劫不复/深渊/镇压/炮灰/提线木偶" |
| **同义反复** | 前后两个分句用不同修辞说同一件事 | "毫无保留地引入…颠覆性全新…" = 双层强调同义 |

### 2.5.3 处置

检测到以上任一信号时，标记该句/段为 `[RHETORIC_INFLATION]`，执行压缩：
1. **保留信息骨架**：提取该句的核心动词和宾语
2. **删除修饰枝叶**：移除不改变信息量的形容词、程度副词和隐喻
3. **压缩后自验**：压缩版是否丢失了任何**不可还原的信息**？如果没有 → 采用压缩版

## §2.7 论证模式饱和度检测 (Argument Pattern Saturation)

> **来源**：Sweller 冗余效应 + Kalyuga 专长反转效应——同一论证模式重复 ≥3 次后，后续出现从"建构理解的脚手架"反转为"增加外在认知负荷的噪音"。
> 
> **与 §2.2 的区别**：§2.2 检测"两段说同一件事"（**内容重复**），§2.7 检测"多段用同一种方式论证不同的事"（**模式重复**）。两者互补。

### 2.7.1 论证骨架提取

对当前 `##` 模块中的每个案例/论证段落，提取其**句式骨架**——即论证的逻辑结构模板。

**常见论证骨架类型**：

| 骨架代号 | 结构描述 | 典型句式 |
|:---|:---|:---|
| **A-vs-B** | 用户视角 vs 机器视角对比 | "用户认为 X → 实际是 Y → 所以操作 Z 是无效的" |
| **BEFORE-AFTER** | 旧版 vs 新版产品对比 | "十年前的 X 需要… → 今天的 X 只需要…" |
| **DEFINITION-EXAMPLE** | 先定义后举例 | "X 是指… → 比如当你…" |
| **PAIN-REVEAL** | 先展示痛点后揭示原因 | "你一定经历过 X → 真正的原因是 Y" |

### 2.7.2 饱和度检测

1. 统计同一骨架类型在当前 `##` 模块中出现的次数
2. **≥ 3 次** → 标记 `[PATTERN_SATURATION]` 🟡

### 2.7.3 处置策略（分级）

| 出现次数 | 处置 |
|:---|:---|
| 第 1-2 次 | ✅ 保留完整展开 — 选择最有教学冲击力的 2 个案例 |
| 第 3 次 | 压缩为**一句话概要**（如"类似地，恒温器也存在同样的阀门-开关错位"） |
| 第 4+ 次 | 降级为**课后延伸材料**或直接删除 |

### 2.7.4 写作时自检

每完成一个 `##` 模块的全部案例后，执行以下自检：
1. 列出本模块所有案例段落的论证骨架
2. 检查是否有 ≥ 3 个案例使用了相同的骨架类型
3. 如果有 → 评估哪 2 个案例最具冲击力并保留完整展开，其余压缩或删除

## §2.8 LLM 隐性膨胀反模式 (LLM Stealth Inflation Anti-Patterns)

> **来源**：对 LLM 产出逐字稿的实证分析——识别出 7 种能**穿透现有 IAR / 修辞通胀检测**的隐蔽膨胀模式。
>
> **核心洞察**：LLM 由于自回归生成机制和 RLHF 安全训练，具有系统性的"多说一点更安全"倾向。这些膨胀不会被标记为 R 类冗余段（因为每段技术上都含有"新信息"），但**对教师记忆负担和学生理解效率构成实质性损害**。

### 2.8.1 压缩比测试（统一检测手段）

对每个自然段执行：
1. 将该段压缩为**最少字数的等效表述**（保留全部不可还原的信息量）
2. 计算 **压缩比 = 压缩后字数 / 原文字数**
3. **压缩比 < 0.4**（原文可被压缩掉 60% 以上而不损失信息）→ 标记 `[INFLATION]` 🟡

> [!TIP]
> 压缩比测试是**总指标**。以下 7 种子模式是**具体触发信号**，帮助定位膨胀的根因并给出精准处置。

### 2.8.2 七种子模式

| # | 模式名称 | 触发信号 | 标记 | 处置 |
|:---:|:---|:---|:---|:---|
| P1 | **结论展开冗余** | 金句/结论句之后，紧跟的段落仅用不同措辞重新解释该结论，无新信息 | `[CONCLUSION_ECHO]` | 删除展开段，金句本身已经足够 |
| P2 | **三段式信封** | `###` 块以"让我们来看…"式预告开头，以"综上/总之"式小结结尾 | `[ENVELOPE_PADDING]` | 删除预告句和总结句，直接进入正文 |
| P3 | **修辞能量过载** | 同一句中 ≥ 2 个极端程度词（"完全/彻底/死命/剧烈/极其"），或同一段中 ≥ 3 个 | `[ENERGY_OVERLOAD]` | 保留 1 个最精准的强度词，其余降级为中性表述 |
| P4 | **对称强迫症** | 两个案例使用完全对称的段落结构，但其中一个案例的信息量仅需 1/3 的篇幅 | `[SYMMETRY_BLOAT]` | 将信息量较少的案例压缩为 1 段或 1 句 |
| P5 | **定义回声** | 同一核心定义在模块内被 ≥ 3 次用不同措辞重述（即使分布在不同案例中） | `[DEFINITION_ECHO]` | 首次完整定义，后续引用时仅用 ≤ 8 字的回指短语（"这种'管用即正义'的特性"） |
| P6 | **脚手架残留** | 段落中存在"写作时帮助进入状态"的背景铺垫句，但该铺垫对读者理解核心概念无贡献 | `[SCAFFOLD_RESIDUE]` | 删除铺垫句，从第一个有信息量的句子开头 |
| P7 | **叙事过度戏剧化** | 案例的情景设置部分字数 > 核心论证部分字数（"戏剧布景比戏本身还长"） | `[DRAMATIZATION_BLOAT]` | 情景设置压缩至 ≤ 1 句（≤ 25 字），将篇幅让给论证 |

### 2.8.3 各模式详解与实例

**P1: 结论展开冗余 (Conclusion Echo)**

```
❌ 原文（3 层同义叠加）：
"鸿沟是表象，模型错位才是病根。
 当执行鸿沟出现时，往往是因为产品的表现模型太靠近实现模型——
 系统强迫用底层的工程术语和用户对话……
 Norman 的鸿沟是临床上的症状诊断工具，告诉你'血流在哪断了'；
 而 Cooper 的三种模型则是病理学框架，从基因层面告诉你'为什么会断'。"
→ 第 1 句是结论，第 2-3 句是展开，第 4 句是用新比喻再述 → 压缩比 < 0.3

✅ 压缩版：
"鸿沟是表象，模型错位才是病根。Norman 告诉你'血流在哪断了'，
 Cooper 则追问'为什么会断'——答案是工程师的系统和用户脑中的世界
 根本不在同一个频道上。"
→ 保留了结论 + 因果推理，删除了中间的重述层
```

**P2: 三段式信封 (Envelope Padding)**

```
❌ "让我们把这个抽象理论带入到日常场景中："  ← 预告句，可直接删除
✅ 直接开始案例正文
```

**P4: 对称强迫症 (Symmetry Bloat)**

```
❌ 恒温器案例（3段完整展开）+ 电梯案例（3段完整展开）
   → 电梯案例的核心信息仅需 1 句话

✅ 恒温器案例（3段完整展开）+ 
   "同样的错位还出现在电梯按钮上——狂按已亮的下行键，
    是将人际催促模型强行套用在只认 0 和 1 的继电器上。"
```

**P7: 叙事过度戏剧化 (Dramatization Bloat)**

```
❌ "寒冷的冬夜你回到家，屋子像冰窖，你急着给冻得发抖的婴儿取暖。
    在这个火烧眉毛的关头，你会怎么操作墙上的空调恒温器？" (50字布景)

✅ "冬夜回家急着取暖，你会怎么调恒温器？" (16字布景)
```

### 2.8.4 写作时自检

每完成一个 `###` 块，执行以下快速扫描：

1. **金句后检查**：刚写完一句有力的结论后，检查下一段是否只是在"解释自己刚说的话"
2. **开头检查**：块的首句是否是"让我们来看/接下来/那么"之类的空转预告
3. **案例篇幅检查**：案例的情景设置是否比论证本身还长
4. **回看检查**：本块中的核心定义，在前面的块中是否已经被说过 ≥ 2 次

### 2.8.5 审计时检测

在 `/audit` Part B-5 脉络清晰度检查 或 `/review` Phase B 中，增加以下扫描：

- 对每个 `##` 模块随机抽取 3 段，执行压缩比测试
- 压缩比 < 0.4 的段落数 ≥ 2 → 标记 `[STEALTH_INFLATION]` 🟡
- 压缩比 < 0.3 的段落数 ≥ 1 → 标记 `[STEALTH_INFLATION]` 🔴

## §3 信息推进节奏 (Advancement Rhythm)


> **来源**：IAR 信息推进率（rule_content_depth §4.1）从「写作后」前移到「写作中」。

### 3.1 段落分类标准

对每个自然段分类：
- **推进段 (A)**：引入新概念/新证据/新案例/新情感冲击
- **支撑段 (S)**：对已引入概念的展开、举例说明、正反对照
- **冗余段 (R)**：换角度重述已有结论 / 总结已知信息 / 过渡套话

### 3.2 写作中节奏约束

在 Phase 2 分段写作时，每完成一个 `###` 块，立即检查：

| 约束 | 标准 | 违规处置 |
|:---|:---|:---|
| 冗余段(R)上限 | ≤ 1 段/块 | 删除或重写为推进段 |
| 连续支撑段(S) | ≤ 2 段连续 | 在支撑段间插入新推进段，或合并支撑段 |
| 首段类型 | 必须为推进段(A) | 重写首段，直接进入新信息 |
| 末段类型 | 必须为推进段(A)或`[TEACHING MOMENT]` | 删除「综上/总之」式小结（模块中间无需小结） |

### 3.3 IAR 即时计算

每个 `###` 块的 IAR = (A + S) / (A + S + R)，必须 ≥ 0.85。低于 0.85 禁止继续写下一个 `###` 块。

## §4 结构断字校验 (Structural Paragraphing)

> **来源**：冷热叙事引擎（研究报告 §方法1）——冷热切换点就是天然的记忆分界线（Von Restorff 效应）。

### 4.1 冷热边界即段落边界

当叙事温度发生转换时（从🧊冷到🔥热，或反之），**必须断段**（插入空行）。温度转换信号：
- 🧊→🔥：从精确定义/结论切换到案例/故事/痛点
- 🔥→🧊：从情感冲击切换到教学金句/技术结论
- 任一方向的切换处不得合并为同一段

### 4.2 视觉锚点即断字锚

每个 `> [VISUAL]` 块**前后必须有段落间隔**（空行）。`[VISUAL]` 块之后的首段必须包含指示性词汇锚定画面（如图/左侧/屏幕上），不得紧跟与画面无关的论述。

### 4.3 禁止行为

-   ❌ 在同一自然段内完成「引入定义 + 展开案例 + 给出结论」的全套流程——这是压缩，不是简练
-   ❌ `###` 块以「我们刚才讲了…/回顾一下…」开头——前一块的内容已经讲完，读者不需要被提醒
-   ❌ 连续 3 个 `###` 块内部结构完全相同（如全部是「定义→案例→结论」三段式）——结构雷同导致认知疲劳，应变换节奏
