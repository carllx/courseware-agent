# 规则：视觉信标分流协议 (Visual Signaling Protocol)

> **核心原则**：PPT 上的文字不是讲者的提词板，而是学生的**认知信标**——精准的少量关键词，放在正确的位置，引导注意力到本质信息（Mayer, Signaling Principle）。

## TL;DR

Speech 中出现 ≥3 个并列要点时，不再一刀切地要求 VISUAL 块必须有 List。按**内容类型分流**：结构性枚举（定义/框架/SOP）→ 必须有 List（≤4 字/项）；论证性递进（首先…其次…）→ 禁止 List；修辞性排比（情感渲染）→ 绝对禁止 List。

---

## §1 理论基础

本规则调和 Mayer CTML 中三条看似矛盾的原则：

| 原则 | 核心要义 | 对 List 字段的指导 |
|:---|:---|:---|
| **Signaling Principle** | 关键词/高亮可引导注意力到本质信息 → 学生走神后也能通过屏幕文字重新定位 | 结构性枚举**必须**上屏 |
| **Redundancy Principle** | 口述 + 屏幕全文重复 = 认知过载 → 逻辑展开通过口述已充分传递 | 论证性递进**禁止**上屏 |
| **Coherence Principle** | 与学习目标无关的修辞渲染不应出现在视觉界面 → 文字化会杀死情感冲击力 | 修辞性排比**绝对禁止**上屏 |

**额外考量（课堂生态效度补丁）**：

- Mayer 冗余效应的实证基底是 e-learning 自学环境，本项目为**有教师在场的现场课堂**
- 课堂中 PPT 文字有一个 e-learning 不存在的功能：**走神恢复锚点**——学生走神后抬头看屏幕可快速重新定位上下文
- 因此对结构性枚举类内容，屏幕上的关键词 List 是必要的认知脚手架

---

## §2 内容类型分流决策矩阵

当 Speech 中出现 ≥3 个并列要点时，按以下矩阵决定 `[VISUAL]` 块的 `**List**` 字段处理：

| 内容类型 | 识别特征 | List 字段 | 每项字数 | PPT 显示内容 |
|:---|:---|:---|:---|:---|
| **结构性枚举** | 定义/框架/分类/维度/原则/标准/阶段/类型/层次/要素/模型/评分标准/考核规则/任务说明 | ✅ **必须有** | ≤ 4 字 | 高度压缩的关键词 |
| **操作性步骤** | SOP/实践步骤/操作指引（含动词：打开/选择/点击/输入/导出） | ✅ **必须有** | 可保留完整步骤编号 | 步骤序号 + 动词短语 |
| **论证性递进** | 首先…其次…再次…最后… / 一方面…另一方面… / 用于展开一个论点的逻辑链 | ❌ **禁止有** | — | 无——口述已充分传递 |
| **修辞性排比** | 情感渲染/故事类比/排比句式（它让…它让…它让…/既…又…既…又…） | ❌ **绝对禁止** | — | 无——文字化杀死冲击力 |

### §2.1 分类优先级

当一段文本可能同时匹配多种类型时，按以下优先级判定：

```
操作性步骤 > 结构性枚举 > 修辞性排比 > 论证性递进
```

理由：操作性步骤和结构性枚举涉及学生需要记住/跟随的信息，优先保障可见性。

### §2.2 分类不确定时的降级策略

当无法确定内容类型时：

- 自动化脚本标记为 `[SIGNALING_AMBIGUOUS]` 🟡
- Agent 执行人工判定，不自动修复
- 默认**不报错**（宁可漏检，不可误杀）

### §2.3 纯文本排版豁免

当 `[VISUAL]` 块的 `Layout` 为 `Code`、`Diagram` 或 `Table`（无论显式声明还是隐式推断），或者该块关联了下方紧跟的纯文本资产（如 Markdown 代码块、表格）时，由于资产本身已在屏幕上展示了高度结构化的信息，此类 Slide **天然豁免** `List` 字段缺失的检查规则。即使讲稿中出现了结构性枚举，也无需在元数据中重复添加 `List`。

## §3 List 条目的字数约束

当内容类型要求有 List 时，每个条目必须是**关键词级别**：

| 约束 | 值 | 理由 |
|:---|:---|:---|
| 每项 ≤ 4 个中文字 | 硬性上限 | 超过 4 字已不再是"信标"而是"句子"，触发冗余效应 |
| 每项 > 10 字 | 🔴 冗余效应风险 | 必须压缩或改用 Text 字段的标题式表述 |
| List 总项数 ≤ 7 | 建议上限 | Miller's Law（7±2），超过 7 项建议拆分为多张 Slide |

**示例对比**：

| ❌ 冗余式 List（旧） | ✅ 信标式 List（新） |
|:---|:---|
| 功能性需求 (Functional Job) | 功能性 |
| 个人情感需求 (Personal/Emotional Job) | 个人情感 |
| 社会情感需求 (Social Job) | 社会情感 |

## §5 禁止行为

- ❌ 在修辞性排比段落的 VISUAL 块中添加 List（杀死情感冲击力）
- ❌ 在论证性递进段落的 VISUAL 块中添加 List（制造冗余认知负荷）
- ❌ List 单项超过 10 个中文字（不再是信标，而是句子）
- ❌ 不区分内容类型，机械地为所有 ≥3 并列项添加 List（旧 Bullet Sync 的反模式）
- ❌ 将完整的逐字稿句子搬到 List 中当"提词器"（讲者的记忆辅助应放 Speaker Notes）

## §6 验证方法

自动化检测：
```bash
/opt/anaconda3/envs/mybase/bin/python \
  .agent/skills/validation_suite/scripts/validate_visual_text_sync.py \
  --course "<课程>" --week <N>
```

脚本将按 §2 决策矩阵自动分类，输出：
- `[SIGNALING_MISSING]` 🔴：结构性枚举/操作步骤缺 List
- `[REDUNDANCY_WARNING]` 🟡：论证性递进有 List（建议移除）
- `[RHETORICAL_VIOLATION]` 🔴：修辞性排比有 List（必须移除）
- `[SIGNALING_AMBIGUOUS]` 🟡：无法自动分类（需 Agent 人工判定）
