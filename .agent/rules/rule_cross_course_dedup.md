# 规则：跨课程案例去重 (Cross-Course Case Deduplication)

> **核心原则**：同一工作区内的不同课程共享案例库知识（KI、教材、网络调研），但每个具体案例在逐字稿中只能归属于一门课程的一个教学位置。跨课程重复使用相同案例会导致教学冗余，并在学生选修多门课程时严重损害教学效果。

---

## §1 触发条件

以下任一场景触发本规则：

1. `/write` 工作流中计划引入一个包含**具名实体**（真实人物、品牌产品、历史事件、新闻案例）的案例段落
2. `/audit` 工作流中发现某个 `[CASE STUDY]`、`[STORY TIME]` 或 VISUAL 块的 Scene 描述与另一门课程高度相似
3. Agent 在生成叙事内容时从 KI 知识库或上下文记忆中调取了跨课程素材

## §2 检查流程

### §2.1 写作阶段（/write）

在引入任何具体案例前，**必须**执行以下检查：

```bash
# 在工作区根目录搜索案例关键实体（取 2-3 个核心关键词）
grep -r "关键词1\|关键词2" --include="*.md" <工作区根>/*/weeks/*/src/ | grep -v "<当前课程>"
```

- 若搜索命中其他课程的 `src/` 目录 → **禁止引入**，必须选用替代案例
- 若仅命中 `build/`、`dist/` 等构建产物目录 → 忽略（构建产物可包含跨课程引用）

### §2.2 审计阶段（/audit）

在 Standard/Deep 审计的叙事检查中，增加以下检查项：

> **CX1: 跨课程案例唯一性**
> 对每个 `[CASE STUDY]` 和 `[STORY TIME]` 块的核心实体（人名/品牌/事件），在工作区内其他课程的 `src/` 目录中执行 `grep` 搜索。若发现重复 → 标记为 `Needs Revision: 跨课程案例重复`。

## §3 替代策略

当检测到案例冲突时，按以下优先级选择替代方案：

1. **同领域不同案例**：寻找本课程学科领域内的替代案例（如信息可视化用 Tufte 的案例替代 Cooper 的案例）
2. **同案例不同切面**：若案例确实横跨两个学科，可在不同课程中从不同理论视角切入（但必须避免叙事文本的实质性重复）
3. **抽象化处理**：将具体案例替换为概括性描述，不展开具体细节

## §4 豁免条件

以下情况可豁免去重要求：

- 案例在本课程中仅以 `[TECH NOTE]` 或脚注形式一句话提及（而非展开叙事）
- 两门课程明确属于不同年级/学期，且教师确认学生不会同时选修
- 用户通过 `<!-- DEDUP_OVERRIDE: 理由 -->` 注释显式标记豁免

## §5 禁止行为

- ❌ 在未执行 §2.1 检查的情况下，从 KI 或上下文记忆中直接复制其他课程的案例段落
- ❌ 仅修改案例的表层措辞（换词不换实质）来规避去重检测
- ❌ 在审计修复中对疑似跨课程污染的内容默认执行合规性修补，而不先质疑其归属课程
