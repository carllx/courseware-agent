# 规则：DMA 专业 AI 课程设计范式 (DMA & AI Pedagogy Protocol)

**定义**: 数字媒体艺术 (DMA) 学生的强项在于视觉表达、情感交互设计、数据叙事与概念模型构筑，而弱项在于计算机工程基础（如复杂的异步逻辑、数据库架构、数据抓取清洗管线、CI/CD部署引擎等）。在引入 Vibe Coding 等 AI 生成能力时，必须设立严格的能力隔离带。

## 1. 核心护栏原则 (Core Guardrails)

### 1.1 项目载体“降维打击”
*   **❌ 禁忌载体**：微型 SaaS、数据管理后台、涉及多表联查的应用、要求真实商业全链路打点（Analytics）指标的项目、需手写复杂爬虫的数据采集系统。
*   **✅ 推荐载体**：单页面互动应用 (SPA)、交互式数据新闻、情绪/体验装置界面、基于 p5.js/Three.js/D3.js 的弱逻辑强视觉呈现方案、互动视觉小说、静态可视化大屏。
*   **判断标准**：项目是否可以通过**纯前端展示 + 极简状态切换/数据映射**来完成验收。一旦碰触“数据库CRUD / Session / 异步并发流”，必须立即降维。

### 1.2 对 AI 生成的去神话化 (De-mythologizing AI)
*   不可假设学生可以通过 AI（v0, CodeGeeX 等）完全跨越工程鸿沟，AI 不是代替基础，而是放大已有设计认知。
*   **AI 的用武之地**：生成界面的前端响应式外壳；调用简单的成熟动画/图表引擎进行视觉表现（如跟手粒子、浮动景深、Echarts基础映射）；补全标准 CSS Tokens。
*   **AI 的滑铁卢（严控介入）**：无尽嵌套的组件状态轮转；报错信息的深层调用栈解读；海量脏数据的清洗与防抖处理。
*   **兜底策略 (Fallback Strategy)**：当学生在 AI 辅助编程中陷入 Debug 死胡同，必须允许退回到使用 Figma 等进行“高保真视觉表现与可交互原型”作为平级验收材料。**叙事与视觉重于沙盒代码。**

## 2. 评估体系“退工程化” (De-engineering Assessment)

### 2.1 抛弃形式主义的工程指标验证
*   脱离真实流量去考核 DMA 学生的“转化率”、“日活”等全链路商业漏斗指标，或考核“代码测试覆盖率”是虚无的。
*   **回归定性与视觉体验研究 (Qualitative & Visual Experience)**：
    *   **启发式评估 (Heuristic Evaluation)**：关注防错手段是否到位，心智隐喻是否产生摩擦，数据编码映射是否准确无歧义。
    *   **行为与情感观察 (Behavioral & Emotional Observation)**：回归传统的受众直观感受测试（如 Think-Aloud），侧重“情感传达是否到位”、“信息是否清晰易读”。

### 2.2 理论模型的纯净度切割 (Methodology Boundaries)
在排布课程理论时，应根据学科特性精准裁剪方法论，严防工程理论的过度入侵：
*   **前期洞察/数据获取**：重敏捷假设与公开安全数据集，轻量化调研，砍掉冗长无用的用户画像或高门槛的爬虫架构教学。
*   **中期架构/信息流转**：重结构（画出状态转换图、数据映射树），防止凭借 AI 生成毫无底层逻辑的散装页面或图表。
*   **后期视觉统摄**：重战术级排版、色彩与空间层级约束，帮助非工程背景写出专业的 System Prompt 以约束大模型的视觉与图表生成质量。

## 3. 工作流强制约束
无论是执行 `/new_course` 还是修改现有大纲，一旦发现课程 Objectives 包含了过重的“自动化流部署”、“SaaS商业闭环”、“复杂中间件概念”、“高难度数据挖掘”，Agent 必须**主动拦截**并引用此规则进行降维纠偏。
