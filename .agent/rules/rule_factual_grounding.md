# 规则：案例事实锚定协议 (Factual Grounding Protocol)

> **核心原则**：案例不是装饰，而是证据。没有出处的案例等同于捏造。

## TL;DR

脚本中每个案例/故事/产品行为引用必须满足 WHO（具体产品名）、WHEN（年份/版本）、WHY（底层原因/出处）三要素中的**至少两项**。禁止"某些软件"、"早期系统"等模糊泛指。审计时标记不达标条目为 `[UNGROUNDED_CLAIM]`。

---

## §1 案例事实锚定三要素（强制）

脚本正文中引用的每一个案例、故事、产品行为，必须满足以下三要素中的**至少两项**：

| 要素 | 定义 | 合格示例 | 不合格示例 |
|:---|:---|:---|:---|
| **WHO** | 具体的产品名/公司名/平台名/人物名 | Windows 10, 360 安全卫士, SAP, Alan Cooper | 某些软件, 一个系统 |
| **WHEN** | 年份、版本号或可定位的时间段 | 2015 年, Word 2003, iOS 14, MS-DOS 时代 | 早期, 以前, 很久之前 |
| **WHY** | 底层技术原因、出处引用或可追溯的事件 | FAT32 文件句柄占用, Cooper《About Face》Ch.1 | 因为设计不好, 因为没考虑用户 |

**对照示例**：

```
❌ "早期系统经常弹出冰冷的报错框"
   → WHO: ❌ (哪个系统？)  WHEN: ❌ (什么时候？)  WHY: ❌ (什么报错？)
   → 锚定要素: 0/3 → 不合格

✅ "在 MS-DOS 与 Windows 95 时代，系统弹出带红叉的 Fatal Exception 0E 蓝屏"
   → WHO: ✅ (MS-DOS, Windows 95)  WHEN: ✅ (隐含90年代)  WHY: ✅ (Fatal Exception 0E)
   → 锚定要素: 3/3 → 合格
```

## §2 模糊泛指禁止词表

以下表达**禁止**出现在叙事正文（Speech）中。`[VISUAL]` 块的 Scene 字段**豁免**（因 Scene 是画面描述而非论证陈述）。

| 禁止模式 | 触发条件 | 修复方向 |
|:---|:---|:---|
| "某些软件/系统/应用" | 修饰产品/平台时使用不定代词 | 替换为具体产品名 |
| "早期/旧版/以前的" | 不附带具体版本号或年份时 | 附带版本号（如"Word 2003"）或年份（如"2015 年"） |
| "各类/各种/很多" | 修饰产品/平台/公司时 | 替换为 2-3 个具体实例 |
| "有一个案例/有人发现" | 不附带具体出处时 | 附带出处人名/机构/文献 |
| "据说/据报道" | 不附带媒体/机构名时 | 附带具体信息源（如"央视网 2020 年数据"） |

## §3 适用范围与豁免

### 3.1 强制适用

- 人文层标签内容：`[CASE STUDY]`、`[STORY TIME]`、`[LIFE CONNECT]`
- 叙事正文中的产品行为描述、系统缺陷举例、历史事件引用

### 3.2 豁免场景

- **假设性思想实验**（以"假设/想象"等词明确标记的虚构场景）
- **通识性常识**（无需引用出处的公共知识，如"手机需要充电"）
- **`[VISUAL]` 块的 Scene 字段**（画面描述可使用概括性表达）
- **`[TEACHING MOMENT]` 金句**（精炼的教学提炼可不附录出处）

## §4 写作阶段自检

在 `/write` Phase 2 的 Phase B（先减后加）中，对每个新增的案例段落追加以下自检：

> _"这个案例，我能当面被学生追问'具体是哪个产品？哪一年的事？为什么会这样？'时，从容作答吗？"_

如果答案为否，该案例必须在写入前完成调研补强。

---

## §5 审计检查项

`/audit` Standard 级别中，新增以下检查：

> **A-FACT (案例事实锚定度)**：
> 扫描每个人文层标签及正文中的案例陈述，检查是否满足 §1 锚定三要素中的至少两项。
> - 不满足者标记为 `[UNGROUNDED_CLAIM]`
> - 判定：🟡 中等严重度（单个模块 ≥ 3 处不达标升级为 🔴 高严重度）

---

## §6 审查检查表

写完或审查案例后，逐项自检：

| # | 检查项 | 标准 |
|:--|:---|:---|
| F1 | 每个案例是否满足 WHO/WHEN/WHY 至少两项 | §1 三要素 |
| F2 | 是否存在 §2 禁止词表中的模糊泛指 | 叙事正文零容忍 |
| F3 | 案例出处是否可被独立验证 | 学生/同行检索能找到相关信息 |
| F4 | 是否存在刻意编造的数据/年份/版本号 | 严禁捏造（宁可不写不可造假） |
