# 叙事与文字规范详细指南 (Narrative Standards Guide)

> **前言**：本指南从旧版 `rule_narrative_standards.md` 中剥离，作为 `script_format` 技能的附属参考（Reference），在需要深入理解叙事规范、过渡技巧或播报禁忌时被调用。

---

## §1 反正统翻译腔与纯净中文 (Quality & Anti-Translationese)

### 1.1 纯正简体中文底线

必须全程使用流畅、自然、高语商的**简体中文**进行叙事（除极少数的软件功能锚点外）。**严禁“中式英语 (Chinglish)”**。任何强行套用英语从句格式、生硬机翻或滥用非必要专业外语词汇的行为都将被直接打回。

### 1.2 竹节结构

句子必须**可断可续**，每个逻辑单元不超过 **20 个字**。

```
❌ "通过使用卷积混响技术并结合脉冲响应文件可以实现对声学空间的精确模拟。"
✅ "卷积混响的秘密，藏在一段脉冲里。‖ 有了它，我们就能把任何空间'拍'下来。"
```

### 1.2 话题优先

中文语序为**话题优先 (Topic-Comment)**，严禁英语 SVO 直译。

```
❌ "Audition 提供了一个强大的降噪模块。"
✅ "降噪这件事，Audition 给了我们一套非常精密的工具。"
```

### 1.3 禁忌词（脚本中严禁出现）

| 禁忌 | 替代 |
|:---|:---|
| "进行" | 用具体动词代替 |
| "实现" | 用"做到/完成" |
| "功能" | 用"能力/本事" |
| "相关的" | 删除或改写 |
| "在…的情况下" | 用"当…/如果…" |

### 1.4 反黑话与费曼画板测试 (Anti-Jargon & Demystify)

严格控制外在认知负荷（Extraneous Cognitive Load）。大语言模型生成文本时极易使用“生硬组合的高级词汇”（如“降维防震”、“硬核厚度”、“赋能闭环”、“底层抓手”）来模拟专业的情绪张力，这会给学生制造解码障碍，严重阻断加工流畅度。
任何修饰语与核心概念必须通过**费曼画板测试 (The Feynman Canvas Test)**：“如果你无法在脑海中用具体的物理画面画出这个形容词组，那么就不准用它”。
高级概念必须降解（Demystify）并落地为实物隐喻（如“救生圈”、“底牌”、“地基”），绝不允许出于偷懒而“强行打包”生造抽象缝合词。

## §2 韵律句法 (Prosody)

### 2.1 音步规则

中文天然律动是 **2+1 / 2+2** 音步。写完后默读，检查是否有"绊嘴"的句子。

```
✅ "声音|穿过|空气，‖ 高频|先死。"   (2+2, 2+1)
❌ "高频率的声音在穿过一段空气后就会首先衰减。"
```

### 2.2 四字格

中文叙事的节奏感可用**四字格**增强，但不可滥用——每段最多 2 个。

```
✅ "它不动声色地吞噬了高频。"
❌ "不动声色、悄无声息、润物无声地……" (堆砌)
```

### 2.3 呼吸测试

**卡嗓子检查**: 对每段正文做朗读测试。如果一口气读不完一句话，必须断句。

## §3 过渡焊接技巧库 (Transition Techniques)

段落 (Segment) 之间的过渡不可使用"下面我们来看"等机械连接词。以下为推荐技巧：

| 技巧 | 定义 | 示例 |
|:---|:---|:---|
| **悬念反问** | 用问题吊起下一段的话题 | "但空间仅仅是形状吗？……" |
| **听觉桥接** | 用声音素材作为过渡锚点 | "听到了吗？这个尾音的秘密，就藏在下一步……" |
| **递进对比** | 从"够了"到"还不够"的递进 | "空间感有了，但它还是太'文明'了。" |
| **回环** | 呼应前文的隐喻/故事 | "爱丽丝掉进的那个洞……那里没有观众。" |
| **时间跳切** | 快速切换时间线 | "1948 年，一个法国人换了张唱片……" |
| **感官切换** | 从一种感官跳到另一种 | "闭上眼，用耳朵去'看'这个空间。" |

### 禁忌过渡

```
❌ "下面我们来看第二个知识点。"
❌ "接下来介绍一下……"
❌ "让我们继续学习……"
```

## §4 朗读测试协议 (Read-Aloud QA)

脚本完成后，必须通过以下三项检查：

| 检查 | 方法 | 不通过标准 |
|:---|:---|:---|
| **卡嗓子** | 朗读全文，标记气短的句子 | 任何一句无法一口气读完 |
| **像人话** | 找一个非技术同事听一段 | 对方说"听不懂"或"太生硬" |
| **视觉对位** (Speech→Visual) | 每句正文检查是否有对应画面 | 超过 30 秒无 `[VISUAL]` 描述 |
| **视觉解读** (Visual→Speech) | 每个 `[VISUAL]` 块检查后续语音是否充分解读 | Scene 中的关键要素未在语音中逐项提及，或 SPEECH 字数 < Scene 字数 × 2 |
| **TTS 盲区** | 扫描 `概念(参数)` 的括号结构 | TTS 会吞噬括号内容，必须改为显性口语：`用 **Param** 来 概念` |
| **信标同步** (Signaling Sync) | Speech 中 ≥3 并列要点按内容类型分流：结构性枚举必须有 List（≤4 字/项）；论证性递进/修辞性排比禁止 List | 结构性知识点仅通过听觉传达而 PPT 上不可见；或反之，修辞段被机械上屏杀死冲击力 |

## §5 教学媒介适配 (Delivery Mode)

根据 `course.yaml` 的 `delivery_mode` 字段动态调整：

| 模式 | 交互性 | 视觉密度 | 语速 | 示例课程 |
|:---|:---|:---|:---|:---|
| `video_essay` | 零交互 | 极高（每 30s 换画面） | ~160 字/分钟 | Audition 混响 |
| `lecture` | 有提问 | 中（每 2-3 分钟换画面） | ~180 字/分钟 | 实习指导 |
| `workshop` | 高交互 | 低（演示为主） | ~140 字/分钟 | 编程实训 |

### 禁忌搭配

- `video_essay` 模式下严禁出现"请大家思考/请举手/请打开你的电脑"等交互话术
- `lecture` 模式下可以有提问，但必须是修辞性的或自答的
- `workshop` 模式下可以有交互指令

## §6 语调与修辞 (Tone & Rhetoric)

### 6.1 干练成熟 (Mature & Capable)
拒绝"哄小孩"或"吓唬人"的低幼语调。
*   **❌ 幼稚**："小朋友们要注意啦，这个很危险哦！" / "不交作业就完蛋了！"
*   **✅ 成熟**："请注意，此处误操作将导致数据不可逆丢失。" / "截点前未提交将直接影响最终考评。"

### 6.2 修辞性铺垫 (Rhetorical Paving)
在进入核心概念前，使用修辞进行"软着陆"，但必须言之有物，切中要害。
*   **❌ 机械**："下面讲一下盖章的规定。"
*   **✅ 铺垫**："公章不是红色的印泥，它是法律效力的物理凭证。任何模糊、缺角，都意味着法律链条的断裂。"

### 6.3 易于理解 (Lucid & Direct)
把复杂逻辑翻译成"人话"，而不是简化成"儿语"。
*   **原则**：用成人的心智对话，用专家的视角降维。

### 6.4 技术-心理桥接 (Tech-Psychology Bridging)
禁止"裸露的物理定义"。任何技术概念必须同时解释"这对听众意味着什么"。
*   **❌ 裸定义**："Haas 效应是 40ms 延迟。"
*   **✅ 桥接**："40ms——这是你的耳朵开始怀疑'声源在那边'的临界点。"

### 6.5 防 CRUD 程序员惯性 (Anti-CRUD Mindset)
在讲解软件工程架构或代码实现（特别是包含界面的系统）时，严禁使用纯后端视角的 "CRUD"（增删改查）或孤立的 API 接口视角。必须从用户操作侧的心智模型、交互路径切入，说明代码是为了解决或响应什么用户动作。
*   **❌ CRUD视角的无意义宣读**："这段代码是对 user 数据库对象的 create 接口回调，我们把用户名参数传进去再在本地存盘刷新。"
*   **✅ 心智桥接**："先别急着写代码。当用户在这里点击保存，他们潜意识里是在获取一种'掌控感'，这是给系统下达的一个动作承诺。这段回调业务逻辑，就是为了接住并兑现这个承诺……"

### 6.6 修辞是盐，不是菜 (The Salt Rule)

修辞（隐喻、成语、类比、拟人、夸张）是调味品，不是主食。

**量化限额**：每 500 字的讲授文本中，修辞性表达的总量**不超过 2 处**。超出即视为堆砌。

**判定方法**：如果删掉一处修辞后，段落的信息传递不受任何影响，它就是多余的盐。盐放多了客人会呕吐。

**自动化检测**：`validate_script_length.py` 的四字格密度指标和「的」字链深度指标可捕获堆砌模式（不依赖具体词汇，只检测结构性密度）。

## §7 反异常注水与作弊防范 (Anti-Padding & Cheating Prevention)

为防范通过生硬粘贴手段绕过长度审计，特设立以下强制基线：

### 7.1 禁止源文件全盘粘贴 (No Verbatim KB Dumps)
**严禁**为了人为撑大脚本字数，将 Knowledge Base (`knowledge/` 下的 `.md` 源文件) 段落全盘粘贴到单个模块末尾的 `> [!NOTE] 教案深度拓展` 区块中。任何未经重新组织的大体积无语义字符堆砌行为，均被视为对 O9 监控审计的恶意作弊。

### 7.2 深度拓展块的体积锁定
`> [!NOTE] 教案深度拓展，即 Advanced Reading` 引用块在整个模块中必须**少而精**。严禁其超过 500 个字符长度，它仅可用于列举关键词、来源出处、1~2条高精炼提要。

### 7.3 真正的高密度扩写要求
绝不能将知识素材当作占位符机械堆放。所有的外部知识源必须被**“物理嚼碎”**，重新提炼为纯正口播叙事，并插入正文逻辑流之中。

### 7.4 反退化规则 (Anti-Degeneration)

如果验证器 `validate_script_length.py` 的 `detect_dilution()` 触发了退化警告（即修饰语密度>6次/百字、最长无标点句>400字、同一4字组合重复>8次），**必须整段重写退化区域**。退化文本不可通过"局部删减修饰语"糊弄修复，必须重构语境逻辑。

### 7.5 反换角度重复 (Anti-Paraphrase Padding)

**定义**：同一个结论/观点在同一模块内被用不同的措辞表述了两次以上，而未引入新的认知维度。

**识别方法**：对每个自然段执行"一句话压缩测试"——将该段核心信息压缩为 1 句话。如果两个段落压缩后的句子语义高度重叠（> 80%），则后者为"换角度重复"。

**判定标准**：
-   如果两段提供了**明确可感知的不同维度**（如段落 A 从用户视角论述，段落 B 从工程视角论述），则共存合理——但必须用不同的 H4 标题标明维度差异
-   如果维度区分需要"费力辨认"，则后者为冗余段，必须删除或合并至前者

**维度可感知性快速判定**：
-   **10 秒测试**：能否在 10 秒内用一个名词短语说出两段的维度差异？（如"用户视角 vs 工程视角"）如果需要超过 10 秒思考 → 维度不可感知，视为重复
-   **标题测试**：能否为两段分别起出**语义不重叠**的 H4 标题？如果两个 H4 标题可以互换而不影响阅读理解 → 实际是同一维度

**物理对称陷阱**：
-   一种常见的啰嗦模式是「正面描述 + 反面对称镜像」——如正面描述物理世界三支柱后，用对称结构逐条描述数字世界三断裂。如果正面已经足够清晰（读者能自行推导反面），则反面对称只需**一句话总结**而非逐条展开
-   **判定**：删除反面对称段后，读者是否仍能理解核心论点？如果是 → 反面段应精简为 1-2 句话的点睛句

**禁止模式**：
-   ❌ "总之，{前面说过的内容}" — 模块中间不需要小结，除非是模块末尾的 `[TEACHING MOMENT]`
-   ❌ "换句话说 / 也就是说 / 简单来讲" — 如果前面的表述已足够清晰，不需要"翻译"
-   ❌ 在不同段落中对同一案例的"意义"做两次以上的总结性评价
-   ❌ 段落 A 结尾给出结论，段落 B 开头以"也就是说"重新陈述该结论后才引入新内容
-   ❌ 正面逐条展开后，反面再逐条对称展开（应精简反面为点睛句，或合并为正反对照表格）

## §8 反浅薄化与双锚点叙事 (Anti-Shallowing & Dual-Anchor)

针对“导入性讲稿、破冰段落、5分钟极简版”等，必须遵循双锚点原则。

### 8.1 严禁技术“美化工具论”
绝不能将严谨的设计学科/技术工程降级描绘为“只是为了让东西变好看、让老板爱看”的纯功利性表面工作。

### 8.2 强制的双重锚点 (Mandatory Dual-Anchor)
合格的引入式长篇必须在这两个极端锚点上来回拉扯：
1.  **职业现实锚点 (接地气)**：解决学生“学这门课以后能干什么”的饥渴。必须结合真实的工业应用场景。
2.  **硬核认知锚点 (反常识)**：解决学生“这东西随便糊弄就行”的心态。必须在前 5 分钟内抛出一个**能推翻学生直觉的具体事实**（如香农信息论冰冷定义）。注意：是事实，不是修辞；是推翻直觉，不是堆砌形容词。

## §9 脉络透明度 (Skeleton Transparency)

> **理论基础**：认知分块（Chunking）——人类工作记忆容量为 7±2 通道（Miller's Law），脚本必须将万字长稿压缩到可被工作记忆承载的粒度上。演讲者的记忆路径是：`全文 → 大块 → 关键词 → 自然展开`。
>
> **详细执行标准**：见 `rule_script_clarity.md`
> **底层体系与延伸训练**：见 [调研报告：演讲稿脉络可视化与结构化记忆](../../../../docs/RESEARCH_SPEECH_MEMORIZATION.md)

### 9.1 骨架链自检协议

写完每个 `##` 模块后，执行以下三步自检：

1. **提取**：串联所有 `###` 和 `####` 标题为一行骨架链
2. **角色标注**：为每个骨架节点标注 SCQA 冷热角色
   - 格式：`### 1.1 [S🧊: 现状] → ### 1.2 [C🔥: 痛点引爆] → #### 1.2.1 [Q: 灵魂拷问] → ### 1.3 [A🧊: 铁律]`
3. **死环检测**：如果两个节点可以被压缩为同一句话 → 合并或删除后者

### 9.2 「读标题知脉络」测试

**测试方法**：将模块的所有 H3/H4 标题（断言式标题）按顺序排列，遮住所有正文。

-   ✅ **通过**：仅凭标题序列即可还原模块的论证走向（从问题到答案），且不存在「同义复述」的标题对
-   ❌ **失败**：需要阅读正文才能理解标题之间的关系，或存在两个标题说的是同一件事

### 9.3 灵魂锚词提取 (H5 记忆检视引擎联动)

在编写正文（Speech）时，为了支持后续利用 H5 工作台的「记忆检视模式」进行脱稿演练，每个自然段如果有核心概念，**必须显式使用 `**包围**` 进行加粗**。

**提取逻辑（H5 Cloak Mode 触发规范）**：
- 渲染器会扫描段落中的**首个加粗词汇**，提取其前 6 个汉字作为该段落的「灵魂锚词」。
- 如果未检测到加粗符号，该段在 H5 排练模式下将**静默留白**（不显示任何悬浮芯片），从而规避了系统机械提取导致的“无意义句首词”干扰。

所有灵魂锚词串联后应构成一个可脱稿的逻辑故事线。
如果灵魂关键词串联后读起来像「随机词语拼凑」而非「故事线」→ 模块的逻辑流需要重构。

**示例**（M01 模块骨架链锚词）：
```
1.1 → "**咖啡机困局**" | 1.2 → "**四大根因**" | 1.3 → "**认知摩擦**" | 1.4 → "**并行退路**"
```

## §10 秒懂优先协议 (Instant Clarity Protocol)

> **理论基础**：Oppenheimer (2006) 加工流畅度法则、Paivio 双重编码理论、Harp & Mayer (1998) 一致性原则、Pinker (2014) 知识诅咒免疫。
>
> **核心哲学**：§6 和 §8 是**油门**（追求情绪张力、修辞铺垫、认知锚点）；§10 是与之**对等权重**的**刹车**（每一句话必须让学生零延迟理解）。二者互为约束，缺一不可。没有 §10 的 §6/§8 会制造华丽但不秒懂的认知噪音。
>
> **完整学术来源与延伸阅读**：[instant_clarity_research.md](instant_clarity_research.md)

### 10.1 Oppenheimer 简洁替代测试 (The Oppenheimer Swap Test)

写完每句话后检查：**能否用一个更短、更日常的词替换当前用词，而不损失任何信息？** 如果能，就必须替换。

```
❌ "信息环境正在发生一场彻底的体量剧变"
✅ "数据量炸了"

❌ "被无数数据科学家奉为圭臬的范式"
✅ "被公认为黄金标准的方法"

❌ "核爆级威力巨大的改革"
✅ "一场彻底的改革"

❌ "你的额叶皮层被语法纠缠剧烈消耗殆尽"
✅ "你的脑子全被语法细节耗光了"
```

**原理**：Oppenheimer 2006 实证——使用不必要的复杂词汇反而降低读者对作者的智力评价。加工流畅度越高，听众越觉得可信和专业。**华丽 ≠ 高级，流畅 = 高级。**

### 10.2 Paivio 具象化强制 (Concreteness Mandate)

每个核心概念必须绑定一个**学生可以在脑海中"画出来"的具体画面**。抽象概念不允许用另一个抽象概念去解释。

```
❌ "有限理性的制约漏斗锁死了探知极限"（4 层抽象叠加）
✅ "就像你在超市只有 5 分钟，货架上一万种选择，你根本逛不完"

❌ "认知维度的向上跃迁"
✅ "你从'埋头写代码的工人'变成了'坐在监控室的总指挥'"
```

**原理**：Sadoski & Paivio (2001)——具象词同时激活语言和视觉意象两个系统（双重编码），记忆效果远超抽象词。学生听到"超市5分钟"就自动脑补出画面，零解码成本。

### 10.3 Mayer 修饰语删除测试 (The Mayer Deletion Test)

对每个修饰语做"删除测试"：**删掉它之后，学生对核心概念的理解会不会下降？** 如果不会，就必须删掉。

```
原文: "进行的一场具有核爆级威力巨大改革的核心原因"
删除测试:
  - "核爆级" → 删掉后理解下降吗？不会 → 删
  - "威力巨大" → 同上 → 删
  - "核心" → 保留（这是限定词）
结果: "改革的核心原因"
```

**判定标准**：如果一个修饰语的作用仅仅是"让句子听起来更厉害"而不是"帮学生更准确理解概念"，那它就是 Mayer 所说的 Seductive Detail（诱惑性细节），必须删除。

> **Mayer 一致性原则**：删掉与核心学习目标无关的装饰性内容后，学生学习效果提升 3 倍（Harp & Mayer, 1998）。

### 10.4 Pinker 新生朗读测试 (The Freshman Read-Aloud Test)

写完每段正文后，执行以下心理模拟：

> **想象一个从未接触过本学科的大一新生，在课堂上第一次听到这段话。他能在 3 秒内明白你在说什么吗？**

*   如果需要"翻译"才能理解 → 改写
*   如果包含学生的词汇库之外的文言词（如"圭臬""桎梏""倾覆"）→ 替换为白话
*   如果 H3/H4 标题本身需要读两遍才能理解 → 标题必须重写

```
❌ 标题: "有限理性的制约漏斗锁死了传统人类深海寻宝的探知极限"
✅ 标题: "为什么你总是做不出好图表？因为选择太多，时间太少"

❌ 标题: "实战引擎：全链路部署实境将文字思维升格为数字导演视角"
✅ 标题: "后半程我们干什么？把你的想法变成一个真正上线的作品"
```

**原理**：Pinker (2014) 知识诅咒——写了太久专业内容的人（包括 AI），会丧失判断"什么对新手来说是难的"的能力。唯一的解药是持续站在新手视角自检。

### 10.5 修饰语密度上限 (Modifier Density Cap)

在单个自然段中，**极端程度修饰语**（极其/极度/极为/绝对/毫无/彻底/死死/完全）不超过 **2 个**。超出时必须精简或分段。

```
❌ "极其杂乱、残缺的原始脏数据残骸……极其高效吞吐理解的标准二元映射矩阵……坚如磐石的高质量基座"
   （单段出现 3 个极端修饰 + 2 个华丽四字格隐喻）
✅ 拆分为多段，每段聚焦一个信息点，用日常词表达
```

### 10.6 Orwell 垂死隐喻自检 (The Dying Metaphor Self-Check)

隐喻分三类（George Orwell, *Politics and the English Language*, 1946）：

-   **Fresh**：唤起全新画面（如「你的大脑是一块画布」） → ✅ 允许
-   **Dead**：已融入日常、无人感知原义（如「瓶颈」「桌腿」） → ✅ 允许
-   **Dying**：被用过太多次、大脑不再激活画面、但作者误以为这是「文采」 → 🔴 禁止

**自检方法**（写作时和审计时）：

读到一个四字格或成语时，问自己：**「我的大脑刚才有没有自动生成一幅画面？」**

-   如果答案是「有，我看到了具体的场景」 → 它是 Fresh 或有效的，保留
-   如果答案是「没有，我只是觉得它读起来挺顺的」 → 它就是 Dying 的，用白话重说

**结构性信号**（自动化可检测，不依赖具体词汇）：

-   同一窗口（约 5 句话）内出现 3 个以上四字格并列 → 极大概率是堆砌而非叙事需要
-   检测方式：`validate_script_length.py` 的四字格密度指标（tetragraph density），基于「XXXX、YYYY」顿号并列结构匹配

**原理**：Orwell 指出，Dying Metaphor 的危害在于作者用它们来逃避精确思考的劳动。当你写下「坚如磐石」时，你实际上没有在思考「到底有多坚固、为什么坚固」。对于 LLM 来说，这个「现成短语库」就是训练语料中高频出现的四字成语——它们是统计捷径，不是思考产物。

### 10.7 宪法批评原则 (Constitutional Coherence Principles)

为防御大语言模型在自我评估时的 Self-Enhancement Bias（导致其无法识别自身生成的客观错误），本协议定义以下 6 条"质量宪法"原则，用于审计和最终校验：

| # | 原则 | 核心精神 | 违反特征（样例） |
|:---|:---|:---|:---|
| **C1** | **反义词共现禁止** | 事实一致性与连贯性 | "统计**有损压缩**...却被**无损压平抛却**" |
| **C2** | **费曼画板探针** | 强制具备物理实体锚点 | "这是对**认知维度的向上跃迁**"（画不出画面） |
| **C3** | **Mayer 删除原则** | 修饰语必须承载信息 | "这是一场**具有核爆级威力巨大的**改革" |
| **C4** | **回译压缩测试** | 拒绝"正确的废话" | 整段压缩为一句话后变成："数据很重要"（空洞） |
| **C5** | **具象化解释强制** | 禁止用抽象解释抽象 | "所谓**范式转移**，就是**底层逻辑的重构**" |
| **C6** | **造词幻觉检测** | 词组必须有真实人类检索量 | "**皮质神经引擎**" / "**肉眼可见的深层次**" |

在执行 `/audit` 或 `/write` Phase 3 校验时，Agent 必须以"专业批评者"人格代入，**逐条应用上述探针**，并精确引用违规文本，而不仅是给出"通过/不通过"的宽泛判断。
