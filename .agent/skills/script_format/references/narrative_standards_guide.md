# 叙事与文字规范详细指南 (Narrative Standards Guide)

> **前言**：本指南从旧版 `rule_narrative_standards.md` 中剥离，作为 `script_format` 技能的附属参考（Reference），在需要深入理解叙事规范、过渡技巧或播报禁忌时被调用。

---

## §1 反正统翻译腔与纯净中文 (Quality & Anti-Translationese)

### 1.1 纯正简体中文底线

必须全程使用流畅、自然、高语商的**简体中文**进行叙事（除极少数的软件功能锚点外）。**严禁“中式英语 (Chinglish)”**。任何强行套用英语从句格式、生硬机翻或滥用非必要专业外语词汇的行为都将被直接打回。

### 1.2 竹节结构

句子必须**可断可续**，每个逻辑单元不超过 **20 个字**。

```
❌ "通过使用卷积混响技术并结合脉冲响应文件可以实现对声学空间的精确模拟。"
✅ "卷积混响的秘密，藏在一段脉冲里。‖ 有了它，我们就能把任何空间'拍'下来。"
```

### 1.2 话题优先

中文语序为**话题优先 (Topic-Comment)**，严禁英语 SVO 直译。

```
❌ "Audition 提供了一个强大的降噪模块。"
✅ "降噪这件事，Audition 给了我们一套非常精密的工具。"
```

### 1.3 禁忌词（脚本中严禁出现）

| 禁忌 | 替代 |
|:---|:---|
| "进行" | 用具体动词代替 |
| "实现" | 用"做到/完成" |
| "功能" | 用"能力/本事" |
| "相关的" | 删除或改写 |
| "在…的情况下" | 用"当…/如果…" |

## §2 韵律句法 (Prosody)

### 2.1 音步规则

中文天然律动是 **2+1 / 2+2** 音步。写完后默读，检查是否有"绊嘴"的句子。

```
✅ "声音|穿过|空气，‖ 高频|先死。"   (2+2, 2+1)
❌ "高频率的声音在穿过一段空气后就会首先衰减。"
```

### 2.2 四字格

中文叙事的节奏感可用**四字格**增强，但不可滥用——每段最多 2 个。

```
✅ "它不动声色地吞噬了高频。"
❌ "不动声色、悄无声息、润物无声地……" (堆砌)
```

### 2.3 呼吸测试

**卡嗓子检查**: 对每段正文做朗读测试。如果一口气读不完一句话，必须断句。

## §3 过渡焊接技巧库 (Transition Techniques)

段落 (Segment) 之间的过渡不可使用"下面我们来看"等机械连接词。以下为推荐技巧：

| 技巧 | 定义 | 示例 |
|:---|:---|:---|
| **悬念反问** | 用问题吊起下一段的话题 | "但空间仅仅是形状吗？……" |
| **听觉桥接** | 用声音素材作为过渡锚点 | "听到了吗？这个尾音的秘密，就藏在下一步……" |
| **递进对比** | 从"够了"到"还不够"的递进 | "空间感有了，但它还是太'文明'了。" |
| **回环** | 呼应前文的隐喻/故事 | "爱丽丝掉进的那个洞……那里没有观众。" |
| **时间跳切** | 快速切换时间线 | "1948 年，一个法国人换了张唱片……" |
| **感官切换** | 从一种感官跳到另一种 | "闭上眼，用耳朵去'看'这个空间。" |

### 禁忌过渡

```
❌ "下面我们来看第二个知识点。"
❌ "接下来介绍一下……"
❌ "让我们继续学习……"
```

## §4 朗读测试协议 (Read-Aloud QA)

脚本完成后，必须通过以下三项检查：

| 检查 | 方法 | 不通过标准 |
|:---|:---|:---|
| **卡嗓子** | 朗读全文，标记气短的句子 | 任何一句无法一口气读完 |
| **像人话** | 找一个非技术同事听一段 | 对方说"听不懂"或"太生硬" |
| **视觉对位** (Speech→Visual) | 每句正文检查是否有对应画面 | 超过 30 秒无 `[VISUAL]` 描述 |
| **视觉解读** (Visual→Speech) | 每个 `[VISUAL]` 块检查后续语音是否充分解读 | Scene 中的关键要素未在语音中逐项提及，或 SPEECH 字数 < Scene 字数 × 2 |
| **TTS 盲区** | 扫描 `概念(参数)` 的括号结构 | TTS 会吞噬括号内容，必须改为显性口语：`用 **Param** 来 概念` |
| **要点同步** (Bullet Sync) | Speech 中 ≥3 并列要点检查紧邻 VISUAL 是否有 `**List**` 字段 | 结构化要点仅通过听觉传达，PPT 上不可见 |

## §5 教学媒介适配 (Delivery Mode)

根据 `course.yaml` 的 `delivery_mode` 字段动态调整：

| 模式 | 交互性 | 视觉密度 | 语速 | 示例课程 |
|:---|:---|:---|:---|:---|
| `video_essay` | 零交互 | 极高（每 30s 换画面） | ~160 字/分钟 | Audition 混响 |
| `lecture` | 有提问 | 中（每 2-3 分钟换画面） | ~180 字/分钟 | 实习指导 |
| `workshop` | 高交互 | 低（演示为主） | ~140 字/分钟 | 编程实训 |

### 禁忌搭配

- `video_essay` 模式下严禁出现"请大家思考/请举手/请打开你的电脑"等交互话术
- `lecture` 模式下可以有提问，但必须是修辞性的或自答的
- `workshop` 模式下可以有交互指令

## §6 语调与修辞 (Tone & Rhetoric)

### 6.1 干练成熟 (Mature & Capable)
拒绝"哄小孩"或"吓唬人"的低幼语调。
*   **❌ 幼稚**："小朋友们要注意啦，这个很危险哦！" / "不交作业就完蛋了！"
*   **✅ 成熟**："请注意，此处误操作将导致数据不可逆丢失。" / "截点前未提交将直接影响最终考评。"

### 6.2 修辞性铺垫 (Rhetorical Paving)
在进入核心概念前，使用修辞进行"软着陆"，但必须言之有物，切中要害。
*   **❌ 机械**："下面讲一下盖章的规定。"
*   **✅ 铺垫**："公章不是红色的印泥，它是法律效力的物理凭证。任何模糊、缺角，都意味着法律链条的断裂。"

### 6.3 易于理解 (Lucid & Direct)
把复杂逻辑翻译成"人话"，而不是简化成"儿语"。
*   **原则**：用成人的心智对话，用专家的视角降维。

### 6.4 技术-心理桥接 (Tech-Psychology Bridging)
禁止"裸露的物理定义"。任何技术概念必须同时解释"这对听众意味着什么"。
*   **❌ 裸定义**："Haas 效应是 40ms 延迟。"
*   **✅ 桥接**："40ms——这是你的耳朵开始怀疑'声源在那边'的临界点。"

### 6.5 防 CRUD 程序员惯性 (Anti-CRUD Mindset)
在讲解软件工程架构或代码实现（特别是包含界面的系统）时，严禁使用纯后端视角的 "CRUD"（增删改查）或孤立的 API 接口视角。必须从用户操作侧的心智模型、交互路径切入，说明代码是为了解决或响应什么用户动作。
*   **❌ CRUD视角的无意义宣读**："这段代码是对 user 数据库对象的 create 接口回调，我们把用户名参数传进去再在本地存盘刷新。"
*   **✅ 心智桥接**："先别急着写代码。当用户在这里点击保存，他们潜意识里是在获取一种'掌控感'，这是给系统下达的一个动作承诺。这段回调业务逻辑，就是为了接住并兑现这个承诺……"

## §7 反异常注水与作弊防范 (Anti-Padding & Cheating Prevention)

为防范通过生硬粘贴手段绕过长度审计，特设立以下强制基线：

### 7.1 禁止源文件全盘粘贴 (No Verbatim KB Dumps)
**严禁**为了人为撑大脚本字数，将 Knowledge Base (`knowledge/` 下的 `.md` 源文件) 段落全盘粘贴到单个模块末尾的 `> [!NOTE] 教案深度拓展` 区块中。任何未经重新组织的大体积无语义字符堆砌行为，均被视为对 O9 监控审计的恶意作弊。

### 7.2 深度拓展块的体积锁定
`> [!NOTE] 教案深度拓展，即 Advanced Reading` 引用块在整个模块中必须**少而精**。严禁其超过 500 个字符长度，它仅可用于列举关键词、来源出处、1~2条高精炼提要。

### 7.3 真正的高密度扩写要求
绝不能将知识素材当作占位符机械堆放。所有的外部知识源必须被**“物理嚼碎”**，重新提炼为纯正口播叙事，并插入正文逻辑流之中。

### 7.4 反退化规则 (Anti-Degeneration)

如果验证器 `validate_script_length.py` 的 `detect_dilution()` 触发了退化警告（即修饰语密度>6次/百字、最长无标点句>400字、同一4字组合重复>8次），**必须整段重写退化区域**。退化文本不可通过“局部删减修饰语”糊弄修复，必须重构语境逻辑。

## §8 反浅薄化与双锚点叙事 (Anti-Shallowing & Dual-Anchor)

针对“导入性讲稿、破冰段落、5分钟极简版”等，必须遵循双锚点原则。

### 8.1 严禁技术“美化工具论”
绝不能将严谨的设计学科/技术工程降级描绘为“只是为了让东西变好看、让老板爱看”的纯功利性表面工作。

### 8.2 强制的双重锚点 (Mandatory Dual-Anchor)
合格的引入式长篇必须在这两个极端锚点上来回拉扯：
1.  **职业现实锚点 (接地气)**：解决学生“学这门课以后能干什么”的饥渴。必须结合真实的工业应用场景。
2.  **硬核认知锚点 (反常识)**：解决学生“这东西随便糊弄就行”的心态。必须在前 5 分钟内抛出一个能推翻他们直觉常识的极端“核心知识大招”（如香农信息论冰冷定义）。
