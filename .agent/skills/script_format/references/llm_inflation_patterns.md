# LLM 隐性膨胀反模式

> 本文件从 `rule_script_clarity.md` 拆分而来。仅在 `/audit` 深度检查时按需加载。

## §2.8 LLM 隐性膨胀反模式 (LLM Stealth Inflation Anti-Patterns)

> **来源**：对 LLM 产出逐字稿的实证分析——识别出 7 种能**穿透现有 IAR / 修辞通胀检测**的隐蔽膨胀模式。
>
> **核心洞察**：LLM 由于自回归生成机制和 RLHF 安全训练，具有系统性的"多说一点更安全"倾向。这些膨胀不会被标记为 R 类冗余段（因为每段技术上都含有"新信息"），但**对教师记忆负担和学生理解效率构成实质性损害**。

### 2.8.1 压缩比测试（统一检测手段）

对每个自然段执行：
1. 将该段压缩为**最少字数的等效表述**（保留全部不可还原的信息量）
2. 计算 **压缩比 = 压缩后字数 / 原文字数**
3. **压缩比 < 0.4**（原文可被压缩掉 60% 以上而不损失信息）→ 标记 `[INFLATION]` 🟡

> [!TIP]
> 压缩比测试是**总指标**。以下 7 种子模式是**具体触发信号**，帮助定位膨胀的根因并给出精准处置。

### 2.8.2 七种子模式

| # | 模式名称 | 触发信号 | 标记 | 处置 |
|:---:|:---|:---|:---|:---|
| P1 | **结论展开冗余** | 金句/结论句之后，紧跟的段落仅用不同措辞重新解释该结论，无新信息 | `[CONCLUSION_ECHO]` | 删除展开段，金句本身已经足够 |
| P2 | **三段式信封** | `###` 块以"让我们来看…"式预告开头，以"综上/总之"式小结结尾 | `[ENVELOPE_PADDING]` | 删除预告句和总结句，直接进入正文 |
| P3 | **修辞能量过载** | 同一句中 ≥ 2 个极端程度词（"完全/彻底/死命/剧烈/极其"），或同一段中 ≥ 3 个 | `[ENERGY_OVERLOAD]` | 保留 1 个最精准的强度词，其余降级为中性表述 |
| P4 | **对称强迫症** | 两个案例使用完全对称的段落结构，但其中一个案例的信息量仅需 1/3 的篇幅 | `[SYMMETRY_BLOAT]` | 将信息量较少的案例压缩为 1 段或 1 句 |
| P5 | **定义回声** | 同一核心定义在模块内被 ≥ 3 次用不同措辞重述（即使分布在不同案例中） | `[DEFINITION_ECHO]` | 首次完整定义，后续引用时仅用 ≤ 8 字的回指短语（"这种'管用即正义'的特性"） |
| P6 | **脚手架残留** | 段落中存在"写作时帮助进入状态"的背景铺垫句，但该铺垫对读者理解核心概念无贡献 | `[SCAFFOLD_RESIDUE]` | 删除铺垫句，从第一个有信息量的句子开头 |
| P7 | **叙事过度戏剧化** | 案例的情景设置部分字数 > 核心论证部分字数（"戏剧布景比戏本身还长"） | `[DRAMATIZATION_BLOAT]` | 情景设置压缩至 ≤ 1 句（≤ 25 字），将篇幅让给论证 |

### 2.8.3 各模式详解与实例

**P1: 结论展开冗余 (Conclusion Echo)**

```
❌ 原文（3 层同义叠加）：
"鸿沟是表象，模型错位才是病根。
 当执行鸿沟出现时，往往是因为产品的表现模型太靠近实现模型——
 系统强迫用底层的工程术语和用户对话……
 Norman 的鸿沟是临床上的症状诊断工具，告诉你'血流在哪断了'；
 而 Cooper 的三种模型则是病理学框架，从基因层面告诉你'为什么会断'。"
→ 第 1 句是结论，第 2-3 句是展开，第 4 句是用新比喻再述 → 压缩比 < 0.3

✅ 压缩版：
"鸿沟是表象，模型错位才是病根。Norman 告诉你'血流在哪断了'，
 Cooper 则追问'为什么会断'——答案是工程师的系统和用户脑中的世界
 根本不在同一个频道上。"
→ 保留了结论 + 因果推理，删除了中间的重述层
```

**P2: 三段式信封 (Envelope Padding)**

```
❌ "让我们把这个抽象理论带入到日常场景中："  ← 预告句，可直接删除
✅ 直接开始案例正文
```

**P4: 对称强迫症 (Symmetry Bloat)**

```
❌ 恒温器案例（3段完整展开）+ 电梯案例（3段完整展开）
   → 电梯案例的核心信息仅需 1 句话

✅ 恒温器案例（3段完整展开）+ 
   "同样的错位还出现在电梯按钮上——狂按已亮的下行键，
    是将人际催促模型强行套用在只认 0 和 1 的继电器上。"
```

**P7: 叙事过度戏剧化 (Dramatization Bloat)**

```
❌ "寒冷的冬夜你回到家，屋子像冰窖，你急着给冻得发抖的婴儿取暖。
    在这个火烧眉毛的关头，你会怎么操作墙上的空调恒温器？" (50字布景)

✅ "冬夜回家急着取暖，你会怎么调恒温器？" (16字布景)
```

### 2.8.4 写作时自检

每完成一个 `###` 块，执行以下快速扫描：

1. **金句后检查**：刚写完一句有力的结论后，检查下一段是否只是在"解释自己刚说的话"
2. **开头检查**：块的首句是否是"让我们来看/接下来/那么"之类的空转预告
3. **案例篇幅检查**：案例的情景设置是否比论证本身还长
4. **回看检查**：本块中的核心定义，在前面的块中是否已经被说过 ≥ 2 次

### 2.8.5 审计时检测

在 `/audit` Part B-5 脉络清晰度检查中，增加以下扫描：

- 对每个 `##` 模块随机抽取 3 段，执行压缩比测试
- 压缩比 < 0.4 的段落数 ≥ 2 → 标记 `[STEALTH_INFLATION]` 🟡
- 压缩比 < 0.3 的段落数 ≥ 1 → 标记 `[STEALTH_INFLATION]` 🔴
