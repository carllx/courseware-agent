# §1.2.1 DMA 认知降级协议 (DMA Cognitive Downgrade)

> **设计理据**：即便一个术语已在前文被正式定义（L1 层），如果该术语的底层逻辑来自计算机科学/数学/工程学，而 DMA 学生的图式库中缺乏对应的认知脚手架，那么"被教过"≠"被理解"。此时必须对该术语执行"认知降级"。

## 触发条件

当术语满足以下**任一条件**时，即便分类为 L1/L2，仍强制执行降级处置：

| 信号 | 示例 |
|:---|:---|
| 术语源自数据库/编程/数学领域 | Key、Value、Index、Pivot、Schema、Query |
| 术语的日常含义与技术含义存在歧义 | Key（钥匙 vs 主键）、Table（桌子 vs 数据表） |
| 术语无法通过一个生活化画面立即具象化 | Hash、Node、Iterator |

## 降级策略

在**后续所有引用中**（不仅限于首次），持续使用生活化别名，并在首次出现时建立"锚定隐喻"：

| 原术语 | 锚定隐喻（示例） | 后续一致性引用 |
|:---|:---|:---|
| Key（主键） | "就像快递单号——绝不允许重复" | 后续全文统一称"单号" |
| Value（值） | "单号对应的那个包裹" | 后续全文统一称"包裹/内容" |
| Pivot Longer | "把横着摆的衣服竖起来挂好" | 后续全文统一称"竖挂" |

## 禁止行为

- ❌ 禁止在降级后又回退到原术语（认知锚一旦建立，切换会造成混乱）
- ❌ 禁止在同一模块内对同一概念使用两套不同的隐喻体系
