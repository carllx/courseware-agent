# 启发式工作流：饱和度边缘法则 (Saturation Towards Edges)

## 1. 前置条件与上下文 (Prerequisites & Context)
- **应用场景 (WHEN)**: 当你需要基于一个基础颜色生成极其暗的变体（用于深色模式元素、深色文本）或极其亮的变体（用于背景、提示框底层）时。
- **理论依据 (WHY)**: 色彩的亮度和饱和度并不是孤立运作的。在 HSL 模型中，当颜色向纯黑（亮度 0%）或纯白（亮度 100%）极端靠拢时，颜色在视觉上的“色素量”会被冲淡或掩盖。如果你只是单纯地修改 Lightness，而不干预 Saturation，生成的浅色会像被洗过的脏水，生成的深色会显得干瘪发灰。为了保持颜色的鲜活性，必须补偿边缘状态下的饱和度损失。

## 2. 综合指南与最佳实践 (Comprehensive Guide & Best Practices)
- **向边缘增加饱和度 (Increase Saturation Towards Edges)**
  - 构建调色板色阶（例如从 100 到 900）时，中间色调（500 左右，Lightness 接近 50%）的饱和度可以适当居中。
  - 当你推演更亮的颜色（Lightness 增加到 80-90% 以上时），因为有大量白色混入，颜色看起来会被洗水。此时必须**提高 Saturation**，甚至拉伸到 90%-100%，以确保浅色背景仍然带有清晰的色彩倾向，而不是变成肮脏的灰色。
  - 同理，当你推演极暗的颜色（Lightness 降低到 10-20% 以下时），大量黑色混入，暗色容易显得死气沉沉。此时也应**适度提高 Saturation**（相比中间亮度时），让深色带有一种深邃的、发光的底色（如宝石蓝般的暗背景），这对于深色模式的质感至关重要。

## 3. 如果/那么 故障排除逻辑 (If/Then Troubleshooting Logic)
- **IF** 你为某个主色生成的超亮背景色（用于提示框）看起来毫无生气，像是一块被弄脏的白布，**THEN** 说明在提高 L 值的过程中，饱和度（S）被稀释的视觉效果没有得到补偿。将其饱和度提高到 80% 甚至 100%。
- **IF** 在深色模式下，由品牌色演化出的深色背景板显得灰蒙蒙的，缺乏高级感，**THEN** 这种“干瘪感”是因为饱和度偏低。增加 S 值，同时可以尝试稍微调整 Hue（色相）模拟深邃夜空的感觉（比如冷色向蓝紫偏移，暖色向红橙偏移）。
- **IF** 色阶系统中的中间色调（如 500、600）非常刺眼，**THEN** 中间亮度的纯色携带了最原始的色彩能量。如果它们饱和度过高，会导致“霓虹灯”效应。应适当降低中间亮度的饱和度，将高饱和度留给浅色和深色变体。

## 4. 验证检查单 (Verification Checklists)
- [ ] 检查从最亮（100/50）到最暗（900/950）的色阶系统，是否呈现出边缘饱和度高于中间饱和度的“U”型分布？
- [ ] 极浅的背景色（如 Info、Warning、Success 背景）是否保持了清晰的色相识别度，没有发灰发脏？
- [ ] 深色模式中的暗色卡片背景是否含有足够的饱和度，传达出品牌的色温（冷灰或暖灰）？
- [ ] 在提取色阶的代码逻辑中，是否有动态补偿 S 值的曲线算法？
