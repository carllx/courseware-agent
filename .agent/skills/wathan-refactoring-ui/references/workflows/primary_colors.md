# 主色应用工作流 (Primary Colors)

## Prerequisites & Context (前提与背景)
- **WHY (为什么需要主色策略)**: 主色（Primary Colors）代表了品牌的灵魂，是用户对产品的首要视觉记忆。它也是引导用户注意力和执行核心交互（Call to Action）的关键信号。
- **WHEN (什么时候使用)**: 当你在一片灰度的UI中，需要引导用户点击、选择，或者展示品牌标识、活动状态时。

## Comprehensive Guide & Best Practices (综合指南与最佳实践)
1. **克制使用原则**:
   - 避免将主色填满整个屏幕。如果一切都是主色，主色就会失去其“强调”的作用。
   - 使用大量的空白和中性色作为背景，让主色在关键的按钮或焦点元素上“发光”。
2. **不要只准备一个主色**:
   - 单一的品牌色是不够的。你需要围绕这个基础主色，生成一个包含暗色调、亮色调的色阶系统。
   - 在 hover 状态下，你可能需要一个更暗的主色；在激活背景或低关注度的标签上，你需要一个极浅的、以主色为基调的背景色。
3. **主色的层级表达**:
   - **高优 (High-priority)**: 实心的主色按钮（如 Submit）。
   - **中优 (Medium-priority)**: 带有主色边框和文本的透明/白色按钮。
   - **低优 (Low-priority)**: 主色作为极浅背景色，配合常规深色文本的标签或微小的高亮区域。

## If/Then Troubleshooting Logic (故障排除逻辑)
- **IF** 界面的品牌感太重，让用户感到压抑或难以辨认核心内容：
  - **THEN** 将大面积的主色块替换为白色或浅灰色，并限制主色仅出现在品牌 Logo、主按钮和选中的控件上。
- **IF** 主色在按钮上的文本难以阅读：
  - **THEN** 主色的亮度可能处于尴尬的中间位置。你必须改变主色的亮度，或者改变文本的颜色（黑或白），以确保文字和主色背景的对比度达标。
- **IF** 没有主色的变体可用于交互状态（如 Hover）：
  - **THEN** 基于主色的 Hue，建立一组完整的深浅色阶，停止使用纯黑/纯白叠加不透明度的方式来模拟变暗变亮。

## Verification Checklists (验证清单)
- [ ] 主色的使用是否具有明确的意图和焦点，而不是为了装饰而装饰？
- [ ] 是否为核心主色构建了完整的配套色阶（极浅的背景、较暗的 Hover 态等）？
- [ ] 界面是否在大部分区域留给了中性色，以突显主色的有效性？
- [ ] 主色在深色模式和浅色模式下，是否都保证了足够的可读性和对比度？
