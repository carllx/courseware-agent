# 启发式工作流：字间距控制 (Letter Spacing)

## 1. 前置条件与上下文 (Prerequisites & Context)
- **应用场景 (WHEN)**: 在排版系统中使用超大字号（如页面主标题）、超小字号（如说明文本）以及全大写字母（All Caps 标签、徽章或分类名称）时。
- **理论依据 (WHY)**: 字体的默认字间距（Tracking / Letter Spacing）是根据常见的正文大小（如 16px）精心设计的。当系统强行对字体进行放大或最极端地应用全大写时，原有的比例平衡会被打破。不恰当的间距会使单词显得松散脱节，或挤作一团难以辨认。

## 2. 综合指南与最佳实践 (Comprehensive Guide & Best Practices)
- **收紧大标题 (Tighten Headlines)**
  - 当字号变大时，字母之间的绝对空白空间也同比例放大，这会导致大标题在视觉上呈现出一种漏风、松垮的感觉。
  - **最佳实践**：字号越大，字间距应该越小（负向间距）。为 H1、H2 等大字号标题应用微小的负字间距（例如 `-0.01em` 到 `-0.05em`，或 Tailwind 中的 `tracking-tight` / `tracking-tighter`）。这能让大字号文本的物理密度回归紧凑，增强视觉冲击力。
- **增加全大写字母间距 (Increase Spacing For All Caps)**
  - 小写字母通过多样的升部（ascenders）和降部（descenders）创造了丰富的外部轮廓，帮助大脑快速识别单词。而全大写字母呈现的都是方块状的轮廓，如果按照默认间距紧挨在一起，很容易糊成一团，难以阅读。
  - **最佳实践**：任何时候使用全大写字母（尤其是小字号时），都必须增加其字间距（正向间距，例如 `0.05em` 到 `0.1em`，或 `tracking-wide` / `tracking-wider`）。拉开间隙能极大地提高全大写文本的清晰度。

## 3. 如果/那么 故障排除逻辑 (If/Then Troubleshooting Logic)
- **IF** 你的 Hero Section 大标语看起来像是一串零散的字母拼凑出来的，而不是一个强有力的整体声明，**THEN** 说明大字号放大了默认的字间距。引入负的字间距（如 `letter-spacing: -1px`），让字母紧密拥抱。
- **IF** UI 中的分类标签或状态徽章（如 "NEW", "COMPLETED"）虽然使用了全大写，但看起来很拥挤、廉价、不易识别，**THEN** 添加额外的字间距。将其字间距拉宽，同时配以稍微加粗的字重（如 Semibold），会让标签看起来更加精致、昂贵。
- **IF** 你修改了正文字体的字间距以求“个性化”，**THEN** 立即撤销。永远不要轻易调整常规正文文本（14-18px）的字间距，字体设计师已经为你做好了最适合长文阅读的设定。

## 4. 验证检查单 (Verification Checklists)
- [ ] 页面中所有大于 24px 的标题是否都应用了适当的负字间距以保持紧凑？
- [ ] 所有采用 `text-transform: uppercase` 的文本是否都同步增加了正向字间距？
- [ ] 常规阅读的正文段落是否保持了字体默认的字间距（未经任何覆盖）？
- [ ] 组件库中对按钮、徽章内的全大写文本是否内置了 `letter-spacing` 设定？
