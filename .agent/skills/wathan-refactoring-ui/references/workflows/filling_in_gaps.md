# 填补色阶间隙工作流 (Filling In Gaps)

## Prerequisites & Context (前提与背景)
- **WHY (为什么要关注色阶间隙)**: 当基准色（500级）以及最亮边界（100级）和最暗边界（900级）确定后，剩余的颜色如果不进行合理、线性的过度，会导致UI中缺乏合适的颜色变体用于边框、副文本或次要状态。填补这些空隙构成了可用设计系统的血肉。
- **WHEN (什么时候使用)**: 在确定了基准色和边缘色，需要产出完整可用调色板（例如包含 100 到 900 共 9 个色阶）的最后步骤时。

## Comprehensive Guide & Best Practices (综合指南与最佳实践)
1. **建立等比或感知的视觉台阶**:
   - 你需要在 100 和 500 之间填补 200, 300, 400；在 500 和 900 之间填补 600, 700, 800。
   - 不要只依赖数学模型（严格平分明度）。人眼的感知是非线性的，请相信你的眼睛。步长应该感觉上是均匀的。
2. **在真实的 UI 组件中测试**:
   - **绝对不要**仅仅盯着一排并列的色块进行调整。并列的色阶看起来完美，不代表它们在 UI 中好用。
   - 建立一个“测试沙盒”组件：例如，一个包含浅色背景 (100)，边框 (300)，图标 (400)，以及文本 (900) 的告警框。
   - 如果你发现 300 作为边框太暗，而 200 又太亮，这就说明低色阶的间隔需要微调。
3. **分配通用角色作为向导**:
   - **100/200**: 通常用于背景。
   - **300/400**: 通常用于非交互元素的边框、禁用状态、线条。
   - **500**: 主色的基准，用于主要按钮。
   - **600/700**: 悬停状态的主按钮、或作为深色模式下的操作背景。
   - **800/900**: 主要文本。

## If/Then Troubleshooting Logic (故障排除逻辑)
- **IF** 在构建 UI 时，总是觉得“少了一个颜色”（比如觉得 400 太浅而 500 太深）：
  - **THEN** 你的色阶在这段区间出现了非线性的断层。回顾并重新调整 400 和 500 之间的感知距离，重新分配亮度和饱和度。
- **IF** 所有的浅色背景（100 到 300）在显示器上看起来几乎一模一样：
  - **THEN** 暗部的步长过大，而亮部的步长过小。你需要压缩暗部之间的差异，拉大亮部层级之间的亮度差距，以满足多级浅色背景的需求。
- **IF** 按照纯数学等分的颜色感觉十分生硬和缺乏活力：
  - **THEN** 这是因为随着亮度的变化，颜色的“感知纯度”也会流失。此时必须在填补间隙的同时，结合“色相偏移 (Hue Rotation)”的方法来修正每个色阶。

## Verification Checklists (验证清单)
- [ ] 100 到 900 之间的每个数字级别是否都能在视觉上与相邻级别明显区分？
- [ ] 是否在模拟了真实的 UI 场景（背景+边框+文字）对这套色阶进行了测试？
- [ ] 每个编号阶段的颜色是否都有明确的功能性归属（如 200 是默认背景，400 是默认边框）？
- [ ] 色板构建完毕后，是否不再产生即时硬编码新颜色的冲动？
