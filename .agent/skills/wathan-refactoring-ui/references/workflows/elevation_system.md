# 阴影与层级系统工作流 (Elevation System Workflow)

## 前置条件与上下文 (Prerequisites & Context)
在现代用户界面设计中，单纯的平面设计容易导致视觉层级扁平化，用户难以区分交互焦点与背景内容。
- **为什么使用 (WHY)**: 
  - **建立深度与层级**：阴影不仅仅是视觉特效，更是用来将界面元素放置在虚拟的 Z 轴上，传达有意义的深度感。
  - **引导用户注意力**：元素在视觉上感觉离用户越近，就越能吸引他们的注意力。
  - **减少视觉噪点**：通过阴影、背景色和间距来区隔内容，可以有效减少边框的使用，从而避免界面显得杂乱无章。
- **何时使用 (WHEN)**:
  - 当需要设计按钮、下拉菜单或模态弹窗等悬浮组件时。
  - 当需要通过交互（如悬停、点击、拖拽）给予用户视觉反馈时。
  - 当你觉得界面元素之间需要分离，但直接加边框又显得界面过于拥挤时。

## 综合指南与最佳实践 (Comprehensive Guide & Best Practices)

### 1. 建立标准的层级系统 (Establishing an Elevation System)
与其每次都随机调整参数，不如像管理颜色、排版和间距一样，定义一套固定的阴影集合（通常 5 个层级就足够了）。
- **小阴影 (低层级)**: 模糊半径小，紧贴元素。使元素看起来只比背景稍微高一点。适用于按钮等需要被注意到但不能喧宾夺主的元素。
- **中等阴影 (中层级)**: 模糊半径中等。适用于下拉菜单 (Dropdowns) 等需要在整个 UI 中稍微突出一些的元素。
- **大阴影 (高层级)**: 模糊半径大。适用于模态弹窗 (Modal dialogs)，这类元素需要完全捕获用户的注意力，并且感觉离用户最近。
- **构建方法**: 首先定义你的“最小阴影”和“最大阴影”，然后以线性的方式填补中间的 3 个层级，使它们的尺寸递增。

### 2. 双层阴影技术 (Two-part Shadows)
细致的阴影通常由两部分叠加而成，每个阴影各自承担不同的物理模拟职责：
- **光源阴影 (Direct Light Source)**: 
  - **特征**: 尺寸更大、更柔和、垂直偏移 (vertical offset) 明显、模糊半径大。
  - **作用**: 模拟直接光源在物体后方投射的物理阴影。
- **环境光遮蔽阴影 (Ambient Occlusion)**: 
  - **特征**: 更紧凑、更暗、垂直偏移很小或没有、模糊半径小。
  - **作用**: 模拟物体底部或边缘难以被环境光照亮而产生的深色暗角。
- **动态调整**: 随着物体在 Z 轴上远离表面（层级升高），由于环境光更容易照射到底部，那个紧密且深色的第二层阴影会逐渐变淡甚至消失。在最低层级时，它应该非常明显；在最高层级时，几乎或完全不可见。

### 3. 将阴影与交互结合 (Combining Shadows with Interaction)
阴影不仅用于静态的 Z 轴定位，还可以作为用户交互的强大视觉线索：
- **拖拽 (Drag and Drop)**: 当用户点击并准备拖拽列表中的某个项目时，增加该项目的阴影大小。这会给人一种它在列表中“弹出”并悬浮于其他项目之上的错觉，明确表示它现在可移动。
- **点击下压 (Active/Pressed State)**: 当用户点击一个按钮时，可以通过切换到较小的阴影，或者完全移除阴影，来模拟按钮被“按下”嵌入页面的物理感觉。
- **思考模型**: 不要仅仅思考“我要加个什么阴影”，而应该思考“这个元素现在在 Z 轴的哪一层”，然后赋予它对应的层级阴影。

### 4. 减少边框的使用 (Use Fewer Borders)
过多的边框会让设计显得繁忙和杂乱。在分隔两个元素时，尝试以下替代方案：
- **使用盒子阴影 (Box Shadow)**: 盒子阴影可以像边框一样勾勒出元素的轮廓，但更为微妙，不会分散注意力。特别是当应用阴影的元素与背景颜色不同时，效果最好。
- **使用不同的背景色**: 给相邻的元素设置略微不同的背景色通常就足以在它们之间建立区分。如果你已经使用了不同的背景色，试着把边框删掉，你会发现其实不需要它。
- **增加额外的间距 (Extra Spacing)**: 没有什么比直接拉开距离更能有效地分隔元素了。这种方式无需引入任何新的 UI 视觉线索即可在元素组之间建立明显的区分。

## If/Then 故障排除逻辑 (If/Then Troubleshooting Logic)

- **IF** 界面看起来过于扁平且缺乏层次感，**THEN** 检查是否所有的悬浮元素（如下拉菜单、卡片、弹窗）都使用了相同的阴影，或者根本没有阴影。请应用 5 级层级系统为它们分配不同的 Z 轴高度。
- **IF** 元素的阴影看起来很脏或不真实，**THEN** 检查是否只使用了一层阴影且颜色过深。改为使用“双层阴影技术”，将扩散大的柔和阴影和底部紧贴的深色阴影组合使用。
- **IF** 两个相邻的内容块难以区分，但加上边框后又显得像个网格一样死板，**THEN** 移除边框，尝试将其中一个区块的背景色微微加深，或者大幅增加两个内容块之间的空白间距 (Margin/Padding)。
- **IF** 模态弹窗感觉没有脱离底层页面，**THEN** 检查其阴影的模糊半径是否过小。必须为最高层级的模态弹窗使用系统内最大的阴影，并确保双层阴影中的“环境光暗影”已经透明或消失。
- **IF** 按钮在点击时缺乏点击感，**THEN** 检查确保在 `:active` 状态下将阴影减小或移除，同时可以配合轻微的垂直位移（如 `translateY(1px)` 或 `translateY(2px)` 模拟物理按下效果）。

## 验证检查表 (Verification Checklists)

- [ ] **系统化**：是否已经定义了一套包含不多于/不少于 5 个级别的标准阴影系统？
- [ ] **物理真实性**：精细的阴影是否采用了双层阴影构建（一层大而柔和的光源阴影，一层小而暗的环境光阴影）？
- [ ] **层级递进一致性**：低层级的紧凑暗阴影是否在升到高层级时逐渐减弱并消失？
- [ ] **交互反馈**：可交互的元素（按钮、拖拽卡片）在被点击或拖拽时，其阴影大小是否发生改变以反映 Z 轴的高度变化？
- [ ] **边框精简检查**：审查设计中的所有线条边框。是否可以通过背景色差异、微妙的盒子阴影或增加间距来替代部分边框，以达到“降噪”目的？
