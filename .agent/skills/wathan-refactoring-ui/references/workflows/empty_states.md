# 工作流：精心设计空状态 (Don't Overlook Empty States)

## Prerequisites & Context (前提与背景)
- **WHY (为什么要关注空状态)**: 在设计新功能或应用时，设计师习惯于填充完美、真实且极具吸引力的占位数据（头像、用户名、长文本等），从而打造出令人惊艳的界面。然而，当真实用户第一次打开这个功能时，由于没有任何用户生成内容（User-Generated Content, UGC），他们往往会面对一个干瘪的表格或一句冷冰冰的“暂无数据”。空状态是用户体验生命周期中的“第一印象”，如果设计得敷衍了事，将极大地降低用户的探索欲和产品的质感。空状态不应被视为边缘情况（Afterthought），而应作为产品引导的优先级核心。
- **WHEN (何时使用此工作流)**: 在设计任何依赖用户输入、数据填充或第三方集成的列表、仪表盘、消息通知、文件库等功能界面时。如果这个界面在未填充数据前呈现为空白或只显示表头，就必须立刻切入此工作流进行设计重构。

## Comprehensive Guide & Best Practices (综合指南与最佳实践)
将空状态从“数据缺失的报错提示”转变为“激发用户操作的营销落地页”。

### 1. 注入视觉趣味性 (Incorporate Visual Interest)
不要仅仅给出一行居中的灰色文字。
- **图像与插画**：使用高质量的图标、插画或微动画来占据屏幕的主视觉区域，吸引用户的注意力。即使你没有专业的插画师，使用简单的几何图形组合或与主题高度相关的放大版 SVG 图标，也能极大缓解视觉上的空虚感。
- **传递情绪价值**：空状态是展现产品性格的好机会。通过有趣、诙谐或温暖的视觉元素与文案，缓解用户在面对全新空白界面时的无所适从感，让产品显得更加生动与人性化。

### 2. 强化“行动号召” (Emphasize the Call-To-Action, CTA)
空状态的核心目的是终结自己，让用户产生内容。
- **清晰的操作指引**：在视觉图形下方，用简洁有力的标题说明当前状态（例如：“你的项目库还是空的”），并紧跟一段辅文，解释产生数据的好处（例如：“创建第一个项目，开启团队高效协作”）。
- **醒目的主按钮**：放置一个高对比度的首要行动按钮（Primary Button，如“创建新项目”或“导入数据”）。不要让用户去页面右上角的隐蔽角落寻找创建按钮，必须将 CTA 直接摆在空状态视线的正中心。

### 3. 隐藏无效的辅助性 UI (Hide Supporting UI)
展示无法使用的功能是一种糟糕的用户体验。
- **移除干扰项**：如果你正在设计一个拥有分类标签（Tabs）、搜索框或过滤器的列表页面，当列表为空时，务必将这些控件完全隐藏。
- **简化认知负荷**：在没有数据的情况下，提供筛选或搜索是毫无意义的。将这些复杂的辅助性控件隐藏起来，能确保用户的视线 100% 聚焦在唯一的“创建/添加”操作上，降低决策成本。

## If/Then Troubleshooting Logic (故障排查与边缘情况逻辑)
- **IF** 你在开发一个通用的空状态组件，但并非所有场景都允许用户直接“创建”内容（例如：搜索结果为空，或数据完全由系统后台生成，用户无权添加）：
  - **THEN** 调整空状态的目的。此时不应展示强烈的“创建”按钮，而应提供“次优解”。例如，对于搜索结果为空，提供清除搜索条件、重置过滤器或返回上一页的次级按钮；对于系统生成的数据，提供帮助文档链接或说明数据何时会被生成的文案。
- **IF** 隐藏辅助性 UI（如筛选器和 Tabs）导致页面布局在数据加载前后发生剧烈的跳动（Layout Shift），或让用户不清楚页面具有哪些分类维度：
  - **THEN** 权衡业务需求。如果分类 Tabs 具有强烈的导航意义（例如让用户知道还有哪些类型的资源），可以保留 Tabs 但禁用（置灰）它们，或者仅在当前激活的 Tab 下展示针对性的空状态引导（并保留其他 Tab 的可点击状态）。
- **IF** 空状态占据了过多的垂直空间，导致在移动端或小屏幕设备上下方的主干内容被挤出视口：
  - **THEN** 对空状态插画或图形进行响应式缩放。在较小视口下，缩小插图尺寸、精简辅文内容，确保最重要的 Call-To-Action 按钮始终处于首屏可见区域。

## Verification Checklists (验证与审查清单)
- [ ] **视觉丰富度审查**：是否摆脱了单纯的文本提示？是否添加了能够吸引注意力、体现品牌性格的图形或插画元素？
- [ ] **操作闭环验证**：空状态页面中是否包含一个明显、易于点击的 Call-To-Action（如“新增”、“导入”），引导用户立即打破这个空状态？
- [ ] **文案引导检查**：空状态的文案不仅描述了“当前没有数据”，是否还说明了“为什么没有”以及“添加之后有什么好处”？
- [ ] **干扰清理**：在数据为空时，是否成功隐藏或禁用了那些毫无作用的排序、过滤、搜索和批量操作控件？
- [ ] **极端数据量验证**：是否针对所有的集合视图（列表、卡片网格、表格）都规划了空状态（0 items）以及少数据状态（1-2 items）的显示效果？
