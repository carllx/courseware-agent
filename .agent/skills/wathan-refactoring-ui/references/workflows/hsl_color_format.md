# 启发式工作流：拥抱 HSL 颜色格式 (HSL Color Format)

## 1. 前置条件与上下文 (Prerequisites & Context)
- **应用场景 (WHEN)**: 从零开始建立 UI 调色板，需要生成同一颜色的多种色阶（用于悬停、激活、边框、背景状态），或在代码中动态调整颜色特性时。
- **理论依据 (WHY)**: 绝大多数开发者习惯使用十六进制代码（Hex，如 `#2D9CDB`）或 RGB 值。然而，Hex 格式是设计给机器看的，它将红、绿、蓝混合的数据加密在字符中，人类无法直观地从中推断出颜色的明暗和鲜艳程度。在设计 UI 时，我们很少需要随机挑选一种新颜色，绝大多数工作是在调整现有颜色的亮度（使其变暗用于 Hover 状态，变亮用于背景）。在这方面，Hex 无能为力，而 HSL（色相，饱和度，亮度）则完美贴合人类的视觉认知模型。

## 2. 综合指南与最佳实践 (Comprehensive Guide & Best Practices)
- **彻底抛弃 Hex，转向 HSL (Ditch Hex For HSL)**
  - HSL 格式将颜色的三个最核心物理维度解耦：
    - **Hue (色相)**：0-360 的角度值（0=红，120=绿，240=蓝）。
    - **Saturation (饱和度)**：0-100% 的比例（0=全灰，100=最鲜艳）。
    - **Lightness (亮度)**：0-100% 的比例（0=纯黑，50=纯色，100=纯白）。
  - 在 CSS 中，全面使用 `hsl(H, S%, L%)` 进行颜色定义。
- **直观的色阶推演**
  - 要为按钮创建一个 Hover 状态颜色？使用 Hex 你需要打开调色盘软件；使用 HSL，你只需要将 `Lightness` 值减去 5% 到 10%（例如从 `hsl(210, 50%, 50%)` 变为 `hsl(210, 50%, 40%)`），颜色将完美变暗而不会偏色。
  - 需要一个浅色的提示框背景？只需将主色的亮度拉到极高的值（如 90% 到 95%），色相和饱和度维持不变即可。
- **语义化的 CSS 变量**
  - 结合 CSS 自定义属性构建动态主题时，仅存储 H、S、L 的数值作为变量：
    `--primary-h: 210; --primary-s: 50%; --primary-l: 50%;`
    然后可以轻松合成变体：`background: hsl(var(--primary-h), var(--primary-s), calc(var(--primary-l) - 10%));`。

## 3. 如果/那么 故障排除逻辑 (If/Then Troubleshooting Logic)
- **IF** 你的代码库中充斥着随意挑选的十六进制色值，并且难以找出哪些颜色属于同一个色系，**THEN** 采用工具将核心 Hex 转换回 HSL。你会发现许多被认为是同一色系的颜色，其 Hue（色相）其实在剧烈跳动，立即对齐它们的 Hue 值进行系统重构。
- **IF** 你在使用 HSL 建立深色模式，简单的反转亮度（L）导致颜色发灰或刺眼，**THEN** 除了调整 L 之外，别忘了调整 S（饱和度）——深色模式下的颜色通常需要更低的饱和度以防刺眼，具体见饱和度工作流法则。
- **IF** 项目需要更高的颜色空间支持（如 P3），**THEN** 可以无缝迁移到概念一致的现代色彩函数（如 `oklch` 或 `hwb`），它们保留了将亮度与色调解耦的核心逻辑。

## 4. 验证检查单 (Verification Checklists)
- [ ] 样式表和设计令牌（Design Tokens）是否全面采用 HSL（或其他知觉均匀色彩空间）替代了 Hex/RGB？
- [ ] 同一组件的不同状态（默认、悬停、激活、禁用）的颜色推演是否仅通过修改 HSL 中的亮度/饱和度实现，而保持色相一致？
- [ ] 开发者在需要微调颜色亮度时，是否能在不打开外部调色工具的情况下直接修改代码中的百分比数值？
