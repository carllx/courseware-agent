# 元素固有尺寸法则 (Everything has an intended size)

## 1. 前置条件与上下文 (Prerequisites & Context)

**为什么重要 (WHY)**:
在界面设计中，任何图形元素（如图片、图标、截图、Logo）都有其“预期”或“固有”的尺寸。如果违背其原有设计意图，强制放大或缩小这些元素，即使是不会发生像素级失真的矢量文件（如 SVG），也会导致界面显得极其不专业、缺乏细节或模糊不清。因此，设计不仅仅是把元素放入网格，而是要尊重元素的原始设计精度与尺度限制。

**适用场景 (WHEN)**:
- 在落地页（Landing Page）的“功能介绍”区等需要展示大图标的场景。
- 需要在界面中嵌入应用截图、功能预览等真实画面的场景。
- 设计 Favicon、网页标题栏图标或小尺寸界面标志时。
- 任何涉及图片、矢量图标或 Logo 的缩放、适配操作。

## 2. 综合指南与最佳实践 (Comprehensive Guide & Best Practices)

### 2.1 严禁过度放大图标 (Don't Scale Up Icons)
- **理论依据**：图标在设计时具有特定的基础网格（通常是 16px 或 24px）。虽然矢量图（SVG）在技术上无损缩放，但在视觉感知上，针对小尺寸绘制的图标被放大 3x 或 4x 时，线条会变得异常粗犷（“chunky”），整体显得缺乏细节，比例失调。
- **最佳实践**：如果手头只有小尺寸图标，而你需要填充一个较大的空间（如大卡片顶部），**不要直接放大图标**。
- **可执行方案**：
  - 将原尺寸的图标放置在一个更大尺寸的基础图形（如圆形、圆角矩形）内部。
  - 为基础图形赋予合适的背景色（Background Color）或柔和的渐变。
  - 这样既让实际图标保持在或接近其“预期尺寸”，又能在视觉上完美填充大面积留白，显得精致且专业。

### 2.2 避免过度缩小截图 (Don't Scale Down Screenshots)
- **理论依据**：在界面展示中，直接将全尺寸的桌面端截图等比缩小（如缩小 70%）来适应狭窄布局，会导致过多的细节被挤压在一个极其有限的空间里。应用中原本 16px 的正文在截图中会变成 4px，导致用户即使贴近屏幕也无法阅读其中的文字。
- **最佳实践**：不要试图将大屏全局截图塞入小容器。你需要通过控制截图的源尺寸或裁剪方式来保留可读性。
- **可执行方案**：
  - **降低源截图的设备尺寸**：不要截取 1080p 的桌面全景，而是截取平板端（Tablet Layout）或移动端界面的截图。这样本身的信息密度更符合展示空间，不需要过度缩小。
  - **局部截图法 (Partial Screenshot)**：不需要展示完整界面时，只截取最核心、最具代表性的局部区域。在同样大小的展示空间里，局部截图可以保持 1:1 的缩放比例或更少缩水，从而保留清晰的细节。
  - **线框/抽象化重绘 (Simplified UI Graphic)**：如果你的确需要在有限空间内展示“整个应用的宏观布局”（Whole-app Screenshot），那么直接放弃真实截图。将应用界面重绘为抽象的矢量图：去掉复杂的细节，将小字文本替换为简单的横线（线框风格）。这种方式传达的是“结构”和“印象”，而不会引诱用户眯着眼睛去试图阅读内容。

### 2.3 禁止强行缩小大尺寸图标或Logo (Don't Scale Down Icons/Logos)
- **理论依据**：就像小图标放大后显得笨拙一样，那些专为大尺寸展示而绘制的图标或 Logo（如 128px 或更大），在被缩小到极小尺寸（如 16px 的 Favicon）时，细节会全部糊在一起（“mush”）。浏览器为了保留这些密集的细节而进行的重采样渲染会使图像变得毛糙且不可辨认。
- **最佳实践**：你不能依赖浏览器或设计软件的自动缩放算法。对于极小尺寸的场景，你需要人工干预。
- **可执行方案**：
  - **重新绘制极简版本**：针对目标尺寸（Target Size，例如 16x16 px），手动重新绘制一个高度简化的 Logo 或图标版本。
  - **人工取舍细节**：去掉原版中多余的线条、文字、渐变和装饰。将核心特征提炼到能在低像素网格中清晰呈现的程度。这样，设计品质由调控你把控，而不是交给浏览器的渲染算法。

## 3. If/Then 故障排除逻辑 (If/Then Troubleshooting Logic)

- **IF** 发现放大后的矢量图标显得笨重、线条极粗且缺少精致感，**THEN** 停止继续放大图标本体，恢复到其基础网格尺寸（如 24px），然后在外面套一层带有背景颜色的几何形状（圆形/方块），整体放大这个复合体。
- **IF** 界面中的应用截图文字完全看不清，用户反馈需要放大镜才能看，**THEN** 说明截图被过度缩小。应改用该应用的较小断点布局（如平板版）重新截图，或者仅截取需要说明功能的核心局部。
- **IF** 需要在极小的展示框中展示全屏宏观布局（必须看清整体结构但无需看清字），**THEN** 放弃位图截图，改用几何色块与线条绘制一个抽象化的 UI 示意图。
- **IF** 网页的 Favicon 或小尺寸 Logo 看上去模糊成一团，**THEN** 不要使用全局统一的那个高分辨率 Logo 资源，必须在设计软件中新建一个 16x16 或 32x32 的画板，手工画一个删减了复杂细节的超极简版专属 Logo。

## 4. 验证清单 (Verification Checklists)

- [ ] **图标比例检查**：检查项目中所有的矢量图标，确认它们是否在或接近其原始设计的基准网格尺寸（如 16px、24px、32px）。
- [ ] **大尺寸图标装饰检查**：当需要在大面积留白中使用图标时，是否采用了背景形状包裹的方法，而非单纯暴力拉伸图标线条？
- [ ] **截图可读性检查**：检查所有嵌入在营销页或说明文档中的应用截图，其中的文本是否依然具备起码的可读性？是否没有出现因过度缩小导致的“文字变横线”的像素模糊？
- [ ] **截图策略检查**：对于截图展示，是否恰当评估并应用了“局部截图”、“平板端/移动端截图”或“抽象线框示意图”的策略？
- [ ] **多尺寸 Logo 资产检查**：项目是否不仅拥有一张全分辨率的高清 Logo，还同时配备了专门为极小尺寸（如 Favicon）手工优化过的简化版 Logo 资源？
- [ ] **浏览器渲染妥协检查**：所有微小尺寸的视觉元素，是否都是由设计师主动做出的细节妥协（人工绘制极简版），而非交给浏览器强制压缩缩放的产物？
