# 色温与情感设定工作流 (Color Temperature)

## Prerequisites & Context (前提与背景)
- **WHY (为什么关注色温)**: 颜色的色温（暖色 vs 冷色）从根本上决定了界面的情感基调和用户的心理感受。哪怕只是极为微弱的底色偏向，也能在潜意识中影响用户对产品的评价——是“冰冷、机械的”，还是“热情、人性化的”。
- **WHEN (什么时候使用)**: 在项目的概念阶段设定视觉语言，或当用户反馈产品看起来过于“缺乏人情味”或过于“不够专业”时。

## Comprehensive Guide & Best Practices (综合指南与最佳实践)
1. **冷色调的传递 (Cool Colors)**:
   - **组成**: 主要由蓝色、青色和少许紫色组成。
   - **传达情感**: 宁静、专业、科技感、严谨、隔离感。
   - **适用场景**: 企业级 SaaS 平台、数据控制台、医疗软件、以及希望建立强烈信任感和高效感的工具。在这些系统中，不仅主色可以冷，中性灰也应当设定为“冷灰（Cool Greys）”。
2. **暖色调的传递 (Warm Colors)**:
   - **组成**: 红色、橙色、黄色及土色系。
   - **传达情感**: 活力、热情、人性化、复古、诱惑力、亲和力。
   - **适用场景**: 社交应用、电商平台（尤其是食品或生活方式）、内容创作工具、或任何主打“温情”陪伴的产品。对应的，中性系统应该向“暖灰（Warm Greys）”靠拢。
3. **冲突与互补 (Conflict & Complements)**:
   - 单纯的冷或暖可能让视觉产生疲劳。高级的设计通常采用一种色温作为绝对统治者，然后少量使用其对立的色温来制造“震荡（Tension）”。
   - 例如：在一个绝对冷酷的蓝色管理后台中，使用温暖的橙色作为少数关键的强调色按钮，效果会极其惊艳。

## If/Then Troubleshooting Logic (故障排除逻辑)
- **IF** 一个面向生活方式的 APP 看起来像个银行的客户端：
  - **THEN** 检查并替换掉中性色中的纯灰或冷灰。把你的背景、边框颜色全部倾向带有一点黄色或棕色的暖灰。同时考虑将主色从冷色系替换为偏暖的色系。
- **IF** 界面的色温让用户感到过于跳跃和不专业：
  - **THEN** 收敛过度的暖色调。把大面积使用的高纯度红色或橙色替换为更稳重的深蓝色，将界面的情感重心拉回到“客观与理智”的冷色温域。
- **IF** 界面色调平淡，缺乏视觉抓手：
  - **THEN** 引入“色温冲突”。在大量冷色调的环境下，挑选一处需要引导用户视线的地方使用暖色调，利用冷暖的天然对抗来建立无形的引导线。

## Verification Checklists (验证清单)
- [ ] 整个系统的核心色温是否与产品的定位（科技感 vs 人情味）完全一致？
- [ ] 主色与中性灰的色调是否属于同一体系，或者具有经过深思熟虑的互补关系？
- [ ] 是否利用了冷暖色调的反差来引导用户对强调按钮的注意力？
- [ ] 界面是否避免了在没有明确意图的情况下随机混合各种不同色温的色彩？
