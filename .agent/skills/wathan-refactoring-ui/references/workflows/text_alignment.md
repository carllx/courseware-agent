# 启发式工作流：文本对齐策略 (Text Alignment)

## 1. 前置条件与上下文 (Prerequisites & Context)
- **应用场景 (WHEN)**: 布局任何文字内容时，包括文章正文、标题组、表格数据以及多段落的组件（如卡片、模态框）。
- **理论依据 (WHY)**: 文本对齐直接控制着眼睛阅读时的起点与终点。人类阅读（特别是从左到右书写的语种）习惯于拥有一个坚固、统一的起点线。错误的对齐方式会极大增加视觉检索的认知负荷，导致阅读速度下降、疲劳以及数据对比困难。

## 2. 综合指南与最佳实践 (Comprehensive Guide & Best Practices)
- **英语/中文正文左对齐 (Left Align For English)**
  - 绝大多数文本应当默认采用左对齐（或对于 RTL 语言为右对齐）。
  - 这提供了一条垂直对齐的左侧“锚线”，让读者的视线每次扫视换行时，都能精确无误地找到下一行的起点。
- **禁止居中长文本 (Don't Center Long Form Text)**
  - 永远不要将超过 2-3 行的文本居中对齐。
  - 居中对齐使得每一行的起点都在变化，读者的眼睛无法依靠肌肉记忆换行，必须在每次换行时重新搜寻起点，这是灾难性的阅读体验。居中对齐仅适用于极短的独立元素（如单行标题、小徽章内的字）。
- **右对齐数字 (Right Align Numbers)**
  - 在表格、财务报表或任何需要进行数值比对的列表中，包含小数或个位数的数字必须采用右对齐。
  - 右对齐可以确保数值的小数点或个位数位于同一垂直线上，让用户瞬间扫视就能通过字符串长度直观比较数量级的差异。
- **带连字符的两端对齐 (Hyphenate Justified Text)**
  - 尽量避免使用两端对齐（Justify），因为它常在词汇间产生巨大且不规则的空白（河流效应）。
  - 如果受制于特定排版风格（如模仿报纸印刷）必须使用两端对齐，则必须开启 CSS 连字符属性（`hyphens: auto;`），允许长单词折行，以此使单词间的间距分布变得均匀、柔和。

## 3. 如果/那么 故障排除逻辑 (If/Then Troubleshooting Logic)
- **IF** 一个功能卡片内部包含标题、多行描述和按钮，采用全部居中显得结构松散且阅读困难，**THEN** 果断放弃居中。将卡片内的所有元素（包括文本和按钮）统统改为左对齐，你会发现整个界面瞬间变得有力和专业。
- **IF** 在财务仪表盘中，用户抱怨难以快速辨别谁的金额最大，**THEN** 检查数据表格的对齐方式。如果金额是左对齐或居中的，立即修改为右对齐（并推荐使用等宽数字字体 `font-variant-numeric: tabular-nums`），使数位严格对齐。
- **IF** 采用两端对齐的段落中出现了一条贯穿多行的大块空白带，**THEN** 检查是否遗漏了 `hyphens: auto`，或者直接将对齐方式改回左对齐以根除此问题。

## 4. 验证检查单 (Verification Checklists)
- [ ] 所有超过三行的正文段落是否全部采用左对齐（或区域一致对齐）？
- [ ] 表格和列表中的金钱、时间、数值等数据列是否正确使用了右对齐？
- [ ] 页面上居中的文本是否被严格限制在了简短的标题、引语或独立的 CTA 说明？
- [ ] 强制两端对齐的文本是否同时启用了连字符功能以缓解内部空白？
