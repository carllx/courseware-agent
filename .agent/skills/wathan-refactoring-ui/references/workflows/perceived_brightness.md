# 感知亮度与色相偏移工作流 (Perceived Brightness)

## Prerequisites & Context (前提与背景)
- **WHY (为什么关注感知亮度和色相偏移)**: 并不是所有颜色在 100% 亮度下的视觉亮度都是一样的。例如，纯黄色比纯蓝色在人眼看来要亮得多。这意味着简单地通过加黑或加白来调整明度会导致色彩显得脏污（泥泞的黄色）或褪色（毫无生气的粉蓝色）。通过色相偏移（Hue Rotation），我们可以欺骗人眼，维持颜色的活力。
- **WHEN (什么时候使用)**: 在微调整个色系（从 100 级到 900 级），或者将浅色界面切换为深色界面的过程中，必须应用该原理来修复色彩。

## Comprehensive Guide & Best Practices (综合指南与最佳实践)
1. **理解色轮上的亮度分布 (Perceived Brightness)**:
   - 在标准色轮中，黄色是感知最亮的，而深蓝色/紫色是感知最暗的。
2. **变亮时向明亮色相偏移 (Rotate Hue For Brightness)**:
   - 当你想要将一个颜色变亮（如从 500 级走到 100 级），除了提高亮度（Lightness）外，**将它的色相（Hue）向色轮上最亮的黄色方向微调**。
   - 示例：让红色变亮时，如果不改色相，它会变成粉红；如果稍微将色相偏向橙/黄，它会变成一个非常有活力的暖红色。让绿色变亮时偏向黄绿。
3. **变暗时向暗红色相偏移 (Rotating Hue For Contrast)**:
   - 当你要将颜色变暗（如从 500 级走到 900 级），**将它的色相向色轮上最暗的蓝色或紫色方向偏移**。
   - 示例：让红色变暗时，如果不改色相，会变成棕色（看起来很脏）；如果让色相稍偏紫红，它会变成高贵的深酒红。让黄色变暗时，如果不改会变成恶心的绿灰色，偏向橙/红则会变成漂亮的暗金棕色。
4. **反转对比度的陷阱 (Flipping The Contrast)**:
   - 当从浅色模式（白底深色文字）切换到深色模式（深黑底浅色文字）时，对比度关系反转。如果直接沿用原来的高纯度颜色，可能由于在暗背景下对比度不足而导致文字眩光。你需要调整感知亮度和饱和度以适应新的底色。

## If/Then Troubleshooting Logic (故障排除逻辑)
- **IF** 你合成的暗色调看起来像沾了泥土一样脏（Muddy）：
  - **THEN** 这是因为你只降低了明度（Lightness）却没有改变色相（Hue）。将其色相向蓝色/紫色区域微小旋转，让它变深的同时保持色彩气质。
- **IF** 你合成的浅色调看起来像被水洗过一样褪色（Washed out）：
  - **THEN** 这是因为你只增加了白色。提高饱和度，并将色相向色轮上的黄色（或青色）等高光泽区域偏移。
- **IF** 同样的文本颜色在亮色和暗色主题下难以平衡：
  - **THEN** 不要强求共用一个十六进制颜色值。根据对比度（Contrast Ratio）要求，深色模式需要更浅（更高感知亮度）、甚至稍微降低饱和度的颜色版本，以防止屏幕光晕效应。

## Verification Checklists (验证清单)
- [ ] 色板中的每一个阶梯，在发生亮度变化时是否都伴随着适当的色相偏移（Hue Rotation）？
- [ ] 极暗的颜色是否保留了清澈的底色而不是单纯的脏黑色？
- [ ] 极亮的颜色是否保留了生机而不是变成了粉笔灰般的粉彩色？
- [ ] 各关键元素的对比度是否满足了 W3C 标准（最低 4.5:1 的 Contrast Ratio）？
