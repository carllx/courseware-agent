# 强调色工作流 (Accent Colors)

## Prerequisites & Context (前提与背景)
- **WHY (为什么要使用强调色)**: 主色主要用于品牌和核心操作，但界面还需要传达其他类型的语义状态（如错误、警告、成功，或者新功能提示）。强调色（Accent Colors）用于填补主色无法覆盖的语义需求。
- **WHEN (什么时候使用)**: 需要向用户提供警报、成功通知、系统状态反馈，或为了区分特定的数据可视化图表、分类标签时。

## Comprehensive Guide & Best Practices (综合指南与最佳实践)
1. **语义映射的克制**:
   - 常规需求只需：红色（破坏性/错误）、绿色（成功/完成）、黄色/橙色（警告/关注）。
   - **绝对避免** 将这些强调色用作单纯的美学装饰，以防止用户产生混淆（例如不要用红色作为普通链接的颜色）。
2. **不要让强调色喧宾夺主**:
   - 强调色的饱和度通常较高，大面积使用会刺眼。
   - **微秒处理**: 可以通过使用极浅的强调色作为背景，并搭配同色系的深色作为文本，来柔和地传达信息，而不是使用一大块鲜艳的实心色块。
3. **结合图标与文本，而不仅仅依赖颜色**:
   - 根据无障碍设计（A11y）原则，不要仅通过颜色来传达关键信息。
   - 在使用红色警报时，必须配合相应的 Icon（如感叹号或警告图标）以及明确的文字提示，以便色弱用户也能接收到信息。

## If/Then Troubleshooting Logic (故障排除逻辑)
- **IF** 界面因为太多的通知/标签而显得像游乐场一样杂乱：
  - **THEN** 降低强调色的视觉权重。不要使用高饱和度的实心色块，改用带有主线框或淡背景色加深色文字的柔和标签样式。
- **IF** 强调色与主色发生冲突（例如主色也是红色，无法区分错误信息）：
  - **THEN** 调整报错状态的视觉设计。增加边框的粗细，使用纹理背景，或者引入中性色配合红色图标，而不是大面积使用红色背景。
- **IF** 黄色/橙色文字在白色背景上无法看清：
  - **THEN** 黄色本身的内在亮度极高，不适合做文字色。对于黄色强调色，应当改变策略：将暗棕色用作文字色，而黄色作为其背景色。

## Verification Checklists (验证清单)
- [ ] 所有的强调色是否都具有明确无歧义的系统级语义？
- [ ] 是否在传达信息时避免了“仅依赖颜色”（是否配有图标和文本）？
- [ ] 当多个强调状态同时出现时，是否调整了视觉重量以避免界面混乱？
- [ ] 每种强调色是否也拥有自己的浅色和深色变体，以满足柔和背景色或高对比文字的需求？
