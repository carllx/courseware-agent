# UI Depth and Accessibility Design Workflow

## Prerequisites & Context
在设计界面时，颜色和深度是传递信息层级的重要手段。然而，仅依赖颜色可能导致无障碍问题，而缺乏深度的界面可能导致用户迷失层级。本工作流旨在指导你如何在不牺牲无障碍性的前提下，利用系统化的阴影、光线模拟和颜色对比度来构建具有深度和可用性的界面系统。

## Comprehensive Guide & Best Practices

### 1. 避免仅依赖颜色传达信息 (Don't Rely on Color Alone)
- **增加辅助视觉提示**：如果使用颜色指示状态（如红/绿表示好/坏），必须添加额外的视觉指示器（如向上/向下的箭头图标），以确保红绿色盲用户能清晰辨别。
  ![](../../images/index-167_1.png)
  ![](../../images/index-167_2.png)
- **在图表中使用明暗对比度**：对于需要区分多条趋势线的图表，不要仅仅使用不同的颜色（色相），而应该利用**对比度（明暗度）**来区分。辨别明暗比辨别两种不同的色相更容易。
  ![](../../images/index-168_1.png)

### 2. 模拟真实光源创造深度 (Emulate a Light Source)
- **遵循“光从上方来”原则**：默认假设界面的光源来自正上方。
- **凸起元素 (Raised Elements)**：
  - 顶部边缘面向光源，应当稍微变亮（使用顶部边框或带轻微垂直偏移的内阴影，**手动选择亮色**而非简单的纯白半透明，以免使底层颜色显得灰暗）。
  - 底部会遮挡光线，因此需要在元素下方添加一个带有微小垂直偏移、模糊半径较小且偏暗的投影，这需要具有相对锐利的边缘。
  ![](../../images/index-176_1.png)
  ![](../../images/index-177_1.png)
- **凹陷/内嵌元素 (Inset Elements)**（如输入框、复选框等“井”状容器）：
  - 顶部内部会被外框遮挡，需添加微弱的正向垂直偏移深色内阴影。
  - 底部边缘（内唇）朝向光源应变亮，使用底部边框或负向垂直偏移的浅色内阴影。
  ![](../../images/index-178_1.png)
  ![](../../images/index-180_1.png)

### 3. 使用阴影构建海拔层级系统 (Use Shadows to Convey Elevation)
- **定义 Z 轴位置**：较小的阴影使元素贴近背景，较大的阴影让元素更靠近用户并吸引注意力。
  - 小阴影：适用于按钮。
  - 中阴影：适用于下拉菜单。
  - 大阴影：适用于模态对话框。
  ![](../../images/index-181_1.png)
  ![](../../images/index-182_1.png)
- **建立 5 级阴影系统**：不要随意捏造阴影值。定义一个最小阴影和一个最大阴影，然后线性填充中间三个层级，确保整个系统的高度一致性。
  ![](../../images/index-183_1.png)
- **结合交互状态**：当用户点击并拖拽列表项时，增加其阴影大小使其“浮起”；当点击按钮时，减小或移除阴影使其感觉被“按下”。
  ![](../../images/index-184_1.png)

### 4. 采用双重阴影技术 (Shadows Can Have Two Parts)
为了获得极佳的真实感，可以将单个阴影拆分为协同工作的两部分：
- **主阴影（直接光源阴影）**：垂直偏移较大，模糊半径大，颜色更柔和。
- **次阴影（环境光遮蔽阴影）**：垂直偏移极小，紧凑且颜色较暗，模拟物体正下方连环境光都无法到达的区域。
  ![](../../images/index-187_1.png)
  ![](../../images/index-188_1.png)
- **随海拔动态调整**：随着元素在 Z 轴上的升高，用于模拟环境光遮蔽的次阴影应当逐渐变淡乃至消失。
  ![](../../images/index-190_1.png)

### 5. 为扁平化设计赋予深度 (Even Flat Designs Can Have Depth)
- **利用颜色区分远近**：在同一色系下，较浅的颜色在视觉上感觉更近（凸起），较深的颜色感觉更远（凹陷）。
  ![](../../images/index-191_1.png)
  ![](../../images/index-192_1.png)
- **实体阴影 (Solid Shadows)**：使用带有垂直偏移但**零模糊半径 (0px blur)** 的短阴影，可以在保持纯粹扁平化美学的同时让卡片或按钮凸显出来。
  ![](../../images/index-194_1.png)

## If/Then Troubleshooting Logic

- **IF** 使用了半透明白色（如 `rgba(255,255,255,0.2)`）来做顶部高光导致组件颜色显得灰暗失去活力， **THEN** 停止使用半透明白色层叠，改为直接在调色板中手动挑选一个更浅、且保持高饱和度的同色相颜色作为高光边框。
- **IF** 界面看起来过于杂乱且不够干净（Over-designed）， **THEN** 检查是否滥用了光线模拟效果。减少不必要的阴影和内嵌效果，仅在需要明确强调层级的元素上使用，切忌追求完全逼真的照片级写实（Photo-realistic）。
- **IF** 折线图或数据卡片在灰度模式或对色盲用户不可辨认， **THEN** 检查趋势线或图例的亮度对比度。确保它们不仅有色相的区别，还能在去色后呈现出清晰的明暗差异（深色线与浅色线）；并引入图标、图案等非颜色指标。
- **IF** 高海拔元素（如模态框）下方有脏脏的黑色色带， **THEN** 检查是否在极高海拔（高 Z-axis）下保留了过深、过紧凑的“环境光次阴影”。此时应大幅减弱或移除次阴影，因为远离地面的物体下方会有更多的环境光进入。

## Verification Checklists

- [ ] **无障碍检查**：是否通过灰度/色盲模拟滤镜审查了设计？所有依赖颜色的状态（成功/失败/趋势）是否都配备了辅助的图标或文字标签？
- [ ] **光源一致性校验**：所有 UI 元素的高光（Highlight）和阴影（Shadow）方向是否统一？（默认为顶面受光高亮，底部产生阴影）。
- [ ] **系统化海拔配置**：界面中所有阴影是否严格来自于预设的层级系统（如 5 级体系），而非随意输入的像素和不透明度？
- [ ] **双重阴影质量审核**：浮动型关键组件（如 Dropdown, Modal）是否应用了双重阴影组合（柔和的大片投影 + 底部锐利的暗面投影）以提升精细感？
- [ ] **扁平深度验证**：对于扁平化风格的子页面，是否有效利用了明暗颜色映射或 0px 模糊的硬阴影来构建层次感？
