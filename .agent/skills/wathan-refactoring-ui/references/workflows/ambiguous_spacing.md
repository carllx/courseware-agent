# 工作流：消除模棱两可的间距 (Ambiguous Spacing)

## Prerequisites & Context (前提与背景)
- **WHY (为什么需要此工作流)**：在格式塔原理中，距离接近的元素会被视为一个整体。如果界面中元素之间的间距相等或差异微小，用户就无法在视觉上区分哪些元素属于同一组。这会导致界面阅读困难、逻辑混乱（即“Ambiguous Spacing”）。
- **WHEN (何时使用)**：构建包含列表、表单组、卡片列表、文章排版等具有明确信息层级和分组的界面结构时。

## Comprehensive Guide & Best Practices (全面指南与最佳实践)
1. **明确分组 (Space Around Groups)**
   - 确保相关元素之间的间距（内部间距）**明显小于**不相关元素或不同组之间的间距（外部间距）。
   - 例如，表单中：`Label` 和 `Input` 之间的间距应该非常小；而上一组 `Input` 与下一组 `Label` 之间的间距应该足够大，使得它们截然分开。
2. **利用间距建立层级**
   - 间距本身也是信息架构的一部分。在没有任何边框或分隔线的情况下，仅靠精准的间距区分，就能清晰地传达界面的内在逻辑。
3. **避免均匀分布**
   - 如果一个容器内有多个元素，不要简单地使用类似 `justify-content: space-between` 让它们均匀散布。应该思考它们之间的逻辑关系，将关系密切的元素靠拢，与其他元素拉开距离。

## If/Then Troubleshooting Logic (故障排除逻辑)
- **IF** 用户在填写表单或查看列表时，容易将下方的内容与上方的标题混淆：
  - **THEN** 这是典型的模棱两可间距。立即减小标题与其直接下方内容的 `margin-bottom`，并大幅增加当前组与下一个标题之间的 `margin-bottom`。
- **IF** 卡片或面板内的元素看起来像一盘散沙：
  - **THEN** 审查内部元素的间距。确保卡片的内边距（Padding）大于卡片内部各元素之间的间距。容器必须将其子元素“包裹”紧密。

## Verification Checklists (验证清单)
- [ ] 相关联元素的内部间距是否显著小于不同组之间的外部间距？
- [ ] 是否在不依赖任何视觉分割线的前提下，界面逻辑依然清晰可见？
- [ ] 组件的外部容器内边距（Padding）是否大于内部元素的间距，从而形成“包裹感”？
