# 工作流：视觉层级决定一切 (Hierarchy is Everything)

## Prerequisites & Context (前提与背景)
- **WHY (为什么需要此工作流)**：在界面设计中，用户往往不是在“阅读”内容，而是在“扫描”内容。良好的视觉层级能引导用户的视线，确保他们首先注意到最重要的信息。单纯依靠字号大小来区分层级是新手的常见错误（即“Size isn't everything”）。
- **WHEN (何时使用)**：当设计仪表盘、卡片、文章列表、表单等包含多级信息维度（主标题、副标题、元数据、辅助文本）的组件时。

## Comprehensive Guide & Best Practices (全面指南与最佳实践)
1. **多维度控制层级 (Beyond Size)**
   - **字重 (Font Weight)**：使用粗体 (Bold / Semi-bold) 来突出重要信息，使用常规体或细体来弱化次要信息。
   - **颜色与对比度 (Color & Contrast)**：重要的文本使用高对比度的深色（如深灰/接近黑色），次要的文本使用较浅的灰色。
   - **字号大小并非唯一标准**：很多时候，你可以保持两段文本字号相同，只通过改变其中一段的字重或颜色来建立主次关系。
2. **彩色背景上的灰色文本禁忌 (Don't use grey text on colored backgrounds)**
   - 灰色在白色背景上会降低对比度，但在有颜色的背景上使用灰色文本不仅对比度不够，还会显得脏乱、不协调。
   - **正确做法**：在彩色背景上需要弱化文本时，应该使用与背景色相同色相但更浅（或更深）的颜色，或者使用带有透明度的白色（如 `rgba(255,255,255,0.7)`），让背景色透过来，保持色调统一。
3. **去重点化 (De-emphasizing)**
   - 有时候为了突出重点，不需要放大主元素，而是缩小或弱化周围的辅助元素。这种“反向操作”往往能让界面看起来更精致。

## If/Then Troubleshooting Logic (故障排除逻辑)
- **IF** 标题和正文难以区分：
  - **THEN** 不要只一味放大标题字号。尝试加粗标题，或者将正文颜色改为次级灰色。
- **IF** 在深蓝色背景上次要信息太显眼：
  - **THEN** 不要使用灰色（`#999`），改为使用带有透明度的白色，或者选用极浅的蓝色（如浅紫蓝）。
- **IF** 界面元素过多导致重点不突出：
  - **THEN** 运用“去重点化”策略，将次要说明文字（如日期、标签、提示）的对比度降低。

## Verification Checklists (验证清单)
- [ ] 界面中的主要操作和核心信息是否在第一眼就被注意到？
- [ ] 是否在不改变字号的情况下，运用了字重和颜色来建立层级？
- [ ] 所有的辅助/次要文本是否使用了较低对比度的颜色进行弱化？
- [ ] 在彩色背景上，是否清除了所有的纯灰色文本，替换为带透明度的白色或同色系变体？
