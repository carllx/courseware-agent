# 启发式工作流：行高与行宽的比例法则 (Line Height Proportional to Line Length)

## 1. 前置条件与上下文 (Prerequisites & Context)
- **应用场景 (WHEN)**: 配置任何多行文本段落的排版系统时，尤其是当你需要处理不同容器宽度（如全宽文章容器、窄侧栏卡片）下的文本展示。
- **理论依据 (WHY)**: 行高（Line Height/Leading）的目的不仅仅是为了留出空间，而是为了引导读者的视线。当行宽（Line Length）增加时，读者眼睛从一行末尾跳跃回下一行起点的距离变长。如果行间距太小，视线在跳跃时极易“串行”或迷失；反之，行宽变窄时，跳跃距离极短，如果行间距过大，文本块就会显得支离破碎，失去连贯性。因此，行高必须与行宽成正比。

## 2. 综合指南与最佳实践 (Comprehensive Guide & Best Practices)
- **正比例调整法则**
  - **宽段落需要大行高**：对于行宽接近 60-75 个字符的文章正文，行高应设定在 `1.6` 到 `1.8` 之间。这给予眼睛足够的上下空间来区分不同的行，并在长距离扫视后准确降落。
  - **窄段落需要小行高**：对于侧边栏、多列网格中的文本或移动端上的短文本，行宽通常只有 30-40 个字符。此时，行高应压缩到 `1.4` 到 `1.5` 左右，以保持文本块的紧凑感和视觉内聚力。
- **放弃全局统一的行高**
  - 避免在全局 CSS 中设置一个 `body { line-height: 1.6; }` 然后期望它在所有场景都适用。
  - 应该基于组件的物理宽度，引入局部作用域的行高变量。
- **整体性视觉感知**
  - 排版的最高境界是将一段文字视为一个灰度的“块（Block）”。动态调整行高能确保不论容器如何变化，这个“块”的灰度密度看起来始终一致。

## 3. 如果/那么 故障排除逻辑 (If/Then Troubleshooting Logic)
- **IF** 文本看起来像是一条条独立的线，而不是一个有机的段落，**THEN** 说明行高相对于行宽而言太大了。减小行高，直到段落恢复为一个完整的视觉块。
- **IF** 用户反馈阅读长文章时容易跳行、疲惫，**THEN** 你的行高可能设置得太小了（尤其是当行宽超过 60 字符时）。立即提高 `line-height`，为长距离视觉移动提供“跑道”。
- **IF** 将桌面端设计适配到移动端屏幕（宽度大幅缩小），**THEN** 必须通过媒体查询同时缩小 `line-height`，否则在小屏幕上段落会被过度拉长，浪费宝贵的纵向空间。

## 4. 验证检查单 (Verification Checklists)
- [ ] 宽屏下的正文文本块（通常限制在 max-width），是否应用了偏大（1.6-1.8）的行高？
- [ ] 窄屏（如手机）或侧边栏、网格卡片内的文本，行高是否相应缩减（1.4-1.5）？
- [ ] 眯起眼睛看段落，文字块是否呈现为均匀的灰度块，而不是一条条被空白强行割裂的斑马线？
- [ ] 你的组件库是否提供了支持按容器宽度动态覆盖行高的工具类（Utility classes）？
