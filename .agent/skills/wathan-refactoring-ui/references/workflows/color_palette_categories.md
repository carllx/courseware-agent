# 调色板分类工作流 (Color Palette Categories)

## Prerequisites & Context (前提与背景)
- **WHY (为什么需要分类)**: 一个复杂的应用不能只有几种颜色。为了保持UI的统一性并满足各种场景的需求，必须将色彩系统划分为不同的类别。这有助于开发者和设计师在构建界面时有章可循。
- **WHEN (什么时候使用)**: 在项目初期构建设计系统，或者在重构现有杂乱无章的调色板时。

## Comprehensive Guide & Best Practices (综合指南与最佳实践)
1. **基础分类架构**: 
   - 调色板应严格分为三大主要类别：**主色（Primary Colors）**、**中性色/灰色（Greys）** 和 **强调色（Accent Colors）**。
2. **中性色 (Greys) 的核心地位**:
   - 灰色是UI中用得最多的颜色（文字、背景、边框、分隔线）。
   - 需要定义一个包含 8-10 个层级的灰色色阶，涵盖从近乎纯白到近乎纯黑的跨度。
3. **主色 (Primary Colors) 的约束**:
   - 你的品牌色。大部分交互元素（如按钮、激活的链接、选中状态）都使用主色。
   - 同样需要为核心主色建立 8-10 个层级的色阶，以适应背景、前景色、悬停状态等需求。
4. **强调色 (Accent Colors) 的功能性**:
   - 用于传达特定信息的语义色彩（如红色代表破坏性/错误，绿色代表成功，黄色代表警告）。
   - 不要为了增加色彩而随意添加。每种强调色都必须有明确的用途。

## If/Then Troubleshooting Logic (故障排除逻辑)
- **IF** 界面看起来像“彩虹”，缺乏专业感：
  - **THEN** 可能是滥用了主色或强调色。约束主色的使用比例（如60-30-10原则），让中性色占据界面的主导地位（约占60-70%）。
- **IF** 开发者在构建UI时经常使用自定义的十六进制颜色：
  - **THEN** 调色板分类不够完善。检查哪类颜色缺失（通常是背景色的极浅色阶或文本的极深色阶），并将其补充到色板类别中。
- **IF** 新功能需要新的颜色，但调色板中没有：
  - **THEN** 只有当新功能具有全新语义时才引入新的强调色；如果是常规状态，优先复用中性色或主色的不同色阶。

## Verification Checklists (验证清单)
- [ ] 是否明确划分了主色、中性色和强调色的类别？
- [ ] 灰色（中性色）是否包含了足够的层级来处理文字、背景和边框？
- [ ] 强调色的定义是否具有明确的语义（成功、警告、危险）并且没有冗余？
- [ ] 系统中的所有UI元素是否都能在现有的三大分类中找到对应的颜色？
