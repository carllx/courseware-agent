# 亮度控制工作流 (Lightness)

## Prerequisites & Context (前提与背景)
- **WHY (为什么需要关注亮度)**: 在UI设计中，亮度（Lightness）是建立视觉层次和区分元素的主力。仅靠色相（Hue）无法创造足够的对比度。理解和控制亮度能够让界面元素从背景中合理地浮现或沉降。
- **WHEN (什么时候使用)**: 在构建色彩系统、区分前景色与背景色、以及为文本、边框、阴影建立层次时，必须优先考虑亮度的差异。

## Comprehensive Guide & Best Practices (综合指南与最佳实践)
1. **亮度优于色相**: 
   - 当需要区分两个元素（如主要文本与次要文本，或者按钮与背景）时，首先调整亮度而不是色相。
   - 高亮度的元素显得更轻盈或退居背景（如浅灰背景），而低亮度（深色）元素具有更高的视觉重量，会吸引用户的注意力。
2. **建立明确的亮度台阶**:
   - 不要在相似的亮度值之间犹豫。如果需要区分，亮度的跨度应该足够大，使得差异一目了然。
   - 避免在白底上使用过浅的灰色文字（亮度过高导致对比度不足），同时避免在深色背景上使用暗淡的颜色。
3. **利用亮度表达状态**:
   - 禁用状态的按钮通常具有更高的亮度（更接近白色或更浅的灰色），以降低其视觉显著性。
   - 悬停（Hover）或激活（Active）状态通过微调亮度（变暗或变亮）来提供反馈。

## If/Then Troubleshooting Logic (故障排除逻辑)
- **IF** 界面元素看起来融为一体，缺乏层次感：
  - **THEN** 检查并拉大关键元素之间的亮度差。确保背景、卡片和边框的亮度有明显的层级区分。
- **IF** 文本阅读困难，尽管颜色不同：
  - **THEN** 这是因为亮度的对比度不足。使用对比度检查工具，降低文本的亮度或提高背景的亮度，以达到至少 4.5:1 的对比度。
- **IF** 亮色主题切换到暗色主题后视觉失效：
  - **THEN** 亮度关系需要反转。原本用于区分层次的暗度（阴影），在暗色主题中应变为亮度的增加（高光或更浅的背景色）。

## Verification Checklists (验证清单)
- [ ] 所有主要文本与背景之间的亮度对比度是否满足可访问性要求？
- [ ] 界面的层级是否能够仅通过黑白模式（灰度图）的亮度差异来清晰辨认？
- [ ] 交互元素（如按钮、输入框）的各种状态是否通过亮度的变化给予了明确反馈？
- [ ] 是否避免了微小、不可察觉的亮度调整？
