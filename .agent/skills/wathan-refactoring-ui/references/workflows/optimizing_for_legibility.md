# 工作流：优化可读性 (Optimizing for Legibility)

## Prerequisites & Context (前提与背景)
- **WHY (为什么需要此工作流)**：界面设计不仅关乎美观，最基础的要求是信息的清晰传达。如果文本难以阅读，任何惊艳的设计都将毫无意义。必须通过一系列排版微调来扫清用户的认知障碍。
- **WHEN (何时使用)**：在任何包含文字的界面设计中，特别是在长文本、小字号注释或关键交互文本的场景。

## Comprehensive Guide & Best Practices (全面指南与最佳实践)
1. **增大字偶距以优化全大写文本 (Letter-spacing for Uppercase)**
   - 当使用全大写字母（ALL CAPS）时，字母原本的设计节奏会被打破，容易粘连。必须适度增加 `letter-spacing`（例如 `0.05em`），才能使其更易于阅读和显得更加优雅。
2. **深色背景上的抗锯齿调整**
   - 在深色背景上渲染浅色文本时，字体通常在视觉上显得更粗。在 macOS/iOS 渲染引擎下，可以启用 `-webkit-font-smoothing: antialiased;` 使得文字看起来更纤细精致。
3. **避免过长的行长 (Line Length)**
   - 人的眼睛在追踪过长的文本行时容易产生疲劳并丢失换行点。理想的单行文本长度应控制在 45 到 75 个字符之间。使用 `max-width` 控制文本容器的宽度。
4. **调整小字号的对比度**
   - 对于极小的字号，必须拥有更高的颜色对比度，避免使用低可见度的淡灰色。

## If/Then Troubleshooting Logic (故障排除逻辑)
- **IF** 用户反馈长篇文章难以阅读或容易串行：
  - **THEN** 检查行高（应为 1.5 到 1.8）与行长。通过给包含段落的容器设置 `max-width: 65ch;` 来限制单行字符数。
- **IF** 导航栏上的全大写标签显得拥挤且具有侵略性：
  - **THEN** 为这些大写标签增加字间距（letter spacing），同时考虑适度减小一点字号，让其视觉比重与普通大小写混合的文本平衡。

## Verification Checklists (验证清单)
- [ ] 所有全大写的文本是否都增加了额外的 `letter-spacing`？
- [ ] 正文段落的单行字符数是否限制在 45 - 75 个字符（约 `60ch`）之间？
- [ ] 在深底色界面上，浅色文字的渲染是否做了相应的平滑与视觉减重处理？
