# 启发式工作流：驾驭色相控制 (Hue)

## 1. 前置条件与上下文 (Prerequisites & Context)
- **应用场景 (WHEN)**: 定义品牌基础色系，寻找搭配强调色，以及构建系统的 UI 语义颜色（警告、成功、危险、信息）时。
- **理论依据 (WHY)**: 色相（Hue）决定了颜色在色轮上的基本位置（它是红、绿、蓝还是黄）。控制色相不仅仅是挑选好看的颜色，更是通过物理角度的相对关系建立视觉协调。过多或混乱的色相会破坏界面的专业性，让系统显得像一个马戏团。

## 2. 综合指南与最佳实践 (Comprehensive Guide & Best Practices)
- **基于色轮的相对主义**
  - 在 HSL 系统中，Hue 是一个 0-360 度的圆。利用这个物理特性，可以通过数学关系寻找完美搭配。
  - **互补色**：加上或减去 180 度。如果主色调是 `Hue 210`（蓝色），一个强有力的对比/强调色就是 `210 + 180 = 390`（即 30 度，橙色）。
  - **类似色**：加减 30-40 度。如果你需要为图表设计一套渐进的冷色调，从蓝（210）衍生出青色（170）和紫色（250）。
- **极简的色相组合**
  - **克制原则**：一个高端且专业的 UI 通常只依赖 1 个核心主色调（Primary Hue）和极少数（甚至不需要）的辅助色相。界面 80% 的区域应该由中性色（灰度系列）组成。
  - 不要为每一个新组件或功能分配一个全新的色相，这会迅速耗尽视觉层级。
- **赋予中性色以温度**
  - 纯灰（色相随意，饱和度0%）在真实界面中往往显得呆板、死气沉沉。
  - 将中性色锁定到与主色相一致或相邻的 Hue，并赋予极低的饱和度（如 2%-5%），你会得到一套极具质感的“冷灰”或“暖灰”，这能让整个界面从平庸走向高级。

## 3. 如果/那么 故障排除逻辑 (If/Then Troubleshooting Logic)
- **IF** 界面色彩显得极为杂乱，“儿童玩具”感很强，**THEN** 这是因为引入了过多无关联的色相。执行色相收敛：选取一个主色，剔除不必要的颜色，并将大部分界面元素还原为中立的灰阶色阶。
- **IF** 你的“成功（绿）”或“警告（黄）”等语义颜色与你的品牌主色（比如一种特定的青蓝色）放在一起时显得极不协调，**THEN** 检查色相差。尝试微调这些语义颜色的 Hue 值，使其稍稍向主色的 Hue 偏移几度（增加类似性），或者拉高/降低亮度，使它们在调性上归属于同一个大家庭。
- **IF** 背景和前景元素之间产生视觉振动感（看起来刺眼或边缘模糊），**THEN** 这是因为选用了色相强烈对立（接近180度）且亮度相近的颜色组合。此时应改变其中一个颜色的亮度，或采用类似的色相。

## 4. 验证检查单 (Verification Checklists)
- [ ] 界面的基础调色板是否控制在 1-2 种核心色相内？
- [ ] 所有的灰阶（中性色）是否被注入了微小的基础色相以统一界面温度？
- [ ] 辅助色、强调色的选择是否遵循了基于色相环角度的计算（如互补色、类似色），而不是盲目吸色？
- [ ] 检查代码中是否存在孤立的、只使用过一次的异常色相，并考虑用核心色相树替换它们？
