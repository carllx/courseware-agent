# 界面深度与光源模拟工作流 (Depth & Light Source Emulation Workflow)

## 一、 先决条件与上下文 (Prerequisites & Context)

**为什么需要光源模拟？(The WHY)**
在用户界面设计中，为了让某些元素看起来像是从页面上凸起（Raised）或内凹（Inset），传统的做法往往依赖复杂的渐变和多重阴影，这容易导致界面显得过时或冗杂。然而，创造真实且自然的深度感（Depth），其核心法则其实只有一个：**模拟真实世界中光源的照射方式。**

由于人类大脑在物理世界中已经习惯了“光总是从上方照射下来”这一自然规律，我们在解析平面图像中的凸起或凹陷时，完全依赖于高光和阴影的分布：
- **凸起的物体（如门板的浮雕）**：顶端边缘朝向天空，因此捕捉到更多光线，显得更亮；底端边缘背离天空，接收更少光线，显得更暗。
- **内凹的物体（如橱柜的凹槽）**：上方的边缘会遮挡光线，在内凹处的顶部投下阴影；而内凹处的底部边缘由于朝向天空，会接收到更多光线而显得更亮。

**何时使用？(The WHEN)**
- 当你需要设计按钮、卡片、浮动操作按钮 (FAB) 等**需要表现出可点击或悬浮在页面上方的元素（Raised elements）**时。
- 当你需要设计文本输入框、复选框、进度槽或背景容器等**需要表现出凹陷于页面内部的元素（Inset elements）**时。
- 当你需要打破界面的扁平感，通过微妙的微交互或视觉层级引导用户的注意力时。

## 二、 综合指南与最佳实践 (Comprehensive Guide & Best Practices)

要让元素呈现凸起或内凹的效果，首先要明确该元素的“横截面轮廓”（Profile），然后模拟光源与该形状的交互。

### 1. 凸起元素设计指南 (Raised Elements)
*适用场景：按钮、卡片、浮动操作按钮 (FAB) 等*

**步骤与启发式原则：**
- **视角假定**：由于用户通常是**微微向下**俯视屏幕的，最自然的视觉表现是暴露出一点点顶部边缘，并隐藏底部边缘的厚度。
- **处理顶部边缘（高光）**：
  - 既然顶部边缘面向上方，它应该比元素主体的正面颜色略亮。
  - **实现方法**：使用顶部边框（Top Border）或带有轻微垂直偏移量（Vertical Offset）的内阴影（Inset Box Shadow）来模拟这道高光。
  - **关键启发式**：**手动选择较亮的颜色！** 不要简单地覆盖一个半透明的白色（如 `rgba(255,255,255,0.2)`）。直接叠加白色可能会吸走（Suck the saturation）底层颜色的饱和度，导致颜色发灰、变脏。手动在 HSL 色板中提高明度并保持或微调饱和度，能获得最纯净的效果。
- **处理底部阴影（遮挡光）**：
  - 凸起的元素会遮挡光线，导致其下方区域产生阴影。
  - **实现方法**：添加一个带有轻微垂直偏移量的、颜色较暗的外部投影（Box Shadow），确保阴影只出现在元素的下方。
  - **关键启发式**：**控制模糊半径（Blur Radius）！** 不要过度模糊。几个像素的模糊半径就足够了。这类阴影的边缘应该相对锐利，就像现实世界中墙上插座或窗框在墙面投下的阴影一样。

### 2. 内凹元素设计指南 (Inset Elements)
*适用场景：输入框（Text Inputs）、复选框（Checkboxes）、凹槽容器（Wells）等*

**步骤与启发式原则：**
- **视角假定**：同样是在微微向下的俯视视角中，内凹元素的内部，只有**底部边缘（Bottom Lip）**是可见的。
- **处理底部边缘（受光面）**：
  - 由于凹槽的底部内侧边缘是朝向天空的，它应该接收到光线。
  - **实现方法**：使用底部边框（Bottom Border）或带有**负**垂直偏移量（Negative Vertical Offset）的内阴影（Inset Box Shadow），赋予该边缘一个稍亮的颜色。
- **处理顶部阴影（遮挡光）**：
  - 凹槽上方的区域会阻挡光线照射到凹槽的最顶部，因此内部的顶部会产生阴影。
  - **实现方法**：添加一个面积较小、颜色较暗且带有**正**垂直偏移量（Positive Vertical Offset）的内阴影（Inset Box Shadow）。
  - **关键启发式**：确保这个正向偏移的内阴影不要穿透到底部（即不要让底部也出现暗色阴影），它应该只局限在内凹区域的上方。

### 3. 克制与视觉清晰度 (Don't Get Carried Away)
- **避免过度拟物化**：一旦掌握了模拟光线的技巧，设计师很容易陷入长达数小时的微调，试图使其尽可能接近真实世界的照片级效果。
- **保持界面整洁**：在实际应用中，过度模拟会导致界面显得嘈杂（Busy）且意图不清晰。从现实世界中借用一些视觉线索是增加深度的好方法，但完全没必要追求照片级真实感（Photo-realistic）。**点到为止，克制即是优雅。**

## 三、 If/Then 故障排除逻辑 (If/Then Troubleshooting Logic)

| 场景条件 (If) | 潜在问题 / 理论约束 | 解决对策 (Then) |
| :--- | :--- | :--- |
| **If** 凸起按钮的顶部高光显得发灰、不通透 | **Then** 可能是使用了半透明白色（Alpha White）叠加，导致底层色彩饱和度流失。 | 改为**手动挑选**同色系中明度较高（High Lightness）、饱和度适中（Adequate Saturation）的不透明颜色。 |
| **If** 凸起元素的底部阴影看起来像发光的污渍或显得不够真实 | **Then** 可能是阴影的模糊半径（Blur Radius）过大，或者没有设置垂直偏移量，导致阴影四周均等发散。 | 缩小模糊半径（如从 10px 降到 2-4px），增加正向垂直偏移量（Y-offset），使阴影集中在下方且边缘锐利。 |
| **If** 内凹输入框看起来像一个扁平的带框矩形，没有深度感 | **Then** 缺乏上方遮挡带来的阴影和下方边缘受光带来的高光。 | 在上方添加带有正垂直偏移量的暗色内阴影，同时在下方添加底边框或负偏移量内阴影作为较亮的高光。 |
| **If** 整个界面因为添加了光源模拟而显得杂乱无章 | **Then** 模拟深度过多，或者元素之间的投影相互冲突，导致认知负荷过高。 | 退回一步，降低阴影的透明度，去除不必要的次要深度的细节。记住：不需要追求照片级别的真实，只需提供轻微的视觉线索。 |

## 四、 验证清单 (Verification Checklists)

**总体光照一致性：**
- [ ] 界面中所有具有深度效果的元素，是否都假定光线是从**正上方**照射下来的？
- [ ] 是否避免了光源方向在不同组件间相互冲突的情况？

**凸起元素 (Raised) 检查：**
- [ ] 顶部高光是否使用了手动挑选的明亮纯色，而不是简单的透明白叠加？
- [ ] 底部阴影是否具有向下的垂直偏移？
- [ ] 底部阴影的模糊半径是否保持克制，边缘是否相对锐利？
- [ ] 是否根据“微俯视”的视角，隐藏了底部边缘的高光/厚度？

**内凹元素 (Inset) 检查：**
- [ ] 内部上方是否具有小范围、正向垂直偏移的暗色内阴影？
- [ ] 内部下方是否具有明亮的高光（通过底边框或负偏移内阴影实现）？
- [ ] 顶部的暗色内阴影是否控制得当，没有穿透或泄漏到输入框的底部？

**全局视觉清晰度：**
- [ ] 添加这些深度细节后，界面是否依然保持清晰、干净，没有陷入过度拟物化（Skeuomorphism）的泥潭？
