# 界面平衡与布局系统工作流 (Balance, Spacing & Layout)

## 1. Prerequisites & Context (先决条件与上下文)
本工作流涵盖了UI设计中关于视觉比重平衡、按钮语义层次、留白、间距系统以及网格与屏幕空间利用的核心原则。当你在进行组件级别的细节打磨或页面级别的排版布局时，应当应用本指南。

**何时使用：**
- 当图标和文字在视觉上显得不协调、比重失衡时。
- 页面上有多个操作按钮，导致用户难以区分主次时。
- 界面看起来拥挤或杂乱，需要进行留白优化时。
- 难以决定元素大小和间距（如在 120px 和 125px 之间纠结）时。
- 在响应式设计中，纠结于是否应让所有元素都填满屏幕，或完全依赖网格系统时。

## 2. Comprehensive Guide & Best Practices (综合指南与最佳实践)

### 2.1 权衡视觉比重与对比度 (Balance weight and contrast)
视觉层次不仅与大小有关，还与元素占据的“表面积”相关。
- **图标与文本的平衡**：图标（尤其是实心图标）通常很“重”，覆盖大面积区域。与文本并排时，图标会喧宾夺主。
  - **行动策略**：由于无法直接减轻图标的“重量”，必须通过**降低对比度**来进行补偿，例如为图标指定一个更柔和、更浅的颜色。
  - 示例：![](../../images/index-57_1.png) -> 优化后：![](../../images/index-58_1.png)
- **通过加重补偿低对比度**：当使用柔和色彩的细线（如 1px 边框）显得过于模糊，而加深颜色又显得刺眼时，应保留柔和的颜色，但增加线条的宽度（即加重）。
  - 示例：![](../../images/index-59_1.png) -> 优化后：![](../../images/index-60_1.png)

### 2.2 按钮语义次于层次 (Semantics are secondary)
不要仅仅根据“动作的危险性或类型”来盲目设计按钮，**层次结构应始终优先**。
- **梳理动作层次**：每个页面通常只有一个真正的主要动作 (Primary)，少数次要动作 (Secondary)，以及少用的第三级动作 (Tertiary)。
- **样式指导**：
  - **主要动作**：应该非常醒目。使用高对比度的实心背景色。
  - **次要动作**：清晰但不突出。推荐使用轮廓线 (Outline) 或较低对比度的背景色。
  - **第三级动作**：可发现但不显眼。将其样式化为普通文本链接。
- **破坏性操作处理**：并非所有的“删除”或破坏性操作都必须是大红色的粗体按钮。如果它不是页面的主要动作，请将其降级为次要或第三级按钮样式。在点击后的“确认步骤”中，再将其作为主要动作使用大红色粗体。
  - 示例对比：![](../../images/index-61_1.png) vs ![](../../images/index-62_1.png)

### 2.3 留白与间距体系 (Layout and Spacing System)
- **从“过度留白”开始**：清理界面的最简单方法是给元素喘息的空间。不要一点一点地添加间距，而应尝试一开始给出**极其夸张的过多留白**，然后逐渐缩减，直到感觉合适。![](../../images/index-68_1.png)
- **高密度 UI 的特例**：在仪表盘或数据密集型场景中，为了在一个屏幕内展示尽可能多的信息，适当降低留白、提高紧凑度是合理的，但必须是“刻意的决定”。
- **拒绝线性比例，建立间距系统**：不要在 120px 和 125px 之间纠结。定义一套严格的间距和尺寸枚举值。
  - **原则**：在较小的尺度上（如图标大小、按钮内边距），小幅像素调整（如 12px 到 16px）差异显著（33%）。而在大尺度上（如卡片宽度），几像素的差异难以察觉。
  - **规则设定**：确保尺寸系统中的任何相邻两个值之间的差值不小于 **25%**。
  - **基准值**：以 16px 为基准值向上和向下推导比例因子（例如：4, 8, 12, 16, 24, 32, 48, 64, 96, 128）。![](../../images/index-74_1.png)

### 2.4 屏幕利用与破除网格迷信 (Screen Usage & Grids)
- **不必填满整个屏幕**：如果你的内容只需要 600px 宽度，就只用 600px。不必要的拉伸只会让界面难以阅读。![](../../images/index-77_1.png)
- **缩小画布设计**：在超大显示器上设计容易失真。建议从 ~400px 的移动端画布开始，满意后再适配大屏幕，微调那些因屏幕小而妥协的部分。
- **思考列结构 (Thinking in columns)**：如果一个表单太窄，在一个宽屏幕里显得不平衡，不要拉宽输入框。尝试将说明文字等移出，形成双列布局。![](../../images/index-81_1.png)
- **网格被高估了 (Grids are overrated)**：不要将所有的布局决策都外包给 12 列网格系统。
  - **并非所有元素都应该是流式的 (fluid)**：如果是侧边栏与主内容区，如果按照 25% / 75% 的比例，当屏幕缩小到一定程度时侧边栏文本会被截断，屏幕太大时又浪费空间。更好的做法是**给侧边栏一个固定宽度 (Fixed Width)**，让主内容区占据剩余空间 (Flex)。![](../../images/index-87_1.png)
  - **不到万不得已不要缩小元素**：不要因为网格的限制让组件在其理想宽度（如 500px）之下收缩，应设置 `max-width`，只在屏幕实际比该宽度还小的时候才迫使它缩小。![](../../images/index-89_1.png)

## 3. If/Then Troubleshooting Logic (If/Then 故障排除逻辑)

- **IF** 一个带有实心图标的按钮看起来过于厚重且抢占了过多的注意力，**THEN** 降低该实心图标的对比度（如使用浅灰色或降低透明度），以平衡其过大的视觉表面积。
- **IF** 页面中存在多个破坏性按钮（如多个列表项的“删除”操作）导致页面充满红色警示，**THEN** 将这些删除按钮调整为次要或第三级样式（如灰色轮廓或普通链接），并在弹出的确认对话框中才使用主要的大红色按钮。
- **IF** 在响应式调整时，发现某个宽卡片在特定断点下变得过宽或过窄，**THEN** 检查是否被流式网格（百分比宽度）所绑架。尝试为其分配一个最优的 `max-width` 并在屏幕空间足够时保持不变，避免过度拉伸或压缩。
- **IF** 文本和图标的对齐或间距总是觉得差了一点，难以决策，**THEN** 严格约束自己只能使用预定义的间距系统（如 4px, 8px, 16px, 24px），抛弃诸如 14px 或 19px 这种不规则的魔法数字。
- **IF** 需要更深层次理解如何在团队中推广这种受限的间距系统，**THEN** 运行动态查询脚本获取理论知识：
  `bash scripts/query_theory.sh "How to convince developers and designers to adopt a strict non-linear spacing scale?"`

## 4. Verification Checklists (验证清单)

- [ ] **视觉比重检查**：页面中的重元素（如粗体字、实心图标）是否使用了对比度弱化来达到视觉平衡？细边框是否通过增加线条宽度来弥补低对比度的不足？
- [ ] **按钮层次检查**：页面是否明确只有一个（或极少数个）Primary 按钮？Secondary 和 Tertiary 按钮是否正确降级以防喧宾夺主？
- [ ] **破坏性操作检查**：非最高优先级的破坏性操作是否已被降权？
- [ ] **留白检查**：是否通过最初给定“过量留白”然后再缩减的方法，确保了UI组件之间有足够的呼吸空间？
- [ ] **间距系统验证**：所有的 margin 和 padding 是否都严格选自建立好的、差异度至少 >25% 的间距比例尺？
- [ ] **屏幕空间验证**：内容是否在宽屏下保持了合理的固定宽度，而非盲目地拉伸填满屏幕？
- [ ] **网格滥用检查**：侧边栏或特定卡片是否错误地应用了流式网格，导致其在特定尺寸下产生阅读困难？是否已将其替换为固定宽度 + `max-width` 策略？
