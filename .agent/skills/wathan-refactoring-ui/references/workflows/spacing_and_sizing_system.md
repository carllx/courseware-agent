# 工作流：间距与尺寸系统 (Spacing and Sizing System)

## Prerequisites & Context (前提与背景)
- **WHY (为什么需要此工作流)**：界面设计中，随意选择间距（如 17px, 23px）会导致布局缺乏节奏感和一致性。建立一个基于约束的系统（“Limit your choices”）可以消除设计中的猜测，提高开发效率，并确保界面在视觉上的和谐。
- **WHEN (何时使用)**：在项目初期设定设计令牌 (Design Tokens)，或在重构无序的前端代码库（如清理散乱的 CSS margin/padding）时。

## Comprehensive Guide & Best Practices (全面指南与最佳实践)
1. **拥抱基于约束的系统 (Limit your choices)**
   - 永远不要在设计或代码中使用随机像素值。提前定义好一组受限的间距/尺寸刻度。
   - 这不仅适用于间距（Margin/Padding），还适用于元素的宽度、高度和图标的尺寸。
2. **构建线性与非线性刻度**
   - **基础基准**：通常以 `4px` 或 `8px` 为基准单位。
   - **小尺寸阶段（线性）**：在较小的值域中，细微的差异是可见的。例如：`4px, 8px, 12px, 16px, 20px, 24px`。
   - **大尺寸阶段（非线性/指数级）**：随着尺寸增大，需要更大的跳跃才能产生显著的视觉差异。例如：`32px, 48px, 64px, 96px, 128px`。
3. **消除任意值 (No Magic Numbers)**
   - 所有的内边距、外边距、容器宽度等，都必须从上述设定的刻度池中选取。
   - 当遇到感觉“介于两者之间”的情况时，强制自己选择最接近的系统值，这往往会让整体界面更加统一。

## If/Then Troubleshooting Logic (故障排除逻辑)
- **IF** 元素之间感觉稍微有点拥挤，但使用下一个间距档位又显得太散：
  - **THEN** 检查是否是由于对比度或边框导致的问题。坚持使用系统中的值，尝试通过微调其他视觉权重（如颜色）来平衡，而不是创造一个非系统的值。
- **IF** 开发人员频繁使用如 `margin-top: 19px` 的硬编码：
  - **THEN** 引入类似 Tailwind CSS 的实用类库，或者在代码中强制引入 spacing tokens，用类似 `spacing.md` 或 `mb-5` 替代具体像素。

## Verification Checklists (验证清单)
- [ ] 是否所有的间距（padding, margin）都遵循了预定义的刻度（如 4px/8px 网格）？
- [ ] 尺寸系统在小范围间距是否足够密集，在大范围间距是否跳跃足够大？
- [ ] 代码中是否已经清除了所有不在刻度表中的“魔法数字 (Magic Numbers)”？
