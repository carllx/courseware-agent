# 启发式工作流：行宽控制 (Line Length)

## 1. 前置条件与上下文 (Prerequisites & Context)
- **应用场景 (WHEN)**: 在设计文章阅读页、博客、文档、或者任何包含连续多行文本的容器（如卡片说明、模态框描述）时。
- **理论依据 (WHY)**: 行宽（Line Length）直接决定了用户的阅读体验。如果一行文本过长，读者的眼睛在从当前行末尾扫视回下一行开头时，容易发生“串行”现象，导致阅读疲劳和迷失；如果一行文本过短，眼睛需要频繁地折返换行，打断阅读节奏，造成急促和紧张感。合适的行宽能让眼球平滑、富有节奏地扫描。

## 2. 综合指南与最佳实践 (Comprehensive Guide & Best Practices)
- **核心法则：45-75 字符法则**
  - 单行文本的最佳长度应该控制在 **45 到 75 个字符**（包含空格和标点符号）之间。对于中文排版，大约对应 30 到 45 个中文字符。
  - 这个范围是人类视觉跟踪在不需要过度转动头部或剧烈眼动的情况下，能够轻松处理的理想宽度。
- **使用 `ch` 单位进行约束**
  - 在 CSS 中，利用 `ch` (character) 单位是控制行宽的完美方案。`1ch` 等于当前字体下数字 "0" 的宽度。
  - 使用 `max-width: 65ch;` 给文本块设定一个合理的上限，而不是使用死板的像素值（px）或百分比（%）。这样无论字号如何改变，行宽的物理视觉都能保持在最佳字数范围内。
- **不要被屏幕宽度绑架**
  - 宽屏显示器不意味着文本必须填满整个屏幕。大片空白（White Space）并不是资源浪费，它是帮助读者集中注意力的缓冲区。
  - 遇到超宽容器时，限制内部文本盒子的宽度并使其居中对齐（`margin: 0 auto;`），或者引入多列布局（如侧边栏、网格系统）来消耗剩余空间。

## 3. 如果/那么 故障排除逻辑 (If/Then Troubleshooting Logic)
- **IF** 文本块处于全屏宽度的容器中，导致每一行长达 150+ 字符，**THEN** 不要拉伸文本。应用 `max-width: 65ch` 到文本容器，并结合 `margin-left: auto; margin-right: auto` 使其在父容器中居中。
- **IF** 你在设计一个多列布局（如仪表盘的三列卡片），其中的文本行宽被挤压到 30 个字符以下，**THEN** 这种情况下必须减小字号，或者改变布局结构（如合并列），以防止出现频繁换行的“碎片化”阅读感。
- **IF** 使用的是流式布局（`width: 100%`）在移动端表现良好，但在桌面端变得极宽，**THEN** 必须在响应式断点（Media Queries）中引入最大宽度限制，或者使用组件级的宽度封顶策略。

## 4. 验证检查单 (Verification Checklists)
- [ ] 随机抽取一段正文文本，点数单行字符是否落在 45 到 75 之间（英文）或 30-45 之间（中文）。
- [ ] 调整浏览器窗口尺寸，从移动端宽度拉伸到 4K 超宽屏，确认文本是否在到达合理行宽后停止拉伸。
- [ ] 文本块的包裹容器是否通过了 CSS 约束（例如使用 `max-w-[65ch]` in Tailwind 或 `max-width: 65ch` in CSS）？
- [ ] 多余的屏幕空间是否合理地留白，或分配给了边缘装饰、侧边导航？
