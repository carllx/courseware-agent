# 模拟光源创建界面深度 (Emulating a Light Source to Create Depth)

## 前提条件与上下文 (Prerequisites & Context)
- **为什么需要 (The WHY)**: 界面设计中，为了让某些元素看起来像凸起 (Raised) 或凹陷 (Inset)，可以利用真实世界的物理光照规律。
- **何时使用 (The WHEN)**: 适用于需要创建按钮、卡片、输入框 (Text Inputs)、复选框 (Checkboxes)、容器 (Wells) 等控件时，通过深度信息引导用户交互，清晰划分界面层级关系。
- **核心原理**: **光线来自正上方 (Light comes from above)**。在这一默认假设下，面向天空的表面和边缘会接收到更多光线（显得更亮），而背对光源或被遮挡的区域则接收到较少光线（显得更暗）。人类习惯于略微俯视屏幕，如果在界面中重现这一视角的物理光影规律，大脑便能自然且直观地感知到元素的深度与层次。

## 综合指南与最佳实践 (Comprehensive Guide & Best Practices)

### 1. 设计凸起元素 (Raised Elements)
凸起元素（如主按钮）表现为悬浮或突出于页面背景之上。

- **模拟视角与边缘曝光**：
  - 用户以略微俯视的角度看屏幕时，由于透视关系，凸起元素的“顶部边缘”应能被看见，而“底部边缘”则会被隐藏。
  - **顶部边缘提亮**：因为顶部边缘面向天空，应使其比元素正面更亮。可以使用顶部边框 (Top Border) 或带有微小垂直正偏移量的内阴影 (Inset Box Shadow) 来实现。
  - **关键色彩技巧**：在提亮顶部边缘时，**必须手动选择更亮的颜色**，而不能简单地在元素上方叠加半透明的白色 (Semi-transparent White)。叠加白色往往会“吸走”底层颜色的饱和度 (Suck the saturation)，导致色彩灰暗。

- **处理遮挡与投射阴影**：
  - 凸起元素会阻挡上方光线到达其正下方的区域，从而产生阴影。
  - **底部外阴影**：添加一个小面积的深色外阴影 (Box Shadow)，带有一些垂直下偏的偏移量，确保阴影仅出现在元素底部。
  - **控制阴影锐度**：现实世界中，非常贴近表面的物体产生的阴影边缘往往是较为锐利的（例如墙壁插座或窗框的投射阴影）。因此，不要滥用阴影模糊 (Blur Radius)。几个像素的模糊半径足以传达深度的物理特性，保持边缘的相对锐利。

### 2. 设计凹陷元素 (Inset Elements)
凹陷元素（如容器 Wells、文本输入框、复选框等）表现为向页面内部陷入。

- **底部边缘反光**：
  - 从略微俯视的视角来看，凹陷部分能暴露给天空的只有它的底部内缘（下唇, Bottom Lip）。
  - **底部边缘提亮**：给下边缘一个较浅的颜色，以此模拟反光。可通过设置底部边框 (Bottom Border) 或带有负垂直偏移量的内阴影 (Inset Shadow with Negative Vertical Offset) 来实现。

- **顶部遮挡阴影**：
  - 凹陷区域的上边界会像屋檐一样阻挡垂直光线进入凹陷空间的顶部区域。
  - **顶部内阴影**：添加一个深色的、带有微小垂直正偏移量的内阴影，用以模拟上方边缘造成的遮光现象。确保阴影只停留在顶部，不至于蔓延穿透到底部干扰反光。

### 3. 克制与简化 (Don’t Get Carried Away)
- **避免过度拟物**：当你掌握了界面光影规律后，可能会倾向于花上几个小时无休止地微调参数，试图实现极致的“照片级真实感 (Photo-realistic)”。
- **保持清晰平衡**：过度拟物会导致界面过于繁杂、重点不突出。借用少量现实世界的视觉线索仅仅是为了增加深度提示。现代界面设计中，光影点到为止即可，切忌喧宾夺主。

## If/Then 故障排除逻辑 (If/Then Troubleshooting Logic)

- **If** 你使用了半透明白色来提亮按钮的顶部边缘，**Then** 你可能会发现边缘的颜色看起来不够鲜艳甚至发灰。
  - **解决方案**：移除白色的透明度叠加。使用颜色选择器，手动在 HSL 面板中调整亮度 (Lightness) 和饱和度 (Saturation)，选取一个明亮且纯粹的色彩。
- **If** 你的凸起元素（如按钮或卡片）感觉像是飘在空中很高的地方，但又不够自然，**Then** 可能是由于底部外阴影的模糊半径 (Blur Radius) 设置得过大。
  - **解决方案**：将模糊半径降低到 2~4 像素，使阴影边缘更加锐利，从而将元素在视觉上“拉回”到距离背景较近的真实高度。
- **If** 文本输入框看起来不是凹陷而是像一个平面的色块，或者感觉凸了起来，**Then** 可能是阴影的上下逻辑弄反了。
  - **解决方案**：确保输入框的顶部具有深色的内阴影（代表光线被阻挡），底部具有明亮的下边框或内高光（代表光线直接照射）。
- **If** 界面整体显得沉重、嘈杂或感觉“过时”，**Then** 你可能在模拟真实光照时用力过猛。
  - **解决方案**：降低所有高光和阴影的不透明度 (Opacity)，删去非核心组件的三维效果。只保留细微的 1 像素上下边缘高光/阴影提示。

## 验证清单 (Verification Checklists)
- [ ] **全局一致性**：整个页面的光源逻辑是否统一？（确保所有组件都假设光从正上方照射）。
- [ ] **凸起元素核查**：按钮和卡片的顶部边缘是否通过**手动调亮纯色**实现了提亮（而非白色叠加）？
- [ ] **物理距离核查**：凸起元素的底部外阴影是否足够克制、边缘相对锐利（小 Blur Radius）？
- [ ] **凹陷元素核查**：输入框、容器等凹陷组件的顶部是否具有正确的深色内阴影遮挡？其底部边缘是否有合理的提亮反光？
- [ ] **视觉纯粹性**：UI 是否避免了不必要的照片级真实感追求？光影效果是否成功服务于层级展示而不是干扰用户视线？
