# 工作流：相对尺寸与独立缩放 (Relative Sizing & Independent Scaling)

## Prerequisites & Context (前提与背景)
- **WHY (为什么需要此工作流)**：许多框架和设计习惯使用 `em` 或百分比等相对单位来进行全组件的等比例缩放。但这往往会导致元素在放大或缩小时，某些部分的比例失衡（比如边框变得太粗，或者图标显得过大）。
- **WHEN (何时使用)**：当需要为不同屏幕尺寸（响应式）或不同使用场景（如大号按钮、小号按钮）缩放组件时。

## Comprehensive Guide & Best Practices (全面指南与最佳实践)
1. **避免盲目的等比例缩放 (Avoid naive proportional scaling)**
   - 将整个组件的字体大小放大一倍，并不意味着 padding、border-width 和 border-radius 也要放大一倍。
   - 粗边框和过大的圆角在视觉上显得笨重，且通常不符合精致 UI 的美学。
2. **独立缩放元素的各个部分 (Independent Scaling)**
   - **文字与图标**：可以按照所需层级进行调整。
   - **内边距 (Padding)**：不需要与字号成正比。小号按钮可能只需要少量的 padding 调整，而大号按钮的 padding 可能更倾向于保持适中的横向比例。
   - **边框与圆角 (Border & Radius)**：尽量保持恒定或只做微调。即使是大按钮，1px 或 2px 的边框和相同的圆角（如 4px）通常也能提供最锐利和现代的外观。
3. **手工打磨每个尺寸 (Hand-craft each size)**
   - 就像字体设计师会针对不同的字号重新调整字偶距一样，UI 组件的每个尺寸（sm, md, lg）都应该被当作一个独立的实体进行设计和微调。

## If/Then Troubleshooting Logic (故障排除逻辑)
- **IF** 使用相对单位（如 `em`）设置了组件的所有尺寸，导致在大尺寸下显得臃肿笨重：
  - **THEN** 解除各部分的耦合，放弃全盘使用 `em`，改用系统设定的绝对约束值（如 rem 结合具体像素系统），手工设定不同断点下的独立尺寸。
- **IF** 响应式组件在小屏幕下圆角看起来不自然：
  - **THEN** 检查圆角是否被按比例缩小导致看起来像直角，固定圆角大小以维持品牌感。

## Verification Checklists (验证清单)
- [ ] 组件在不同尺寸（大、中、小）下的形态是否都是经过手工微调和优化的？
- [ ] 缩放组件时，边框粗细和圆角等修饰性细节是否保持了合理的恒定，而不是被过度放大？
- [ ] 是否避免了使用 `em` 统管一个复杂组件内的所有间距和尺寸？
