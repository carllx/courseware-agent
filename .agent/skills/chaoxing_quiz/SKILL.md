# 超星学习通题库生成引擎

> 核心价值：将 practice.yaml 中的 `materials[type:quiz]` 声明，自动转化为可直接粘贴到超星学习通后台的合规题库文件。

## §1 触发条件

以下任一条件成立时激活本 Skill：

1. `/design_practice` Step 4.5 产出了 `materials[type:quiz]` 节点
2. 用户显式请求生成超星题库/学习通测验
3. `/audit` 检测到 `chaoxing_export` 字段指向的文件不存在
4. **逐字稿已包含 `Type: Quiz` 的 ACTIVITY 块**，需要导出为超星格式

## §1.1 双源统一协议

> [!IMPORTANT]
> **逐字稿内联 Quiz 块是唯一真相源 (SSoT)**。
>
> 当逐字稿中已存在 `> [ACTIVITY] Type: Quiz` 块时，chaoxing-quiz 技能**不再独立出题**，
> 而是从已有的内联 Quiz 块中**提取**题目数据，转换为超星导入格式。
> 仅当逐字稿中完全没有 Quiz 块时，才按 §2 的传统流程独立生成题库。

**提取优先级**：
1. **P0** — 扫描 `src/M*.md` 中所有 `> [ACTIVITY] Type: Quiz` 块，提取 Q/Options/Answer/Explain 字段
2. **P1** — 若内联 Quiz 块不足（< 5 题），则从 `concept_registry.yaml` + `theory_prerequisites` 中补充出题
3. **P2** — 补充题目仍需写回逐字稿的 ACTIVITY 块中（保持 SSoT 一致性）

## §2 生成协议

### 2.1 知识点提取

按以下优先级提取本周核心知识点：

1. **P0** — `practice.yaml → theory_prerequisites[]`（直接列出的前置知识）
2. **P1** — `<课程>/concept_registry.yaml` 中 `first_introduced` 等于目标周次的概念
3. **P2** — `course.yaml → calendar[week].teaching_requirements`（通过 `extract_week.py` 提取）

#### 2.1.1 逐字稿回溯验证（强制门控）

> [!CAUTION]
> 此步骤为**阻断性前置条件**，不得跳过。

在完成知识点列表提取后、开始出题前，Agent **必须** `view_file` 读取本周**所有**逐字稿模块（`src/M*.md`），逐一确认：

1. 每个 `theory_prerequisite` 在逐字稿中存在对应的教学段落（记录模块编号与小节号，如 `M03 §3.1`）
2. `concept_registry.yaml` 中 `first_introduced` 匹配本周的概念，在逐字稿中有实际讲授内容
3. 将已确认的**模块定位信息**记录为草稿表，作为后续编写 `答案解析：` 的强制输入

未经此步骤验证的题库产出视为**盲标**，不得提交。

### 2.2 课程目标提取

从 `course.yaml → calendar[week].supported_objectives[]` 提取，映射到 `objectives` 下的具体描述。
格式范例：`课程目标：能力目标（2分）；创新目标（3分）`

### 2.3 题型-教学场景映射矩阵

| 教学场景 | 推荐超星题型 | 题量 | 分值建议 |
|---|---|---|---|
| 概念辨析（是/否判断） | `【判断题】` | 2-3 题 | 2 分/题 |
| 术语精确归类（单一正确） | `【单选题】` | 2-3 题 | 2 分/题 |
| 多维度知识点覆盖 | `【多选题】` | 1-2 题 | 3 分/题 |
| 术语回忆强化 | `【填空题】` | 1-2 题 | 2 分/题 |
| 情境应用分析 | `【单选题】`（情境型） | 1-2 题 | 3 分/题 |
| 深度理解论述 | `【简答题】`/`【名词解释】` | 0-1 题 | 5 分/题 |

**总题量目标**：8-15 题（覆盖本周全部知识点，按每题约 20 秒估算作答时间）

### 2.4 题目设计原则

1. **禁止纯记忆题**：每道题必须包含至少一个干扰项或情境转化
2. **答案解析必填**：每道题必须附 `答案解析：`，解释为什么对/错
3. **解析必须锚定逐字稿**：每道题的 `答案解析：` 必须包含至少一个逐字稿模块引用（如"M03 模块的三层解剖图"或"M04 第 4.2 节"），使学生在答错时能精确回溯到课堂讲授的具体场景与案例
4. **知识点标注必填**：每道题必须附 `知识点：`，对应 §2.1 提取的知识点名称
5. **知识点全覆盖**：`theory_prerequisites` 中的每个知识点至少被 1 道题的 `知识点：` 标签覆盖，不允许出现零覆盖的前置知识
6. **课程目标可选**：仅在需要 OBE 数据追溯时附 `课程目标：`
7. **难度分布**：易 40% / 中 40% / 难 20%

### 2.5 输出规范

- **文件路径**：`<课程>/practices/materials/W0X/chaoxing_quiz_w0X.txt`
- **编码**：UTF-8（无 BOM）
- **格式**：严格遵循 [超星智能导入格式规范](references/chaoxing_format_spec.md)
- **题目间隔**：题与题之间空一行，提升超星识别率

### 2.6 回填协议

生成文件后，**必须同步更新** `practice.yaml` 对应 `materials[type:quiz]` 节点的**所有**字段：

| 字段 | 回填规则 |
|---|---|
| `chaoxing_export` | 生成文件的相对路径 |
| `questions` | 实际生成的题目总数（必须与 `.txt` 文件中的题号数一致） |
| `time_limit_sec` | 按 `题量 × 20秒` 重新计算（上限 300 秒），不得沿用旧值 |

```yaml
# 示例（13 题 × 20秒 ≈ 260秒，取整至 300）
materials:
  - type: quiz
    title: "W01 交互基础快测 (超星题库)"
    questions: 13
    time_limit_sec: 300
    chaoxing_export: "practices/materials/W01/chaoxing_quiz_w01.txt"
```

## §3 生成后自检清单

| # | 检查项 | 标准 |
|---|---|---|
| C1 | 题号格式 | 连续数字 `1. 2. 3.` |
| C2 | 题型标注 | 每题含 `【题型名称】` |
| C3 | 答案格式 | 单选=字母，多选=逗号分隔，判断=对/错，填空=分号分隔 |
| C4 | 选项格式 | `A.`/`B.`/`C.`/`D.`，选项间无空行 |
| C5 | 解析存在 | 每题有 `答案解析：` |
| C6 | 知识点存在 | 每题有 `知识点：`（名称来自 §2.1） |
| C7 | 题量范围 | 8-15 题 |
| C8 | 文件路径 | 物理文件已创建且路径已回填到 YAML |
| C9 | 知识点全覆盖 | `theory_prerequisites[]` 中的每个知识点至少被 1 道题的 `知识点：` 标签覆盖 |
| C10 | 难度分布 | 易(2分题) ≥ 40%, 中(2-3分情境题) ≥ 30%, 难(3分深度题) ≤ 30% |
| C11 | 解析锚定率 | 100% 的 `答案解析：` 包含至少一个逐字稿模块引用（如 M03/M04） |
| C12 | YAML 回填完整 | `questions` / `time_limit_sec` 已同步更新，数值与生成文件一致 |
