# 颜色外观与标签编码工作流 (Color Appearance & Labeling)

## Prerequisites & Context (前提与背景)
在可视化中，颜色编码是区分分类数据（Nominal Codes）的核心手段。然而，颜色外观极易受到面积大小、背景颜色（同时对比效应 Simultaneous Contrast）和用户色觉异常的影响。本工作流旨在规范数据符号、大面积背景以及文本的颜色应用策略。
> **理论深潜**: `bash scripts/query_theory.sh "什么是同时对比效应以及颜色在小面积和大面积下的感知差异？"`

## Comprehensive Guide & Best Practices (综合指南与最佳实践)

### 1. 符号与背景的色彩分配
- **小符号使用高饱和度**：为小面积符号进行颜色编码时，必须使用更高色度（Chroma/饱和度）的颜色，以确保其易读性 [G4.10]。
- **大面积使用低饱和度**：对于大面积背景或区域编码，使用低色度（柔和、明亮）的颜色。亮色在颜色空间中占据更广阔的范围，容错率更高 [G4.12]。
- **经典层叠模式**：在低色度、高明度的背景（如柔和的粉彩色）上，叠加高色度、较暗的小符号。切忌反向操作（避免在鲜艳背景上放暗淡符号）[G4.13]。
  - **视觉参考**: 查看 `../../images/f04-24-9780128128756.jpg` 获取层叠最佳实践。

### 2. 亮度对比的强制要求
- **确保双重对比**：小面积颜色编码不仅要与背景有较大的色彩（色相）差异，还必须具备显著的**亮度对比** [G4.14]。
- **添加高对比边框**：如果彩色符号与部分背景亮度相近（等亮度 Isoluminant），必须为其添加高亮度对比的描边边框。例如：黄色符号加黑边，深蓝符号加白边 [G4.15]。

### 3. 分类命名与数量限制
- **使用可命名的颜色**：优先选择人类语言中高度一致的可命名颜色进行编码（如：红、绿、黄、蓝、棕、粉、紫、灰），这样更易于记忆和搜索 [G4.16]。
- **颜色语义与文化**：利用颜色语义（绿=安全/植被，红=危险/亏损，蓝=水/平静），但需警惕跨文化差异（如中国文化中红色代表财富与好运）。
- **控制编码上限**：如果需要准确识别，分类颜色的数量绝对**不能超过10种** [G4.18]。
- **颜色家族 (Color Families)**：如需更多分类，可使用“色相”区分大类，并通过改变同一色相的饱和度和亮度来划分子类（每组最多3个层次）。
  - **视觉参考**: 参阅 `../../images/f04-26-9780128128756.jpg` 了解颜色家族的设计。

### 4. 高亮与文本
- 改变字体颜色时，必须维持与背景的极高亮度对比（使用深色/高饱和度颜色）。
- 改变文本背景色高亮时，应使用低饱和度、高明度的浅色块。
  - **视觉参考**: 参阅 `../../images/f04-27-9780128128756.jpg` 获取文本高亮案例。

## If/Then Troubleshooting Logic (故障排除逻辑)
- **If** 用户反馈在复杂地图上找不到特定的彩色符号：
  - **Then** 检查该符号是否使用了低饱和度颜色。将符号改为高饱和度，并为其添加黑色或白色高对比边框。
- **If** 需要为色盲用户优化显示：
  - **Then** 避免使用红-绿轴向的颜色区分。采用**黄-蓝方向**的色彩变化来确保红绿色盲群体的可辨识性 [G4.17]，并利用亮度差异作为备用编码。
- **If** 图表显得混乱、眼花缭乱（Visual Clutter）：
  - **Then** 检查背景是否使用了高饱和度颜色。立即将大面积背景替换为低色度（柔和浅色）调色板。

## Verification Checklists (验证清单)
- [ ] 数据符号的分类颜色总数是否控制在10种以内？
- [ ] 所有的小面积散点/符号是否采用了高饱和度颜色？
- [ ] 背景填充色是否已经降级为低饱和度、高明度的色彩？
- [ ] 在等亮度背景下，关键符号是否已经添加了黑色或白色的对比边框？
- [ ] 系统调色板是否考虑了黄-蓝通道，以兼容色盲用户？
