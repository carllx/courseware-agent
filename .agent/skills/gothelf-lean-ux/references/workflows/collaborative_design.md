# 协作式设计与研究 (Collaborative Design & Research)

## Prerequisites & Context
**目的**: 打破设计、产品、开发之间的孤岛，促进跨职能团队在整个产品生命周期中的共同参与和责任分担。
**适用场景**: 产品探索期、需求迷茫期或需要快速发散与收敛想法的阶段。

## Comprehensive Guide & Best Practices

### 1. 协作式设计 (Collaborative Design)
- **核心活动**: 举办 Design Studio (设计工作坊)。
- **步骤**:
  1. **问题定义 (Define)**: 明确要解决的用户痛点。
  2. **发散 (Diverge)**: 团队所有成员（不论背景）在 5 分钟内快速绘制 6-8 个草图（Crazy 8s）。
  3. **展示与批评 (Critique)**: 每人展示自己的草图，接受建设性反馈。
  4. **收敛 (Converge)**: 整合优秀的点子，形成一个团队共识的解决方案。

### 2. 持续的用户研究 (Continuous User Research)
- **节奏**: 提倡“每两周至少与用户接触 3 次”。
- **方法**: 使用轻量级的可用性测试，无需繁琐的招募和实验室环境。
- **实践**: 团队全员（至少两人一组）参与测试观察。开发者和产品经理直接倾听用户的声音。

## If/Then Troubleshooting Logic
- **如果** 开发者或非设计人员拒绝参与草图绘制：
  - **则** 强调这是“为了沟通而画”，不要求任何美术功底，哪怕只画方块和文字也是极好的。
- **如果** 用户测试反馈与团队的假设完全相反：
  - **则** 必须毫不犹豫地 Pivot（转向），更新 Lean UX Canvas，切忌为了维护面子继续开发错误的功能。

## Verification Checklists
- [ ] 是否包含了跨职能成员参与设计讨论？
- [ ] 每个人是否都放下了对职位的偏见，平等地贡献了想法？
- [ ] 测试反馈是否被迅速转化为下一次迭代的输入（Backlog 更新）？
