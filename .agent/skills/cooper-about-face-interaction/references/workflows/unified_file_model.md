# 交互设计工作流：统一文件模型 (Unified File Model)

## 1. Prerequisites & Context (前提与背景：WHY & WHEN)
> [!WARNING]
> **WHY (传统文件模型的原罪)**
> 传统的“文件系统”（包括需要手动操作的打开、保存、另存为、关闭）是计算机实现模型强加给人类心智的产物。用户关心的是“文档的内容”，而不是磁盘上的磁道读写。要求用户显式点击“保存”是在强迫他们管理存储机制，这违背了目标导向设计。统一文件模型主张通过自动化彻底消除这一层认知摩擦。
> 
> **WHEN (何时应用此工作流)**
> 适用于任何涉及文档创建、内容编辑、媒体处理的应用（如写作软件、设计工具、表格应用等）。

## 2. Comprehensive Guide & Best Practices (综合指南与最佳实践)

### 2.1 隐性保存与持续存在
- **消除“保存”按钮**: 用户在界面上做的任何修改，系统应在后台静默、增量且即时地保存。
- **持续的状态**: 用户关闭应用并重新打开时，界面应完全恢复到他们离开时的状态，不需要提示“您有未保存的工作”。

### 2.2 自动文档管理
- **取消“另存为 (Save As)”**: “另存为”逻辑常常混淆用户（我修改的到底是新文件还是旧文件？）。
- **采用“副本 (Duplicate)”和“版本历史 (Version History)”**: 允许用户在不离开当前工作流的情况下创建时间节点，随时查阅或恢复历史版本。

### 2.3 重新定义文件出口
- **导出与发布**: 只有当用户需要将作品传递给其他系统或以其他格式分享时，才引入文件层级的交互。设计“导出 (Export)”或“发布 (Publish)”功能，并明确它仅是生成当前内容的一个外部快照。

### 2.4 面向文档的交互范式
- 将应用界面围绕着“文档库”或“最近打开的画布”来构建，弱化传统的本地文件夹层级树，使用标签 (Tags) 和搜索 (Search) 替代深层级的目录管理。

## 3. If/Then Troubleshooting Logic (故障排除与逻辑分支)

- **IF** 自动保存导致性能下降或网络拥堵（在处理大型文件如视频或 3D 工程时）：
  - **THEN** 采用增量差异保存技术 (Delta Saving)，或在空闲状态下节流 (Throttling) 上传。同时在状态栏用极简的指示器（如微小的同步图标）告知用户保存进度，而非阻断操作。
- **IF** 用户进行了大量实验性修改，但随后后悔，想要放弃所有更改：
  - **THEN** 由于没有“不保存并退出”的选项，必须提供强大的“恢复至上次打开时状态 (Revert to Opened)”或完整的时间线历史版本 (Time Machine) 功能。
- **IF** 用户需要将文件发给使用旧版本或不同系统的同事：
  - **THEN** 提供一键式的“导出为标准格式”功能，使其完全脱离源文件的自动保存体系。

## 4. Verification Checklists (验证清单)

- [ ] 界面中是否完全剔除了传统的“保存 (Save)”按钮？
- [ ] 在应用意外崩溃或强制关闭后，用户的任何按键或修改是否能被完全恢复？
- [ ] 软件是否用“副本/导出”功能替代了容易引起认知错乱的“另存为”？
- [ ] 是否为文件提供了直观且易于回退的版本历史管理能力？
