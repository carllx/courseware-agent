# 交互设计工作流：减少工作量与消除附加工作 (Reducing Work and Eliminating Excise)

## 1. Prerequisites & Context (前提与背景：WHY & WHEN)
> [!IMPORTANT]
> **WHY (为什么需要消除附加工作)**
> 在目标导向设计 (Goal-Directed Design) 中，用户的终极目标是完成任务并获得成就感，而不是操作软件本身。**附加工作 (Excise)** 是指用户为了满足系统的实现模型或操作机制，而不得不付出的额外努力。这会导致认知摩擦、效率降低和用户疲劳。
> 
> **WHEN (何时应用此工作流)**
> 贯穿整个交互框架设计与界面细化阶段。特别是在复杂系统、企业级应用或存在长表单、多视图切换的场景中，减少附加工作是提升可用性的关键。

## 2. Comprehensive Guide & Best Practices (综合指南与最佳实践)

### 2.1 识别不同类型的附加工作
- **认知附加工作 (Cognitive Excise)**: 强迫用户记忆系统状态、去记住不可见的快捷键、或理解晦涩的界面隐喻。
- **视觉附加工作 (Visual Excise)**: 缺乏清晰的视觉层级，导致用户在屏幕上无目的地扫视以寻找所需信息或按钮。
- **物理附加工作 (Physical Excise)**: 过多的鼠标点击、长距离的鼠标移动、频繁的键盘与鼠标切换。
- **导航附加工作 (Navigational Excise)**: 为了到达目标页面而穿梭于层层嵌套的菜单、不必要的视图切换和模态对话框中。

### 2.2 消除导航附加工作 (Navigational Excise) 的核心策略
1. **扁平化层级**: 将视图总数降至最低。尽可能在同一界面通过面板、折叠或悬浮层解决，而不是跳转新页面。
2. **避免“房间”隐喻**: 不要强迫用户在完成一个任务前退出当前“房间”并进入另一个“房间”。
3. **提供标志物 (Signposts)**: 在系统内清晰标记用户当前的位置，提供明确的全局和局部导航。
4. **精简模态对话框**: 模态对话框（特别是确认框）会打断用户的心流。尽量使用非模态提示或撤销 (Undo) 机制替代。

### 2.3 减少整体工作量的高级试金石
- **不要让用户输入系统已知的信息**: 如果可以通过默认值、历史记录或推断得出，就不要让用户手动输入。
- **记住用户的习惯**: 系统应该记住界面的大小、位置、最后一次输入的数据等（即实现智能的持久化状态）。
- **优化视觉流**: 将相关元素聚集，采用符合阅读习惯的 F 型或 Z 型布局，减少眼球转动距离。

## 3. If/Then Troubleshooting Logic (故障排除与逻辑分支)

- **IF** 用户频繁需要在两个视图间切换以对比数据：
  - **THEN** 重新设计界面，采用分屏布局或可拖拽的悬浮窗口，消除工作记忆的认知负担。
- **IF** 业务流必须要求用户经过多个繁杂的步骤：
  - **THEN** 将其转换为线性的向导 (Wizard) 模式，并预填尽可能多的智能默认值 (Smart Defaults)。
- **IF** 出于安全或业务规定必须保留确认对话框：
  - **THEN** 重新审视是否可以通过提供强大的“撤销 (Undo)”和“版本恢复”机制来免除前端的硬性阻拦。

## 4. Verification Checklists (验证清单)

- [ ] 是否所有的点击都是直接为了实现用户目标，而非为了配置系统？
- [ ] 界面是否提供了合理的默认值，让大多数用户无需修改即可继续？
- [ ] 系统是否记录了用户上一次的视图状态或表单数据？
- [ ] 是否消除了所有仅用于提示“操作成功”的模态对话框？
- [ ] 视觉流是否顺畅？核心操作是否位于用户视线自然落下的位置？
