# 交互设计工作流：平板应用布局与设计 (Tablet Format Apps)

## 1. Prerequisites & Context (前提与背景：WHY & WHEN)
> [!IMPORTANT]
> **WHY (为什么平板需要独立的设计范式)**
> 平板电脑既不是放大的手机，也不是缩小的桌面屏幕。其物理尺寸决定了用户的握持姿势（双手握持、平放、搭配支架）、使用场景（沙发上的消费级使用 vs. 会议中的生产力使用）以及交互模式（多点触控为主）。
> 
> **WHEN (何时应用此工作流)**
> 当产品需从桌面端或移动端适配至 iPad 或 Android 平板时。绝不能采用简单的响应式拉伸。

## 2. Comprehensive Guide & Best Practices (综合指南与最佳实践)

### 2.1 姿态与握持优化 (Posture & Ergonomics)
- **舒适操作区**: 考虑双手握持边缘时大拇指的触达范围。将高频交互动作（如主导航、主要操作按钮）放置在屏幕左右边缘中下部。
- **避免中心疲劳**: 屏幕最顶端和中心区域对于握持状态下较难触达，应留给内容的呈现，而非高频控制元素。

### 2.2 空间利用与分屏架构
- **抛弃单一堆叠布局**: 平板有足够的横向空间。广泛采用**主从列表布局 (Master-Detail / Split View)**。左侧放置列表，右侧直接显示内容详情。
- **内容消费至上**: 平板应用应采用“沉浸式姿态”，弱化框架，隐藏非必要导航，使内容充满屏幕。
- **悬浮面板 (Popovers)**: 替代模态对话框与下拉菜单，在上下文中轻量化展示次要选项。

### 2.3 触控靶区与手势支持 (Touch Targets & Gestures)
- **触控热区**: 确保所有可点击元素的最小尺寸为 44x44 pt（iOS）或 48x48 dp（Android），并保证足够的间距以防误触。
- **丰富手势**: 支持滑动分页、多指捏合缩放、长按呼出上下文菜单，但**手势不能是唯一的交互方式**，必须提供可见的替代操作按钮。

### 2.4 减少物理打字负担
- **替代输入法**: 屏幕键盘会占据近乎一半的屏幕空间，极其破坏心流。尽可能使用滑动条、拨盘、下拉选择、单选按钮或语音识别来替代键盘文本输入。

## 3. If/Then Troubleshooting Logic (故障排除与逻辑分支)

- **IF** 应用必须支持大量的文本输入和表单处理：
  - **THEN** 优化外部实体键盘的兼容性（支持快捷键，如 Cmd+C/V），同时在屏幕内建工具栏上提供丰富的快捷宏块。
- **IF** 在横屏 (Landscape) 下设计完美的双栏布局，切换到竖屏 (Portrait) 后空间显得极其拥挤：
  - **THEN** 设计自适应折叠机制。在竖屏时将左侧的列表导航折叠为隐藏的抽屉侧边栏 (Off-canvas drawer)，或变为下拉菜单。
- **IF** 复杂的表格数据在平板上无法完全显示：
  - **THEN** 冻结首列首行，支持双轴方向的自然滑动，并允许轻点单元格在弹出的 Popover 中编辑详情。

## 4. Verification Checklists (验证清单)

- [ ] 应用是否在横屏和竖屏下都经过了针对性的排版优化，而非简单的内容挤压？
- [ ] 高频操作（返回、确认、核心工具）是否都落在大拇指易于触达的安全区域内？
- [ ] 所有的触控热区是否满足最小 44x44 pt 的标准且间距合理？
- [ ] 是否利用分屏视图或悬浮层尽可能减少了跨页面的跳转？
