# 工作流：工具栏与标签栏设计 (Bars)

## 1. 前置条件与上下文 (Prerequisites & Context)
**为何需要 (WHY)**: 
“栏”（Bars，包括工具栏 Toolbars、标签栏 Tab bars、状态栏等）是图形用户界面（GUI）中最高效的全局导航和命令触达区域。与深埋在菜单中的选项不同，栏能将最常用的功能扁平化地呈现，利用肌肉记忆降低用户的认知与操作负荷（Excise）。
**何时使用 (WHEN)**:
- 当需要为高频操作提供一步直达的快捷方式时（工具栏）。
- 当需要在同层级的不同内容视图间快速切换时（标签栏）。

## 2. 综合指南与最佳实践 (Comprehensive Guide & Best Practices)
- **图标与文字的平衡**：工具栏图标必须极具表意性。如果图标含义可能产生歧义，必须提供工具提示（Tooltips）；在空间允许或功能极重要时，采用“图标+文字”标签。
- **状态的可见性**：栏中的元素必须清晰地传达当前状态（如按钮被按下、某个 Tab 处于激活状态）。选中状态必须与未选中状态有强烈的视觉对比。
- **功能分组与逻辑排序**：
  - 将相关工具通过视觉分隔符（竖线或空白）进行逻辑分组（如：格式化工具一组，对齐工具一组）。
  - 最高频或最重要的操作应放置在最容易到达的位置（如屏幕边缘，符合 Fitts's Law 菲茨定律）。
- **避免多排工具栏的混乱**：不要让工具栏占据过多的垂直空间。如果工具过多，考虑使用带折叠的“抽屉”、“Ribbon（面板）”或者允许用户自定义工具栏。
- **禁用状态的处理**：当某个工具在当前上下文中不可用时，不要将其隐藏，而是将其置灰（Disabled），以维持界面布局的稳定性和用户的空间记忆。

## 3. If/Then 故障排除逻辑 (If/Then Troubleshooting Logic)
- **If** 标签栏（Tab bar）的标签数量超过了屏幕宽度能容纳的上限，**Then** 不要使用多排标签（这会破坏视觉和层级的一致性），而应使用水平滑动或将溢出项放入一个“更多...”的下拉菜单中。
- **If** 工具栏占用了太多的屏幕内容区域，**Then** 考虑使工具栏变为可停靠/浮动（Dockable/Floating），或者在滚动页面时自动隐藏（如移动端的向下滚动隐藏）。
- **If** 用户不清楚某个不常见工具图标的作用，**Then** 确保光标悬停超过 0.5 秒时弹出包含名称及快捷键提示的富工具提示（Rich Tooltip）。

## 4. 验证检查表 (Verification Checklists)
- [ ] 高频操作是否都在第一级工具栏/标签栏中可见？
- [ ] 激活的标签或按下的工具按钮是否有明确的视觉反馈（颜色、深浅或边框变化）？
- [ ] 栏中的命令是否按逻辑和功能相似性进行了视觉分组？
- [ ] 不可用的命令是否被一致地置灰，而不是突然消失？
- [ ] 工具栏的点击热区（Hit targets）是否足够大（特别是在触屏设备上，至少 44x44 pt）？
