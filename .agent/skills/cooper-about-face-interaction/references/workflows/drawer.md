# 工作流：抽屉式界面设计 (Drawer)

## 1. 前置条件与上下文 (Prerequisites & Context)
**为何需要 (WHY)**: 
抽屉（Drawer）是一种可以在主内容区上方滑动出现或将主内容区推开的面板组件（如导航抽屉 Navigation Drawer、底部抽屉 Bottom Sheet）。它解决了屏幕空间有限的问题，允许用户在不离开当前上下文的情况下访问全局导航或辅助信息。
**何时使用 (WHEN)**:
- 当需要提供不常用的全局导航选项，且不希望占用主屏幕的常驻空间时（如汉堡菜单引出的侧边抽屉）。
- 在移动端或拥挤的界面中，需要对当前对象进行复杂设置或查看详情，但不希望跳转到新页面而丢失当前上下文时（底部或侧边抽屉）。

## 2. 综合指南与最佳实践 (Comprehensive Guide & Best Practices)
- **区分使用场景**：
  - **导航抽屉（侧边）**：通常位于屏幕左侧，用于在应用的高层级视图之间切换。它应该始终包含返回主页/核心视图的路径。
  - **模态抽屉（Modal Drawers）**：出现时通常带有一个半透明的黑色遮罩（Scrim），阻止用户与主内容区交互。适用于必须先处理完毕才能继续的任务。
  - **非模态抽屉（Standard Drawers）**：与主内容区同级，打开时挤压（推开）主内容，允许用户同时与抽屉和主内容交互（适用于桌面端或宽屏设备）。
- **进入与退出机制**：
  - 必须提供明确的关闭方式：点击抽屉外的遮罩区域关闭（对于模态抽屉）、向下滑动/侧滑关闭手势、以及明确的“关闭(X)”或“取消”按钮。
  - 动画应当遵循物理规律：从边缘滑入，速度应当迅速且带有平滑的缓动曲线（Easing）。
- **层级深度控制**：绝对不要在抽屉内部再打开另一个抽屉（嵌套抽屉），这会严重破坏用户的空间记忆和层级认知。如果抽屉内包含复杂流程，应该考虑使用全屏页面。

## 3. If/Then 故障排除逻辑 (If/Then Troubleshooting Logic)
- **If** 抽屉中的内容过长需要滚动，而抽屉自身也支持滑动关闭，**Then** 必须仔细处理滚动冲突。通常的策略是：当抽屉内部滚动到顶部时，继续向下滑动才触发抽屉关闭机制；或者提供一个不可滚动的“把手（Handle/Drag indicator）”区域专门用于拖拽。
- **If** 用户频繁地打开侧边导航抽屉在两个页面之间来回切换，**Then** 说明这种架构效率低下。应考虑将这两个视图放在底部标签栏（Bottom Tab bar）中，暴露在第一层级。
- **If** 抽屉遮挡了用户在进行操作时必须参考的底层关键信息，**Then** 将模态抽屉改为非模态侧边栏，或者使用底半部抽屉（Bottom Sheet）仅遮挡部分屏幕。

## 4. 验证检查表 (Verification Checklists)
- [ ] 抽屉滑入和滑出的动效是否流畅且不突兀（通常在 200-300ms 之间）？
- [ ] 用户是否可以通过点击外部遮罩（Scrim）或使用返回手势轻松关闭模态抽屉？
- [ ] 是否避免了在抽屉内部打开多层级的新视图或嵌套抽屉？
- [ ] 对于包含重要设置项的抽屉，关闭时是否会自动保存（或提醒用户保存）未提交的更改？
- [ ] 抽屉是否被过度滥用以隐藏那些本应该直接展示给用户的核心功能？
