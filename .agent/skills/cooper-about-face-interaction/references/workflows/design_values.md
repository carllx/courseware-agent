# 工作流：设计价值观 (Design Values)

## 1. 前置条件与上下文 (Prerequisites & Context)
**为何需要 (WHY)**: 
在交互设计中，如果没有一套统一的核心价值观，设计决策将不可避免地沦为工程师的个人喜好、营销团队的临时冲动或管理层的妥协。Alan Cooper 认为，有效的设计必须建立在道德和商业并重的价值观基础之上。
**何时使用 (WHEN)**:
在项目启动、制定产品愿景、以及在多个功能需求之间产生优先级冲突，需要裁决权衡（Trade-offs）时。

## 2. 综合指南与最佳实践 (Comprehensive Guide & Best Practices)
- **以目标为导向的核心价值观**：
  1. **符合伦理道德 (Ethical)**：不伤害用户（包括身体、心理、隐私及经济上的伤害）。必须保护用户的数据安全并尊重他们的注意力。
  2. **有用 (Purposeful/Useful)**：产品必须切实地帮助用户达成其个人、职业或生活上的最终目标（Goals），而不是仅仅提供花哨的技术功能。
  3. **实用 (Pragmatic)**：产品应当能够满足商业目标，并且在现有的技术和时间约束下是可构建的。设计不能脱离现实。
  4. **优雅 (Elegant)**：最简单的解决最复杂问题的方案。通过消除不必要的摩擦（Excise）和复杂性，提供流畅、愉悦的体验。
- **处理冲突的层级**：
  - 当商业目标（如增加广告曝光）与用户目标（如快速找到信息）冲突时，应当优先寻找不损害体验的商业创新。若不可避免，必须遵守“不作恶”和不进行过度干扰的伦理底线。
  - 保护用户的自尊心。绝对不要让用户觉得自己很愚蠢（避免居高临下的错误提示）。
- **透明与信任**：设计应当是透明的，让用户理解系统在做什么，为什么这么做。建立产品与用户之间的长期信任。

## 3. If/Then 故障排除逻辑 (If/Then Troubleshooting Logic)
- **If** 利益相关者要求加入诱导性设计（Dark Patterns）以达成短期的商业指标，**Then** 利用设计价值观中的“伦理”底线进行反击，并提供能够双赢的“优雅”替代方案，展示由于丧失用户信任所带来的长期商业风险（如高流失率）。
- **If** 工程师认为某个体验设计在技术上太难实现而要求妥协，**Then** 评估妥协对用户“有用性”的损害。如果损害了核心体验目标，需要坚持并共同寻找创新的技术路径；如果仅是外观细节，可基于“实用”原则进行妥协。
- **If** 现有的产品功能极度臃肿，**Then** 利用“优雅”价值观进行审计，砍掉那些不能服务于用户核心目标或商业核心目标的边缘功能。

## 4. 验证检查表 (Verification Checklists)
- [ ] 设计方案是否尊重了用户的隐私和注意力？（有无滥用通知或收集不必要数据）
- [ ] 设计是否直接服务于用户试图达成的最终目标，而非只是堆砌任务？
- [ ] 当出现错误时，系统是否主动承担责任，而不是将责任推给用户？
- [ ] 产品交互是否足够流畅，尽可能减少了操作上的认知负荷（Excise）？
- [ ] 现有的设计决策是否可以在团队内部明确地与“伦理、有用、实用、优雅”建立联系？
