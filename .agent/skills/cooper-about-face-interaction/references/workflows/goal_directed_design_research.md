# 工作流：目标导向设计研究 (Goal-Directed Design Research)

## 1. 前置条件与上下文 (Prerequisites & Context)
**为何需要 (WHY)**: 
“垃圾进，垃圾出”。没有建立在对用户行为和动机深度理解基础上的设计注定失败。目标导向的研究旨在通过定性研究手段（Qualitative Research）揭示用户的行为模式（Patterns）、思维模型（Mental Models）以及驱动这些行为的潜在目标（Goals）。
**何时使用 (WHEN)**:
项目的最早期（Phase 1）。在任何草图被绘制或任何代码被编写之前。

## 2. 综合指南与最佳实践 (Comprehensive Guide & Best Practices)
- **启动会议 (Kickoff Meeting)**：
  - 采访业务利益相关者（Stakeholders）和技术领袖（SMEs）。了解商业目标、技术限制、项目愿景以及现有的知识沉淀。
- **文献回顾与竞品审计 (Literature/Competitive Audit)**：
  - 梳理现有的行业报告、内部文档以及竞品。重点关注竞品如何解决类似问题，而不是为了抄袭功能。
- **定义人物志假设 (Persona Hypothesis)**：
  - 在见用户之前，先基于常识和案头研究推测可能的行为变量（如：极客型 vs 恐科型，自主规划 vs 接受指令）。这将决定你需要去寻找哪些类型的受访者。
- **人种学访谈与观察 (Ethnographic Interviews & Contextual Inquiry)**：
  - 去用户真实的发生场景。
  - 提问结构：背景破冰 -> 整体工作流 -> 深入特定任务 -> 挖掘变通策略（Workarounds） -> 探索期望与终极目标。
  - 倾听重于提问。关注行为背后的原因（The 5 Whys）。
- **研究的终点 (When to Stop)**：
  - 遵循“理论饱和（Theoretical Saturation）”原则：当你在后续的访谈中开始不断听到重复的模式，不再有新的重大行为模式出现时（通常在访问了每类角色的 5-7 个人之后），研究就可以停止了。

## 3. If/Then 故障排除逻辑 (If/Then Troubleshooting Logic)
- **If** 利益相关者坚持只使用问卷调查或数据分析（定量分析）而不做定性研究，**Then** 向他们解释：定量数据只能告诉我们“发生了什么（What）”以及“频率（How many）”，只有定性研究能告诉我们“为什么发生（Why）”和“如何改进”。争取进行少量的定性抽样访谈以证明价值。
- **If** 访谈对象是具有高度专业知识的领域专家（SME，如医生、工程师），他们喜欢提供具体的解决方案而非描述痛点，**Then** 礼貌地将他们引导回场景：“这听起来是个很棒的功能，但您能带我回到您遇到这个困难的那一天，告诉我当时具体的情境吗？”
- **If** 在访谈中发现实际用户的行为模式与最初的“人物志假设”完全相悖，**Then** 这是极好的结果。立即抛弃原有的假设，根据实地收集到的真实行为模式重新调整变量和招募计划。

## 4. 验证检查表 (Verification Checklists)
- [ ] 是否在正式研究前与业务方对齐了商业目标和技术约束？
- [ ] 访谈样本是否覆盖了预测的行为变量两端（例如最活跃的用户和最边缘的用户）？
- [ ] 是否主要通过“观察用户实际操作”而非仅仅“听他们讲述”来收集数据？
- [ ] 是否识别并记录了用户目前使用的任何非官方工具或变通方法（Workarounds）？
- [ ] 研究结果是否能够清晰地归纳出用户的行为模式和根本目标，以供下一步构建 Persona 使用？
