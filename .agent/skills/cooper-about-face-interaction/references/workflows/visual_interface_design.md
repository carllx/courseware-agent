# 交互设计工作流：视觉界面设计 (Visual Interface Design)

## 1. Prerequisites & Context (前提与背景：WHY & WHEN)
> [!TIP]
> **WHY (视觉设计在交互中的价值)**
> 视觉设计不仅仅是关于“美感”和品牌包装。在目标导向设计中，视觉设计是传达信息层级、提供交互线索 (Affordance)、组织信息流并减少用户认知负荷的核心手段。优秀的视觉设计能让界面的结构不言自明。
> 
> **WHEN (何时应用此工作流)**
> 在交互框架（线框图）已经确立，开始进行保真度提升和最终界面交付时。

## 2. Comprehensive Guide & Best Practices (综合指南与最佳实践)

### 2.1 建立视觉层级 (Visual Hierarchy)
- **利用视觉属性**: 通过大小、色彩对比度、字体粗细、空间位置，精确反映元素在逻辑上的重要性。
- **逻辑对应**: 屏幕上视觉上最突出的元素，必须也是人物角色完成关键路径任务时最需要的核心元素。

### 2.2 引导视觉流 (Visual Flow)
- 人的眼睛倾向于遵循特定的扫视模式（如从左到右、从上到下的 F 型或 Z 型）。
- **对齐与网格**: 利用严格的网格系统和隐形线条来引导视线。不对齐会产生视觉噪音（视觉附加工作），强迫眼睛做不必要的跳跃。
- **相关性与接近性**: 格式塔原理。在逻辑上相关的元素在空间上也应该紧密靠近，用留白（而非线条框）来划分不同的内容区块。

### 2.3 交互线索与启示 (Affordance & Signifiers)
- 如果一个元素可以点击，它的视觉处理（如阴影、微弱的渐变、特定的可交互色彩）必须明确暗示它的可点击性。
- 区分不同状态：正常、悬停 (Hover)、按下 (Active)、聚焦 (Focus) 和禁用 (Disabled)，每种状态都需明确的视觉反馈。

### 2.4 极简主义与信噪比
- 最大化信噪比。去掉一切不传达有用信息或交互状态的装饰性元素（如无用的渐变背景、过重的边框线）。
- 颜色应当有节制地使用，通常作为高亮重要信息、指示状态（红黄绿）或呼唤行动 (CTA) 的工具。

## 3. If/Then Troubleshooting Logic (故障排除与逻辑分支)

- **IF** 界面看起来极其杂乱，用户找不到视觉焦点：
  - **THEN** 执行“眯眼测试 (Squint Test)”。眯起眼睛看屏幕，看哪些色块最突出。如果突出的都是次要元素，说明视觉层级失效。减少整体色彩，增加大量留白，降低次要元素的对比度。
- **IF** 开发团队反映界面上的线条和边框太多导致界面僵硬：
  - **THEN** 用合理的负空间（留白）代替物理线条来分割区域。留白是最高级的分割线。
- **IF** 重要的按钮或警报在屏幕上不够显眼：
  - **THEN** 不要盲目放大按钮的尺寸。通过改变色彩对比度，或在按钮周围增加大量留白，使其在空间上独立，这比纯粹变大更有效。

## 4. Verification Checklists (验证清单)

- [ ] 界面的视觉重心是否完美对应了该界面的核心业务目标？
- [ ] 所有的可交互元素（按钮、链接、输入框）是否传达了统一且清晰的交互启示 (Affordance)？
- [ ] 界面是否遵循了严格的对齐和网格系统，视觉流向是否顺畅？
- [ ] 是否在设计中保持了高信噪比，去除了所有不必要的视觉装饰物和重边框？
- [ ] 颜色使用是否具有一致的逻辑语义（如统一的主题色代表可交互，特定颜色代表错误或警告）？
