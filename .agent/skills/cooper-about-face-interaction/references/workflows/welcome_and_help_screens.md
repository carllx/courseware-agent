# 交互设计工作流：欢迎界面与帮助系统 (Welcome and Help Screens)

## 1. Prerequisites & Context (前提与背景：WHY & WHEN)
> [!IMPORTANT]
> **WHY (为什么初学者体验至关重要)**
> 每一个专家用户都必须经历一个“初学者阶段”。初次打开软件的几分钟往往决定了产品的留存率。传统的“使用手册”或枯燥的文案墙不仅无法帮助用户，反而会引发抵触。需要通过精心设计的引导 (Onboarding)、空状态 (Empty States) 和上下文化帮助来护送用户平滑度过初学者阶段。
> 
> **WHEN (何时应用此工作流)**
> 必须在核心交互流程设计完成后，专门针对“首次启动体验”和“异常空白状态”进行专项设计时。

## 2. Comprehensive Guide & Best Practices (综合指南与最佳实践)

### 2.1 破冰与欢迎 (Welcome Experience)
- **展示价值而非仅仅是Logo**: 在首次启动时，简明扼要地传达产品能帮用户达成什么**终极目标**，而不只是列举功能。
- **提供快速通道**: 为新手提供一键式的示例模板或向导，消除“面对白纸的恐惧”。不要在一开始就强迫他们进行繁琐的全局设置。

### 2.2 利用空状态 (Empty States)
- 首次进入数据列表、信息流时，屏幕必然是空的。这是最好的教育阵地。
- **空状态三要素**: 
  1. 告知这里将显示什么。
  2. 告知为什么它是空的。
  3. 提供一个明显的“行动号召 (CTA)”按钮或箭头，引导用户进行首次创建。

### 2.3 上下文感知与嵌入式帮助 (Inline Help)
- 废弃厚重的“帮助中心”隐喻。帮助应该在用户遇到困惑的当下，就近提供。
- **微文案与提示气泡 (Tooltips)**: 对于生僻图标或复杂表单，提供即时的悬停提示或行内解释。
- **逐步揭示 (Progressive Disclosure)**: 随着用户的深入，逐渐展开高级功能的提示，不要在新手教程里一次性倾倒所有信息。

### 2.4 容错式向导与画中画 (Guided Tours)
- 如果必须要有流程向导，确保用户可以随时跳过并轻松找回。
- 让用户在真实的界面中边做边学 (Learn by Doing)，而不是通过非交互的轮播图。

## 3. If/Then Troubleshooting Logic (故障排除与逻辑分支)

- **IF** 分析数据显示绝大多数用户疯狂点击“跳过新手引导”：
  - **THEN** 说明强制的、遮罩式的全局向导阻碍了用户探索。废弃强制向导，改用空状态教育 (Empty States) 或非模态的提示语，让用户自主探索。
- **IF** 系统具有非常复杂的领域专业知识（如 3D 建模、复杂的财税计算）：
  - **THEN** 仅仅靠界面线索是不够的。引入包含样例项目 (Sample Projects) 的画廊，让用户可以直接打开一个已完成的优秀案例进行逆向学习和修改，这是专家型产品最好的欢迎方式。
- **IF** 用户在长期的使用中遗忘了某些偶尔才用的功能的用法：
  - **THEN** 确保所有嵌入式提示可以随时唤出（如界面常驻的问号图标）。系统的帮助模型必须既兼顾初学者的“手把手引导”，也兼顾中级用户的“按需速查”。

## 4. Verification Checklists (验证清单)

- [ ] 首次启动应用时，是否将用户的核心注意力引导至产品的核心价值，而非无聊的注册表单？
- [ ] 所有的空数据视图是否都设计了有意义的“空状态”，并包含了明确的第一步操作按钮？
- [ ] 复杂的专业词汇或操作是否配备了上下文相关的 Tooltip 或悬浮解释？
- [ ] 帮助系统是否允许用户“在上下文中”边看边操作，而不是强制跳转到外部网页？
- [ ] 强制的新手引导流程是否被控制到了绝对的最短长度，并允许随时跳过与找回？
