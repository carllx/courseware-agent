# 用户研究：人物角色假设工作流 (Persona Hypothesis)

## Prerequisites & Context (前提条件与上下文)
**WHY（为什么使用）**：
在真正走进田野开展人种学访谈之前，我们不能盲目地去街上随便拉人提问。“人物角色假设（Persona Hypothesis）”是目标导向设计的第一步。它是基于团队现有的业务知识、前期市场调研或对利益相关者的访谈，初步构建出的目标用户草图。它为后续的实地研究划定了边界、指明了访谈对象的选择方向，并提供了待验证的假设框架。
**WHEN（何时使用）**：
- 项目刚刚启动（Kick-off）时。
- 在制定用户访谈计划（Interview Plan）和筛选问卷（Screener）之前。
- 在与利益相关者（SME、业务方）进行初步访谈时。

## Comprehensive Guide & Best Practices (综合指南与最佳实践)
构建人物角色假设主要包含三个核心维度的预判：

### 1. 假设不同类别的潜在用户 (Identify Potential User Categories)
根据产品所处的行业和业务模式，初步列出可能的用户群：
- **按角色划分**：例如在一个医院系统中，可能是“护士”、“主治医师”、“科室主任”、“IT维护人员”。
- **按生命周期划分**：新手、活跃用户、流失用户。
- **按业务链条划分**：内容的生产者、内容的消费者、内容的审核者。

### 2. 预测可能的行为变量 (Anticipate Behavioral Variables)
这是最重要的一步。猜测不同用户在面对同一任务时，可能在哪些维度上表现出差异（光谱的两端）：
- **频率与强度**：偶尔使用 vs 高频重度使用。
- **专业水平**：领域小白 vs 领域专家；电脑盲 vs 技术极客。
- **动机与态度**：为了完成工作任务应付差事 vs 出于个人热情精益求精。
- **思维方式**：偏好宏观数据图表 vs 偏好逐条核对细节。

### 3. 制定访谈采样计划 (Create the Interview Sampling Plan)
- 将上述假设转化为实际招募受访者的指标。
- 确保访谈名单能够覆盖你预测的各个“行为变量”光谱的两端。例如，如果你假设“技术熟练度”是一个重要变量，你的访谈名单里就必须既有老手也有极度小白。
- **最佳实践**：每个细分群体（或变量端点）至少计划访谈 4-6 人，以确保发现模式。

## If/Then Troubleshooting Logic (If/Then 故障排除逻辑)
- **IF** 团队在会议上对假设角色的具体特征产生了激烈争论（例如“护士绝对不会用iPad”对战“护士现在都用iPad”），**THEN** 立即停止争论。将争议点记录为“高优先级待验证假设（Hypothesis to Validate）”，留到后续的实地访谈中用真实数据来裁决。
- **IF** 业务方提供的用户类别完全是基于市场人口统计学（如“18-25岁的一线城市女性”），**THEN** 引导他们思考这些人在“行为”上的差异。追问：“同样是18-25岁，有没有哪类人是狂热购买者，哪类是只看不买的？他们为什么不同？”从而将人口属性转化为行为变量假设。
- **IF** 假设生成的访谈受众过广，超出了项目的时间和预算限制，**THEN** 要求业务团队或项目发起人进行优先级排序，暂时放弃边缘用户群，聚焦于被认为是产品成功关键的 2-3 个核心假设群体进行深度访谈。

## Verification Checklists (验证清单)
- [ ] 是否已经明确区分了基于市场营销的假设（人口统计）和基于设计的假设（行为变量）？
- [ ] 是否梳理出了一份待验证的“行为变量清单（Behavioral Variables List）”？
- [ ] 访谈招募计划的受众是否足够多样化，能够覆盖假设变量的两端？
- [ ] 团队是否达成共识：这仅仅是一个“假设”，并且做好了在实地研究后推翻并重写这些角色的准备？
