# 移动设备与触控：多点触控手势工作流 (Multi-Touch Gestures)

## Prerequisites & Context (前提条件与上下文)
**WHY（为什么使用）**：
随着移动设备和平板电脑的普及，多点触控（Multi-Touch）已成为主流的交互媒介。与传统的基于鼠标的精确点击（WIMP 界面）不同，触控手势具有直观、直接操作（Direct Manipulation）的优势，但也伴随“胖手指问题（Fat-finger problem）”、缺乏可见性（Invisible affordance）以及物理疲劳等挑战。《About Face》要求设计师将手势不仅视为输入手段，更要视为与数字内容产生情感与物理共鸣的工具。
**WHEN（何时使用）**：
- 为智能手机、平板、触屏信息亭等移动/触控设备设计界面时。
- 需要将复杂的桌面级功能平移到有限的移动屏幕上时。
- 当界面需要提升沉浸感、减少可见的控制按钮（UI chrome）时。

## Comprehensive Guide & Best Practices (综合指南与最佳实践)

### 1. 理解触控环境与人体工程学 (Understand Touch Ergonomics)
- **触控区域 (Touch Targets)**：人类手指不够精准。可点击区域必须足够大，至少应满足 44x44 像素（iOS）或 48x48 dp（Android）的标准物理尺寸（约 7-10mm）。
- **手持姿势 (Device Posture)**：考虑用户是单手持握操作（拇指控制，有效热区在屏幕下方和侧边）、双手持握（键盘输入）还是平板的桌面平放。核心操作应放在最舒适的“拇指自然接触区”。

### 2. 核心手势的标准化应用 (Apply Standard Gestures Correctly)
不要随意发明新动作，优先采用用户已形成的肌肉记忆：
- **Tap (轻击)**：用于选择对象、触发按钮或链接。等同于鼠标左键点击。
- **Swipe / Flick (滑动/轻扫)**：用于平移内容（如滚动列表、翻页）。具有物理惯性（Kinetic scrolling）。
- **Pinch & Spread (捏合与张开)**：专用于无级缩放（Semantic zoom），如地图、图片。
- **Drag (拖拽)**：长按后移动，用于重新排列列表项或移动对象。
- **Long Press (长按)**：用于唤出上下文菜单（Context menu）或进入特殊编辑模式（如 iOS 桌面图标重排）。需注意长按的可见性极低。

### 3. 处理手势的可发现性与隐形性 (Manage Discoverability)
- **不可见的手势**：除了 Tap 明显的按钮外，Swipe、Pinch、Long press 都是“不可见”的 UI 元素，新手可能不知道它们的存在。
- **最佳实践**：
  - **提供视觉暗示 (Visual Signifiers)**：例如轮播图露出下一张边缘的一部分，暗示可以 Swipe；或者提供一个小抓手（Grip/Handle）图标暗示可 Drag。
  - **优雅降级**：对于复杂的进阶手势（如三指滑动），必须提供相应的可见按钮作为备选方案（Alternative path）。

### 4. 反馈与直接操作感 (Provide Feedback & Direct Manipulation)
- **零延迟响应**：触控手势必须与屏幕内容的物理位移做到 1:1 零延迟绑定。当手指移动时，对象应严格跟随手指。
- **动效反馈**：当手指触碰、滑动达到边界或释放时，应提供符合物理直觉的视觉反馈（如触控水波纹、列表到底的回弹动画/Rubber-banding）。

## If/Then Troubleshooting Logic (If/Then 故障排除逻辑)
- **IF** 用户频繁发生误触（Accidental touches）导致意外跳转，**THEN** 检查并扩大热区之间的物理间距（Padding），特别是具有破坏性后果的按钮（如“删除”和“保存”不能紧挨着）。
- **IF** 数据显示某个通过“长按”或“双击”触发的高级功能使用率极低，**THEN** 说明手势的可发现性差。在界面上增加显式的“更多（...）”按钮，或在初次进入时加入轻量级的动画引导（Onboarding Hint）来教授该手势。
- **IF** 界面同时需要支持屏幕纵向滑动（滚动内容）和特定条目的横向滑动（如滑动删除），**THEN** 必须设计严格的手势方向防抖（Gesture locking）机制，确保当用户斜向滑动时，系统能准确判断并锁定为单一轴向，防止界面同时产生横纵向的抖动。

## Verification Checklists (验证清单)
- [ ] **热区尺寸**：所有可交互元素的热区是否达到了 7~10mm（约 44x44pt）的最低触控标准？
- [ ] **防误触间距**：破坏性操作附近是否有足够的安全空间防止“胖手指”误触？
- [ ] **人体工程学**：最常用的核心功能是否位于单手持握时拇指可舒适触及的区域（如屏幕底部）？
- [ ] **手势防冲突**：应用内的自定义手势是否与系统级手势（如边缘滑动返回、底部上滑回桌面）产生了冲突？
- [ ] **备选路径**：依赖于不可见手势（如长按、双指捏合）的关键功能，是否提供了可见的备选触控方式（如放大镜按钮、显性菜单）？
- [ ] **触觉与视觉反馈**：所有手势操作是否都具有即时的状态改变反馈和物理回弹动效？
