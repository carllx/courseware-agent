# 用户研究：访谈阶段工作流 (Interview Phases)

## Prerequisites & Context (前提条件与上下文)
**WHY（为什么使用）**：
在目标导向设计（Goal-Directed Design）中，人种学访谈（Ethnographic Interviews）是理解用户目标、动机和实际行为的最有效方法。成功的用户研究访谈不应是随意的聊天，而应按照结构化的“早期、中期、晚期”三个阶段逐步推进，从探索领域边界走向挖掘具体行为，最终收敛于验证和细化角色假设。
**WHEN（何时使用）**：
- 在建立初步的人物角色假设（Persona Hypothesis）之后。
- 计划开展定性研究（Qualitative Research）以挖掘用户深层需求与目标时。
- 需要将宽泛的领域知识具象化为特定的设计需求时。

## Comprehensive Guide & Best Practices (综合指南与最佳实践)

### 1. 早期访谈阶段 (Early Phase: Domain Exploration)
- **核心目标**：探索领域知识（Domain knowledge），理解基本词汇、行业术语、高层级的目标以及大致的工作流。
- **受访者特征**：通常选择经验丰富、乐于表达的用户或领域专家（SME）。
- **提问策略**：采用高度开放式（Open-ended）的问题，鼓励受访者讲述他们工作/生活环境的整体图景。
  - *“请向我描述一下您典型的一天是如何度过的？”*
  - *“对于这项工作，最大的挑战或最重要的指标是什么？”*
- **最佳实践**：在这个阶段，研究者应表现出“好奇的学徒”心态，多听少说，不去纠结极端边缘情况，致力于建立宏观的概念模型。

### 2. 中期访谈阶段 (Middle Phase: Task & Behavioral Understanding)
- **核心目标**：深入理解用户的具体任务、目标、常见痛点以及他们为了达成目标而采取的变通方法（Workarounds）。
- **受访者特征**：涵盖不同层级的目标用户（新手、中间用户、专家），此时人物角色假设开始受到挑战或被强化。
- **提问策略**：从开放式问题逐渐转向针对具体行为、情境的探究式（Probing）问题，要求提供具体例子。
  - *“您刚才提到经常遇到系统卡顿的问题，能回想一下上一次发生这种情况时，您具体是怎么处理的吗？”*
  - *“为什么您会选择先导出到 Excel 再处理，而不是直接在系统里做？”*
- **最佳实践**：密切关注用户“所说”与“所做”之间的差异。在情境调查中，观察用户的实际操作、桌面的便签贴、或者自制的备忘录（这些往往是系统设计失败的证据）。

### 3. 晚期访谈阶段 (Late Phase: Verification & Clarification)
- **核心目标**：验证之前发现的模式（Patterns），澄清模糊的边界情况，确认提取的潜在人物角色特征是否准确。
- **受访者特征**：针对在角色矩阵（Persona Grid）中尚未覆盖的用户类型，或者用来补全特定行为变量的用户。
- **提问策略**：问题变得更加具体、封闭，侧重于澄清或确认。
  - *“之前的受访者提到他们会因为 X 而中断任务，这种情况在您的工作中也普遍吗？”*
  - *“如果您不执行这个步骤，会发生什么最坏的情况？”*
- **最佳实践**：这是填补知识空白的最后机会，不要再把时间花在已经明确的宏观领域知识上。开始在脑海中（或团队间）将受访者映射到具体的人物角色原型上。

## If/Then Troubleshooting Logic (If/Then 故障排除逻辑)
- **IF** 在早期访谈中，受访者过于纠结具体功能抱怨或提出“我想要个XX按钮”的解决方案，**THEN** 研究者应及时引导回溯其背后的目标，提问：“如果有这个按钮，能帮您解决什么根本问题？（What goal does this help you achieve?）”。
- **IF** 在中期访谈中，用户表示“一切都很顺利，没有任何问题”，**THEN** 不要停止追问。要求用户现场演示一次核心流程，仔细观察其是否存在无意识的习惯性变通行为（如繁琐的复制粘贴），并对其行为原因提出探究。
- **IF** 到了晚期访谈，依然不断发现全新的重大行为模式或完全陌生的业务逻辑，**THEN** 说明早/中期的覆盖面不足或领域过于复杂。必须增加访谈样本量，或将研究周期延长，直到获取的数据达到“饱和状态（Saturation）”。

## Verification Checklists (验证清单)
- [ ] **早期验证**：团队是否已经掌握了受访者的行业黑话和基本业务流转机制？
- [ ] **中期验证**：是否收集到了足够的“真实场景案例”，而非仅仅是用户的概括性描述？
- [ ] **痛点深挖**：是否找出了用户自创的、用于弥补现有系统不足的 Workarounds（变通方法）？
- [ ] **晚期验证**：访谈问题是否已经从“探索式”成功过渡到了“验证式”？
- [ ] **数据饱和**：在最后几次访谈中，是否感觉到“听不到新的核心概念了”（即达到了研究饱和状态）？
