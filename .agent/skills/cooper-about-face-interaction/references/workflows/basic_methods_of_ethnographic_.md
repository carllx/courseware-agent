# 工作流：人种学访谈的基本方法 (Basic Methods of Ethnographic Interviewing)

## 1. 前置条件与上下文 (Prerequisites & Context)
**为何需要 (WHY)**: 
《About Face》强调，定量的市场调研和传统的焦点小组（Focus Groups）无法揭示用户在实际工作或生活中的真实动机、目标和行为模式（Workarounds）。人种学访谈（结合实地观察与情境访谈）能够绕过用户自己“以为的需求”，发掘出驱动设计决策的真实目标（Goals）。
**何时使用 (WHEN)**:
在目标导向设计（Goal-Directed Design）的“研究”阶段早期，需要了解潜在用户、他们所处的情境、现有的痛点以及他们为了完成任务所采用的辅助手段时。

## 2. 综合指南与最佳实践 (Comprehensive Guide & Best Practices)
- **早期准备**：确定你要访谈的角色（Persona 候选人）。挑选具有代表性的极端用户和普通用户。
- **主从关系（Apprentice-Master Model）**：在访谈中，设计师应当扮演“学徒”，而将用户视为“大师”。让用户教你他们是如何工作的，而不是你像审问者一样提问。
- **情境访谈（Contextual Inquiry）**：必须在用户实际工作的自然环境（Context）中进行。不要把他们请到无菌的会议室。观察他们桌子上的便签纸、物理工具和非正式的交流。
- **捕捉“异常”与“变通（Workarounds）”**：用户往往会对糟糕的系统习以为常，并自己创造解决办法（例如把常用数据抄在纸上贴在屏幕旁边）。这些变通行为是系统缺乏设计的直接证据，也是创新的突破口。
- **开放式问题与避免引导**：
  - 避免问“如果是这个功能，你会用吗？”（用户倾向于礼貌性同意）。
  - 应该问“你昨天遇到这个问题时，具体是怎么解决的？”
  - 追问“为什么”（The 5 Whys），挖掘行为背后的根本目标，区分体验目标、最终目标和人生目标。
- **配对访谈**：最好由两名研究人员进行，一人主导访谈（引导对话），另一人负责详细记录和捕捉非语言信息。

## 3. If/Then 故障排除逻辑 (If/Then Troubleshooting Logic)
- **If** 受访者开始长篇大论地抱怨某个无关的细节或提出具体的解决方案（而不是谈论问题），**Then** 礼貌地承认他们的反馈，并将其拉回到目标上：“这确实是个问题。当你遇到这种情况时，你最终想达成的目的是什么？”
- **If** 受访者在描述操作时与你观察到的实际操作有出入，**Then** 优先相信你的观察，并在合适的时机温和地指出并询问：“我注意到你刚才点击了那里，能告诉我你当时的考虑吗？”
- **If** 受访环境非常嘈杂或用户非常忙碌无法长时间交流，**Then** 将访谈切分为短小的片段（如影子观察 Shadowing），仅在他们任务间隙进行快速简短的探询（Probing）。

## 4. 验证检查表 (Verification Checklists)
- [ ] 访谈是否在用户的自然使用环境中进行？
- [ ] 访谈计划是否以开放式问题为主，没有包含引导性的产品方案暗示？
- [ ] 是否记录了用户在系统之外的辅助工具或流程（如便签、Excel 汇总表）？
- [ ] 是否挖掘出了用户表层任务（Task）背后的根本目标（Goal）？
- [ ] 观察笔记中是否区分了“用户所说的”与“用户实际做的”？
