# 界面设计：移动设备姿态工作流 (Postures for Mobile Devices)

## Prerequisites & Context (前提条件与上下文)
**WHY（为什么使用）**：
在交互设计中，“姿态（Posture）”描述了软件界面与其用户之间的行为契约和关注度水平。对于桌面软件，常见的姿态是独占姿态（Sovereign）或辅助姿态（Transient）。但移动设备（智能手机、平板、穿戴设备）由于其物理形态、使用情境和网络条件的特殊性，具有其独特的交互姿态。明确应用的设计姿态，是决定界面密度、导航深度和交互反馈机制的前提。
**WHEN（何时使用）**：
- 在进行移动端 App、平板 App 或跨端生态系统的交互框架（Interaction Framework）设计时。
- 在决定一个移动应用的层级结构是应该深还是应该平时。
- 在规划信息架构和首屏（Dashboard/Home）重点展示内容时。

## Comprehensive Guide & Best Practices (综合指南与最佳实践)
《About Face》定义了移动设备界面的三种核心姿态，设计师必须在设计前明确产品定位：

### 1. 短暂姿态 (Transient Posture)
- **特征描述**：手机上绝大多数工具类应用和通知。用户在移动、分心或多任务状态下，短暂地查看信息或执行一个快速动作（通常几秒到一两分钟）。
- **设计原则**：
  - **极致直接**：打开即用，直达核心功能，无需深层导航。
  - **大控件高可见度**：控件必须符合“胖手指”标准（触控热区大），且具有极高的视觉对比度（考虑户外强光）。
  - **状态保存**：用户随时可能将手机塞回口袋，应用必须自动保存所有状态并在下次打开时无缝恢复。
- **典型案例**：计算器、天气、相机、语音备忘录、扫码器。

### 2. 卫星姿态 (Satellite Posture)
- **特征描述**：该应用不是一个独立存在的完整系统，而是作为另一个主要设备（通常是桌面端系统或云端平台）的延伸或“卫星”。
- **设计原则**：
  - **聚焦特定场景**：不要试图将桌面端的 100% 功能塞进卫星应用。提取那些在“移动场景”下最具价值的功能（如：查看审批、即时沟通、数据采集、简单阅读）。
  - **无缝的数据同步**：这不仅是技术要求，更是交互要求。必须让用户明确感知到数据已经同步到了主系统。
  - **互补而非替代**：鼓励用户在移动端进行快速处理，将深度编辑或复杂配置留给桌面端。
- **典型案例**：企业协同软件的移动端（如 Jira、Salesforce App）、Photoshop 的手机预览端。

### 3. 独立姿态 (Standalone Posture)
- **特征描述**：通常存在于平板电脑（iPad）或大屏手机中，或者是用户的唯一计算设备。用户会进行长时间、沉浸式的操作，类似于桌面端的独占姿态（Sovereign）。
- **设计原则**：
  - **全功能与深层架构**：提供完整的功能闭环，支持复杂的内容创建或深度消费。
  - **高效的屏幕利用**：利用丰富的屏幕空间进行多窗格布局（如左侧列表、右侧详情），减少不必要的页面跳转。
  - **高级交互手势**：可以引入多点触控（捏合、多指滑动）、拖拽等复杂交互，以提升专家用户的效率。
- **典型案例**：Procreate (iPad)、移动端大型游戏、全功能的视频剪辑 App。

## If/Then Troubleshooting Logic (If/Then 故障排除逻辑)
- **IF** 你的移动应用需要用户连续填写超过 10 个字段的表单或进行精细的文本排版，**THEN** 它的设计违背了“短暂姿态”。应考虑将其简化为基于选项/语音输入的轻量表单，或者将其定位为“卫星姿态”，仅提供查看/审核功能，将复杂输入转移到桌面端。
- **IF** 用户抱怨平板应用（独立姿态）用起来就像是个“放大的手机应用”，**THEN** 说明你没有充分利用屏幕空间。必须重构布局，将手机上的“深层跳转（Drill-down）”结构扁平化，采用分屏（Split-view）或弹出式面板（Popover）在同一界面内展示更多上下文。
- **IF** 你的“卫星姿态”App 每次打开都要重新加载云端数据导致长达数秒的等待，**THEN** 这破坏了移动端的敏捷体验。必须引入本地缓存机制，在打开时先展示缓存数据，并在后台默默更新，同时提供下拉刷新的惯用法。

## Verification Checklists (验证清单)
- [ ] 是否在设计之初就明确了该移动应用属于短暂、卫星还是独立姿态？
- [ ] **短暂姿态验证**：用户是否能在单手操作、注意力涣散的场景下，在 5 秒内完成核心任务？
- [ ] **卫星姿态验证**：移动端功能是否经过了严格裁剪，去除了不需要在移动场景下使用的冗余功能？
- [ ] **独立姿态验证**（平板端）：是否充分利用了屏幕尺寸，避免了大规模留白或无意义的拉伸控件？
- [ ] 无论何种姿态，应用是否都能应对意外中断（来电、切后台、没电），确保用户工作状态绝对不会丢失？
