# 实操类 A/B 卷生成指令模板引擎

本技能封装了生成实操类考查试卷 A/B 卷的核心逻辑。当需要生成 `course_assessment.yaml` 或直接填写 `practice_paper` 时，请**严格按照以下指令模板与规则执行**。

## 核心设计原则
实操类考查试卷设计的红线逻辑：**“核心技能点一致，应用场景（主题）平行区分”**。
- **A 卷与 B 卷难度必须完全对等**。
- **主题必须平行隔离**：例如信息可视化，A 卷可以是“宏观经济数据可视化”，B 卷必须是另一独立应用场景如“公共健康数据可视化”。
- **规范不可更改**：除《创作主题》和《题目基本要求》中的技术栈描述外，其余涉及提交方式、防抄袭、重修规定的条款，须一字不漏地保留。

---

## 🤖 执行模板 (Prompt Template)

请在生成数据时，提取以下【课程变量】并将其注入【输出模板】中：

### 1. 提取课程变量
* `{{年级专业}}`：获取授课对象（例如：2023级 数字媒体艺术专业）
* `{{学年学期}}`：当前执行学期（例如：2025～2026学年度 第 2学期）
* `{{课程名称}}`：课程名称（例如：交互产品开发）
* `{{截止时间}}`：一般设定为期末考试周（例如：2026年6月20日）
* `{{核心技术点}}`：从该课程大纲或实验中提取的关键技术（例如：使用 Python 及大模型 API，前端实现响应式）
* `{{提交文件格式}}`：产出物要求（例如：工程源码 ZIP + 网页导出的 PDF 分析报告）

### 2. 生成 YAML 数据要求

你生成的数据最终将映射到 `PracticePaperVersion` 数据结构：
- `practice_theme`: 对应下方的【一、创作主题】
- `practice_requirements`: 对应下方的【二、题目基本要求】
- `practice_deliverables`: 对应下方的后续条款内容（结果呈现、提交时间、提交途径等）

> ⚠️ 注意：不要改变下方模板中条款的序号和硬性措辞，尤其是关于抄袭、超星学习通提交、旷考等教务规定。

### 3. Agent 数据生成规范与占位符映射

**一、创作主题:**
**[Agent 必须在这里用一段话描述一个具体的设计/开发项目。要求说明应用场景、自由发挥的空间，并强调拓扑结构、数据逻辑或代码规范等细节。A卷和B卷此处的项目必须是不同且工作量平行的]**

**二、题目基本要求:**
（1）**[Agent 必须根据 `{{核心技术点}}` 拆分为 2-3 点专业技能要求]**；
（2）单人的形式制作；
（3）制作过程原创，不得抄袭或者使用网上现成模板/模型；
（4）提交作者自己设计的界面草图、灵感参考图或数据集来源说明。

**三、结果呈现方式：**
文件以“学号+姓名+课程名称”的方式命名，研究报告提供：`{{提交文件格式}}`。

**四、提交时间：**
`{{截止时间}}`前。

**五、提交途径：**
超星学习通。逾期未提交且未提前申请缓考将视为学生旷考/缺考，请知悉。

**六、其他说明：**
（1）`{{截止时间}}`前，逾期未提交未提前缓考申请的，将视为自主放弃本次考核资格，并按旷考、缺考记录。
（2）旷考、缺考或违纪作弊、抄袭（作品中所使用的主素材必须是作者原创，个别素材使用公共素材的，必须注明出处，否则视为作弊、抄袭），该门课程按照总成绩不合格处理，不允许参加重考。
（3）重考、缓考使用的是期末正考未启用过的试题，重缓考学生不得提交过往提交过的作品（含个人或他人/队员作品），否则将作抄袭、作弊处理，成绩为0。
