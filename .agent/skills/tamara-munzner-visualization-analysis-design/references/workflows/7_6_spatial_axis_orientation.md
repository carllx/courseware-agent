# 空间轴方向与布局密度 (Spatial Axis Orientation & Layout Density)

## Prerequisites & Context (前置条件与背景)

在数据可视化设计中，空间是编码数据的最重要资源。如何规划空间轴的方向（如直角坐标系、平行坐标系或径向坐标系）以及如何处理空间的密度分布（如密集布局或空间填充），直接决定了图表的信息承载量、可读性及感知的准确性。

**WHY (为什么重要)**：
空间布局不仅改变图表的视觉形态，更根本地改变了人类对其中数据的感知方式。例如，由于认知机制的限制，基于角度通道的径向布局在准确度上天生弱于直角布局。

**WHEN (何时使用)**：
- 当你需要展示少于或等于两个定量属性，且关注点在趋势与分布时，考虑基础的 **直角坐标布局 (Rectilinear Layouts)**。
- 当处理包含数十个定量属性的高维表格数据，且需寻找相关性、异常值或属性极值时，考虑 **平行布局 (Parallel Layouts)**。
- 当数据具有周期性特征 (Cyclic patterns)，或者关注部分与整体的关系时，考虑 **径向布局 (Radial Layouts)**。
- 当需要在有限屏幕内呈现上万条数据记录（如代码行状态监控）时，考虑 **密集布局 (Dense/Pixel-oriented)** 或 **空间填充式布局 (Space-Filling)**。

## Comprehensive Guide & Best Practices (综合指南与最佳实践)

### 1. 空间轴方向设计 (Spatial Axis Orientation)

#### A. 直角坐标布局 (Rectilinear Layouts)
这是最常见的基础设计空间。数据沿着相互垂直的水平与垂直轴分布。
- **最佳实践**：优先将其作为基准设计。人类对对齐的直线位置通道感知最为精准。由于分离性好，适合承载精确的数量对比与趋势分析任务。

#### B. 平行布局 (Parallel Layouts)
用于处理多维定量属性（如平行坐标系）。每个数据项不再是一个点，而是一条穿过所有平行轴的折线。
- **最佳实践**：
  - **任务匹配**：用于展示属性总览、寻找数据极值、发现异常值以及探索属性间的**相关性**。如果相邻轴呈现强正相关，连线近乎平行；强负相关，则交汇于一点。
  - **缩放限制**：平行布局可横向扩展至数十个属性（受屏幕宽度限制），纵向可容纳数百条数据（Items）。若超过上千条数据，将因严重遮挡导致失效。
  - **交互增强**：必须提供**交互式轴重排**功能。平行坐标系的效用高度依赖于相邻轴之间的视觉关系。建议与其他视图（如散点图）联动使用以降低学习成本。
  - **参考示例**：
    ![平行坐标系与散点图矩阵对比](../../images/376437371ea3a89ac093016d0bc16f06b8f443189ee51471eedabc2d5f35a055.jpg)

#### C. 径向布局 (Radial Layouts)
使用极坐标系，数据通过**角度 (Angle)**和到圆心的**距离**进行分布。
- **最佳实践**：
  - **周期性匹配**：仅在展示具有**周期性或循环性模式**的数据时推荐使用径向布局。对非周期性数据强制使用角度通道容易产生误导。
  - **权重不对称**：因为角度与线性空间的不对等，径向布局暗示了属性间的不对称性。如果需要映射，最重要的属性应映射在扇区 (Sectors)，次要属性映射在环形 (Rings) 上。
  - **饼图与玫瑰图陷阱**：
    - 饼图基于面积和角度感知，准确率远低于使用长度通道的条形图。
    - **规范**：如果要展示总体与部分的占比结构，推荐使用归一化堆叠条形图 (Normalized Stacked Bar Chart)。只有在分类不超过 10 种左右时，才勉强考虑饼图。极区图 (Polar Area Chart / 玫瑰图) 改变了楔形的长度而不是角度，是稍微准确一些的变体。
  - **参考示例**：
    ![条形图与饼图、极区图对比](../../images/66654b314458cda32aa2080b7120bf3605a39b1f7fc0483d5977f76caea61eca.jpg)

### 2. 空间布局密度控制 (Spatial Layout Density)

#### A. 密集布局 (Dense Layouts / Pixel-oriented)
采用微小、高密度的标记（如只有 1 像素高/宽的线段或像素点）来最大化视野内的信息量。
- **最佳实践**：
  - **极简视觉通道**：在此类布局中，标记本身的尺寸和形状丢失，只能依赖**平面位置**和**颜色**通道。
  - **保持空间结构**：在如代码结构可视化（Tarantula系统）中，即使文字无法辨认，也要保留原有的缩进与行长特征，从而形成视觉地标 (Landmarks)。
  - **参考示例**：
    ![密集代码浏览工具 Tarantula](../../images/833ed4675dbfd8e6f228212bec9708f3e4d0e42d8118674250703558ab73e0b6.jpg)

#### B. 空间填充布局 (Space-Filling)
铺满视图内所有可用空间，通常使用面积 (Area) 标记或包含 (Containment) 标记（如矩形树图 Treemap）。
- **最佳实践**：
  - **扩大颜色编码区**：通过牺牲留白 (White space)，最大化每个色块的感知面积，从而提升颜色的视觉显著性。
  - **利用嵌入空间**：更大的单一面积提供了充裕的内置文本标签 (Labels) 的空间。
  - **警惕负面效应**：缺乏留白可能会导致视图拥挤、缺乏重点和视觉平衡感。在图形设计中需谨慎权衡留白的损失。

## If/Then Troubleshooting Logic (故障排查与边缘情况逻辑)

如果用户提出特定的设计需求或遇到视觉传达瓶颈，请执行以下判断逻辑：

- **IF** 任务目标是展示数据不同部分占整体的比例，**THEN**：
  - 检查分类数量。若分类 > 12 种，放弃径向饼图，使用列表式或归一化堆叠条形图。若需精确读取具体比例数据，同样改用归一化堆叠条形图。
- **IF** 数据呈现多属性 (大于 3 个) 且用户试图在直角坐标系叠加三维甚至更多通道，**THEN**：
  - 制止这种行为（三维空间存在严重遮挡与透视畸变问题）。指导用户转用 **平行坐标系 (Parallel Coordinates)** 或 **散点图矩阵 (SPLOM)**。
- **IF** 在平行坐标系中，线条交叉形成一片混沌无法看出趋势，**THEN**：
  - 检查数据集大小。若 Items 超过一千条，发生了严重的遮挡 (Occlusion)。建议用户实施数据聚合 (如层次化平行坐标系)，或者引入基于不透明度 (Opacity) 的透明度叠加渲染。
  - 检查轴顺序。提示用户调整相邻轴以显露特定的相关性特征。
- **IF** 用户对非周期性线性数据要求使用极坐标 / 环形图 (Radial Layout)，**THEN**：
  - 提醒用户角度感知天然不如线性长度感知，且环形布局容易被大脑解读为时间或周期的轮回。建议重构为直角坐标的线性趋势图。
- **IF** 视图上使用了空间填充式布局导致用户迷失，**THEN**：
  - 检查是否因为缺失了留白 (White space) 导致层级不清晰。建议引入微妙的边界线 (Borders)、阴影或层次颜色渐变以提供视觉层级暗示。

## Verification Checklists (验证检查清单)

在输出针对空间轴方向与布局密度的设计方案前，请核对以下项目：

- [ ] **轴方向合理性**：径向布局是否严格约束在具有周期性特征、层级包含结构或强调不对称属性的场景中？
- [ ] **精准度与任务匹配**：若核心任务是高精度的数值比较，是否已经优先提供了使用直角坐标系与长度位置通道的方案（如 Bar Chart）？
- [ ] **高维扩展性**：在涉及多维变量的设计中，若选择平行坐标系，是否考虑了用户重排坐标轴的交互设计？
- [ ] **视觉缩放评估**：在密集布局 (Dense) 中，是否确认仅使用了颜色与平面位置作为有效编码通道（剔除形状和尺寸依赖）？
- [ ] **视觉地标设计**：在无法阅读细节的超密集视图中（如代码热图），是否保留了必要的整体轮廓或宏观结构特征以供定位？
- [ ] **留白与认知负荷**：在空间填充布局中，权衡颜色编码优势与结构清晰度的同时，是否没有引发过度的认知拥挤？
