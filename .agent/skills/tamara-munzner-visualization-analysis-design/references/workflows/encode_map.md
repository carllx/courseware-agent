# 视觉编码映射工作流 (Encode Map Workflow)

## 1. 先决条件与背景 (Prerequisites & Context)

- **目标 (WHY)**：在可视化系统中科学地将数据属性映射到颜色（亮度、饱和度、色相）及其他非空间视觉通道（大小、角度、形状、运动等），以最大程度提升信息传递准确性，避免视觉误导。
- **场景 (WHEN)**：当你需要为图表中的类别数据（Categorical）、顺序数据（Ordered/Sequential/Diverging）或双变量数据（Bivariate）配置视觉通道时。
- **动态理论查询**：本工作流侧重于实操启发式规则，若需深入掌握色彩空间计算或人类视网膜色觉原理，请指示 Agent 运行动态查询脚本：
  - `bash scripts/query_theory.sh "What are opponent color channels and how do they explain color deficiency?"`
  - `bash scripts/query_theory.sh "Why is the L*a*b* space perceptually linear, and why should RGB/HSL be avoided for interpolation?"`

## 2. 综合指南与最佳实践 (Comprehensive Guide & Best Practices)

### 2.1 颜色编码：解耦三大独立通道
在视觉编码设计中，必须将“颜色”拆解为三个独立且特性各异的通道：亮度（Luminance）、饱和度（Saturation）与色相（Hue）。

![](../../images/19e7001ca8c7ddc57580baa2497bca3e60a829dd10b24464cf21322625a39bb2.jpg)

#### 2.1.1 亮度通道 (Luminance) - 用于顺序表达
亮度能够有效传达数据的相对大小与排序。
- **精细边缘识别**：亮度对比度是我们解析细节和清晰边缘的**唯一方式**。纯文本或微小标记必须具备足够的亮度对比。标准建议文本对比度达到 10:1，最低限度为 3:1。
- **辨识度限制**：不要使用超过 2-4 个灰阶用于非连续区域的分类。对比度效应会导致分散图形的亮度极难精确匹配。
- **不可复用性**：一旦使用亮度通道编码了数据属性，就不能再用亮度去实现“高亮”或提供细节结构。

#### 2.1.2 饱和度通道 (Saturation) - 用于顺序表达
饱和度可用于排序，但受图形面积的影响极大。
- **面积效应（Size Interaction）**：
  - **小尺寸标记**（如点图、细线）：极难辨认低饱和度色彩。**必须使用明亮、高饱和度的颜色**确保可见性。
  - **大尺寸区域**（如背景填充）：**必须使用低饱和度颜色（如粉彩）**，以防高饱和度造成的视觉刺眼和疲劳。
- **辨识度限制**：对于分离的小块区域，人类大概只能分辨 3 个不同的饱和度层级。

#### 2.1.3 色相通道 (Hue) - 用于分类表达
色相是除空间位置以外，展示类别和分组数据的最佳通道。
- **天然无序性**：色相不存在人类感知的天然顺序（与亮度和饱和度不同）。**切勿使用不同色相暗示大小或严重程度**，除非借助社会习得的惯例（如绿-黄-红的交通灯顺序）。
- **辨识度限制**：在分离的小块区域中，最多只能使用 6-7 种不同的色相进行有效区分。

### 2.2 色谱设计 (Color Map Construction)

色谱的选择直接取决于数据属性类型：
- **分类色谱 (Categorical)**：纯粹使用色相进行无序分类。
  ![](../../images/4bbba39f14f6afbd785b15718e76953d02f8fd0f9e1ed6e48cfbc3cc4007a17f.jpg)
- **顺序色谱 (Sequential)**：从极小值到极大值，通常配合亮度和饱和度递变。
- **发散色谱 (Diverging)**：拥有明确中心的零点（如正负、温差），向两端发散。
  ![](../../images/d747bf26f3489755b4416aad5fcb55f0a8cbc23fb70412c4ab5525b7adfcba4c.jpg)
- **双变量色谱 (Bivariate)**：同时展现两种属性的复杂矩阵，需结合色相、饱和度、亮度以保证可读。
  ![](../../images/c5ce3aa23c0a6b2e4c6caa66a58cdf6f89e82d01515e2a8b2b76b51da540bfc2.jpg)

*注意：计算机常用的 RGB 空间是感知非线性的，会导致严重的失真。不要在 RGB 空间中插值计算色彩渐变！必须使用感知均匀的空间（如 L*a*b*）。*
*如需深入了解转换计算原理，请运行：* `bash scripts/query_theory.sh "Compare HSL lightness, true luminance, and perceptually linear luminance L*."`

![](../../images/49dbf250b38f901815366b885aabaa53a30193ce15ff46bf938d20d628d5d8b7.jpg)

### 2.3 其他非空间通道与透明度

- **幅度通道 (Magnitude Channels)**：大小 (Size)、角度 (Angle)、曲率 (Curvature)、体积 (Volume)。
- **标识通道 (Identity Channels)**：形状 (Shape)、运动 (Motion，如方向、速率、频率)。
  ![](../../images/cc036d3d76add7fe42a47f82451201c8325ef3abd814470e73a836a9641823c3.jpg)
- **透明度 (Transparency)**：
  - 透明度不能单独使用，必须与其他通道结合。
  - **严禁**与亮度或饱和度通道同时编码不同数据（会产生严重干涉）。
  - 可以与色相搭配使用，但辨别层级**最多仅为 2 级**。
  - 常用于前背景叠加区分或数据的冗余编码（Redundant Encoding）。

## 3. 条件排障逻辑 (If/Then Troubleshooting Logic)

*   **IF** 文本、标签或细小线条在图表中模糊难辨，或难以阅读...
    *   **THEN** 立即检查**亮度对比度**（Luminance Contrast）。单纯的色相或饱和度差异无法生成清晰的边缘，必须确保文本与其背景之间的亮度对比至少为 3:1。
*   **IF** 你需要给分散的散点或线段进行排序/分级，且分级数 > 4...
    *   **THEN** 不要使用亮度和饱和度。分散图元的亮度/饱和度分别只能支撑不到 4 个或 3 个等级。此时应该考虑切换为其他视觉通道（如大小或空间位置）。
*   **IF** 散点图或折线图使用了很低饱和度的粉彩色系...
    *   **THEN** 修正配色方案！小面积区域很难识别低饱和度颜色。将小面积标记更改为**高饱和且明亮**的颜色。
*   **IF** 图表的背景色或大面积填充块（如地图多边形）使用了极高饱和度的颜色...
    *   **THEN** 立即将其调为低饱和度颜色。大块的高饱和纯色会带来强烈的视觉负担。
*   **IF** 发现透明度的变化使用户无法分辨图形本身的固有颜色...
    *   **THEN** 停止在叠加层中使用多梯度的透明度。透明度仅保留 2 级状态，或确保叠加层的颜色编码恒定。

## 4. 验证清单 (Verification Checklists)

- [ ] **对比度合规**：所有需要清晰边缘的图形元素（特别是文字信息），是否均具备至少 3:1 的亮度对比度？
- [ ] **色觉障碍适配**：是否考虑到 8% 的男性人群患有红-绿色觉缺陷（如 Deuteranopia 或 Protanopia）？方案中是否避免了仅依赖红绿对比的设计，而辅以亮度或其他维度的区分？
- [ ] **视觉映射匹配**：是否遵循了“数值/顺序型数据对应亮度或饱和度”、“分类数据对应色相”的基本规则？
- [ ] **避免色相误导**：是否存在用不同色相暗示数据大小导致误导的风险？
- [ ] **颜色插值正确性**：生成的连续色谱是否是在感知均匀色彩空间（L*a*b*）中进行插值的？（确认未直接使用 RGB 空间）
- [ ] **面积补偿适配**：颜色是否根据图元的面积大小进行了饱和度的合理调优（大面积低饱和、小面积高饱和）？
- [ ] **透明度约束**：图表中的透明度通道设计是否没有对亮度和饱和度通道的辨识造成破坏性干扰？
