## 理论前置准备 (Theory Prerequisites)

在开始实战之前，请快速回顾以下核心概念：
1. **Munzner What/Why 框架**：从“数据是什么（What）”和“为什么要做可视化（Why）”出发，而不是一上来就调样式。
2. **属性分类壁垒**：
   - **Categorical (分类)**：代表无序的类别标签，不支持大小比较与数学运算（如省份、学号、区划代码）。
   - **Ordinal (顺序)**：代表有严格先后或高低顺序的等级，支持排序，但不支持精确加减（如灾害等级、年份）。
   - **Quantitative (定量)**：代表真正的量化数值，支持无差别的算术运算（如受灾人口、经济损失）。
3. **Tidy Data 三原则 (Wickham)**：
   - 每个变量占一列（Columns as Variables）。
   - 每个观测实体占一行（Rows as Observations）。
   - 每种类型观测单元构成一张表（Tables as Units）。

## 验证站 1：灾害数据基因初探 (DS1 - 10分钟，教师演示)

### 操作目标
见证 AI 对“披着数字外衣的分类属性（区划代码）”的经典类型误判，学会如何通过“语义纠偏”夺回数据解释权。

### 演示步骤
1. 教师在 VSCode 中双击打开 [disaster_sample.csv](file:///Users/yamlam/Downloads/2025-2026-2 课程/信息可视化/weeks/W03_Data_Literacy/public/practice/disaster_sample.csv)，展示原始数据的文本形态。
2. 打开 VSCode 的 AI Agent 侧边栏，向 AI 发送以下诊断 Prompt：
   ```text
   你是一个资深的数据可视化架构师，正在指导 DMA (数字媒体艺术) 大二学生进行数据可视化。请分析当前打开的 disaster_sample.csv，诊断每一列在 Munzner 属性分类体系中属于哪种类型（Categorical, Ordinal, 还是 Quantitative）？请直接指出表格中隐藏的、可能导致可视化渲染引擎报错的类型混淆“认知陷阱”。
   ```
3. **观察盲区**：AI Agent 通常会因为 `区划代码`（440000等）和 `年份`（2021等）是纯数字，而冷酷地将其分类为 `Quantitative`（定量/数值），甚至会建议对它们进行求和。
4. **教师现场纠偏**：向 AI 发送以下语义修正指令，逼迫其提纯逻辑：
   ```text
   纠正：虽然‘区划代码’是由数字组成的，但代表的是不可求和、不可比较大小的特定省级行政区域，它属于 Categorical（分类属性）。年份代表年份标记，属于 Ordinal（顺序属性）。请重新生成修正后的数据属性诊断表。
   ```
5. **核心结论**：在没有人类先验的业务语义输入前，机器对属性类型的分类是完全死板的。程序员和设计者必须牢牢掌控“数据解释权”。

## 验证站 2：特征分流与分类判决 (DS2 - 20分钟，学生分组)

### 操作目标
学生分组协作，在 Excel 中审视原始表格，识破数据类型的算术陷阱，并进行格式隔离。

### 实战步骤
1. **打开并审视表格 (5min)**：在 Excel 中打开周次级数据 [disaster_sample.xlsx](file:///Users/yamlam/Downloads/2025-2026-2 课程/信息可视化/weeks/W03_Data_Literacy/public/practice/disaster_sample.xlsx)，定位到 Sheet1【宽表(原始)】。
2. **AI 辅助评估 (5min)**：在 VSCode AI Agent 插件中输入以下指令，辅助评估属性类型：
   ```text
   请分析“序号、省份、区划代码、灾害等级、以及包含 2021-2023受灾人口/经济损失”的表头。根据 Munzner 属性分类体系，它们分别属于什么类型？如果是数值分类，它们是否支持求和、求平均等操作？
   ```
3. **识破认知陷阱 (5min)**：
   - 检查 AI 是否能够成功分析出嵌入表头中的“2021-2023年”实际上代表着**年份**这一隐性“顺序（Ordinal）维度标签”，而不是被直接当作单纯的度量指标一部分。
   - 分组讨论：为什么不能对 `区划代码` 做加法？（因为 440000 加上 330000 不等于任何有实际意义的地理单元）。
   - 为什么类似 `2021年受灾人口(万人)` 这样把年份数字（时间维度）和指标（数值变量）混写在列头里的设计会违背 Tidy Data 的“变量独立成列”原则？
4. **Excel 格式隔离实操 (5min)**：
   - 在 Excel 中，选中【区划代码】整列（C列），右键选择“设置单元格格式”，将其强制修改为**“文本”**格式，避免在数据导入时被默认识别为数值。
   - 分组在草稿纸上设计：如果要把这个列头中混杂了“年份 + 指标”的多维宽表拆解成最标准的 Tidy Data 长表，应该设立哪几个“属性列”作为主键（Key），哪些作为值（Value）？
5. **成果提交**：将标注了各列属性类型、完成格式转换的 Excel 界面拍照或截图，准备提交。

## 验证站 3：混沌表重组极刑突围 (DS3 - 25分钟，学生实操)

### 操作目标
在不编写 Python 或 NodeJS 代码的情况下，利用“三层结构化 Prompt”命令 VSCode AI Agent 原地重写 CSV 文件，完成宽表转长表的 Tidy 规范化。

### 实战步骤
1. **起草结构化 Prompt (8min)**：
   学生新建一个临时的文本文件，参考以下**【三段式金字塔 Prompt 模板】**，根据我们的 `disaster_sample.csv` 补充细节。
   
   > #### 📝 零代码宽转长重组 Prompt 模板
   > ```text
   > # Context (输入语境)
   > 当前打开的 CSV 文件是一份非标准的自然灾害宽表。顶部含有“2021-2023年自然灾害表”等大标题和多行空行，尾部有“注1、注2”等噪声备注。表格内部第10行还包含了一行“全国总计”行。多列数据平铺了 2021年、2022年、2023年两个不同指标（受灾人口和直接经济损失）的混合属性。
   > 
   > # Target Shape (目标骨架)
   > 请执行 Pivot Longer（宽转长）操作，将其重构为标准的 Tidy Data 长表结构。重组后的长表必须包含且仅包含以下 6 列，并以这 6 列作为首行表头：
   > 省份,区划代码,灾害等级,年份,受灾人口(万人),直接经济损失(亿元)
   > 
   > # Constraints (核心约束)
   > 1. 必须彻底剔除首部合并大标题、空行、尾部备注噪声。
   > 2. 必须剔除“全国总计”这一行（因为它与省级的观测粒度不一致，属于聚合行反模式）。
   > 3. 清洗并对齐每个省份（广东省、浙江省、四川省、甘肃省、辽宁省）在 2021、2022、2023 年的所有观测值。
   > 4. 【极重要红线】：无需编写任何 Python、Pandas 或 JavaScript 代码，请直接利用你的文本处理能力，在编辑器中将当前打开的灾害数据 CSV 原地重写为符合上述 6 列长表骨架的纯 CSV 文本。用半角逗号严格分隔，确保数据无失真，不要截断任何数据。
   > ```

2. **另存副本与 AI 原地重构 (7min)**：
   - 在 VSCode 中打开原始的 [disaster_sample.csv](file:///Users/yamlam/Downloads/2025-2026-2 课程/信息可视化/weeks/W03_Data_Literacy/public/practice/disaster_sample.csv)。
   - **【核心防丢保护】**：在编辑任何数据之前，在 VSCode 中点击菜单 `文件 -> 另存为` (Save As)，将该文件另存为 `tidy_disaster.csv`。
   - 保持在新建的 `tidy_disaster.csv` 文件编辑状态下，唤醒内置 AI Agent 面板，复制上面的完整 Prompt 发送给 Agent，要求其在当前 CSV 中**原地改写（Refactor / Edit）**。
3. **数据完整性校验 (5min)**：
   - 仔细检查改写后的 `tidy_disaster.csv`。
   - 重点审查 3 大漏洞：首尾噪声是否除尽？“全国总计”是否已消失？5个省份 × 3个年份 = 15 行数据是否行行对齐，有无数值错位？
4. **保存交付 (5min)**：
   - 校验无误后直接点击保存 (Save)。此时，我们不仅得到了干净的 `tidy_disaster.csv`，也完美保留了最原始的 `disaster_sample.csv`，以便下一步做对照实验！

### 操作目标
将清洗前后的数据分别导入 RAWGraphs 进行可视化绑定，通过“对照实验”直观体悟 Tidy 长表对渲染引擎的终极价值。

### 实战步骤
1. **反面对照组实验 (5min)**：
   - 访问网页端 [app.rawgraphs.io](https://app.rawgraphs.io/)。
   - 拖入原始的混沌宽表 `disaster_sample.csv`。
   - **观察结果**：RAWGraphs 会因为前几行非标标题和噪声空行产生解析错位，生成大量杂乱的空白列，且由于“2021受灾人口”、“2022直接经济损失”被横向判定为 6 个独立的平行列，导致你在配置面板中根本找不到【时间/年份】这个可以拖拽的统一 X 轴维度，多系列折线图根本无法绘制。即使你尝试跳过前几行，也依然无法跨越宽表物理骨架带来的渲染障碍。
2. **正面标准组实验 (10min)**：
   - 刷新 RAWGraphs 页面。
   - 拖入我们在验证站 3 中历经千辛万苦清洗生成的 `tidy_disaster.csv`。
   - **观察秒级绑定**：系统绿色通道亮起，完美识别 6 列属性类型。
   - 在图表库中选择 **【Line Chart (折线图)】**。
   - **执行视觉通道拖拽绑定**：
     - **X Axis** $\leftarrow$ 将【年份】拖入
     - **Y Axis** $\leftarrow$ 将【受灾人口(万人)】拖入
     - **Color** $\leftarrow$ 将【省份】拖入

3. **多维映射探索 (5min)**：
   - 尝试将 Y 轴更换为【直接经济损失(亿元)】，观察经济损失和受灾人口是否呈现正相关性。
   - 尝试选用 **【Alluvial Diagram (冲积图)】**，将【省份】、【灾害等级】、【年份】串联绑定，观察灾害流转在时空维度上的层级律动。
4. **成果截图**：保存折线图与冲积图的可视化成果图，并截取对应的通道拖拽配置面板。

## 🛠 AI 误判与避坑速查表 (LLM Pitfall Lookup Table)

在操作 VSCode AI Agent 进行数据清洗时，如遇到以下“AI 降智”行为，请使用**“一句话纠偏指令”**现场训诫：

| 异常表现 | 底层诱因 | 现场一句话纠偏指令 |
| :--- | :--- | :--- |
| **数据被截断** | CSV 字符数较多，AI 偷懒输出 `...` 占位 | “不要截断！请输出完整的 15 行 Tidy 数据，确保从广东省到辽宁省无一遗漏！” |
| **试图输出 Python 代码** | AI 习惯了用 pandas 解决重组，忽视了机房环境约束 | “机房电脑没有 Python 解释器，不要给我任何代码！请利用你自己的文本处理能力原地改写 CSV！” |
| **将区划代码进行相加** | 只要长得像数字，机器默认就想进行求和求平均 | “警告：区划代码是省级地域的 Categorical（分类属性），不是数值！不允许对其进行相加或计算！” |
| **年份插值丢失** | 宽表转长表时，将年份和指标对齐错位 | “年份是 Ordinal 键，每个省份在 2021、2022、2023 必须各有且仅有 1 行记录，重新检查对齐！” |

## 📊 RAWGraphs 排障指南 (Troubleshooting Table)

| 报错现象 / 异常 | 可能原因 | 解决办法 |
| :--- | :--- | :--- |
| **"Error parsing data: columns mismatch..."** | 原始表中的首部标题行或空行导致列数不匹配 | 在 RAWGraphs 上传界面中勾选“Skip first [X] rows”，或者直接使用清洗干净的 `tidy_disaster.csv`。 |
| **折线图的 X 轴散乱，无法形成连续时间轴** | 年份被识别为 Categorical（分类），折线图无法建立定量/顺序刻度 | 在 RAWGraphs 数据类型解析区（拖拽面板上方），点击年份上方的图标，将其类型手动强制修改为 **Date** 或 **Number**。 |
| **找不到 Y 轴的拖拽目标** | 受灾人口或经济损失包含“万人”或“(估)”等文字，导致被误判为 Categorical | 检查你的 CSV 数据是否包含非数字字符。如有，在 VSCode 中命令 AI 剔除所有汉字后缀，仅保留纯数字。 |
| **折线杂乱扭曲，拧成麻花** | 没有指定 Color 区分，多省数据被挤在了一条折线上 | 将【省份】拖入 **Color** 槽位，或者将【省份】拖入 **Lines (多条线)** 槽位，使各省线条独立分离。 |
