## Module 4: 存在即被看见 (30 分钟 + 30 分钟 ACTIVITY)

> [!NOTE]

经过了排错的洗礼和封装的蜕变，你们的项目现在应该已经具备了技术上的健壮性和视觉上的专业感。但是，我必须向你们宣告一个也许令人不安的事实：这一切目前仍然只存在于你们自己的笔记本电脑里面。你的队友看不到最新版本，你的导师无法在办公室预览进度，你甚至无法在手机上给家人展示你这个学期最引以为傲的成果。这件作品此刻就像一封写好了但从未寄出的信，它承载了所有的心血和才华，但依然是一封内心独白，从未触达任何一位读者。

> [PHILOSOPHY]
> **存在主义的数字映射**
> 法国哲学家萨特说过，"存在先于本质"。但在数字世界里，这个命题需要一个前提条件——你的最终产出必须首先"存在"于一个可被他人访问的公共空间中。一个锁在你 C 盘某个子文件夹深处的 `index.html`，在互联网的视角下，和一个从未被创造出来的文件没有任何区别。它对这个世界的影响力为零。

> [STORY TIME]
> **Exp7: 如果一棵树倒在无人的森林**
> 哲学史上有一个著名的思想实验：如果一棵树在没有人的森林里倒下，它发出的声音算不算存在？这个问题在数字创作领域有一个更加现实的版本——如果你做了一个精美绝伦的数据可视化作品，但全世界只有你自己能看到它，这个作品算不算完成？答案是：不算。对于数字媒体艺术专业的你们来说，"部署"不是一个可选的附加步骤，它是作品从"半成品"变成"成品"的**存在性分水岭**。这个交互网页不上线，等于它不存在。

> *   **Text**: "静态站点 vs 动态站点"

好消息是，你们本学期的所有项目都是纯前端静态页面。什么是静态站点？它就像一本数字出版物：由纯粹的 HTML 骨架、CSS 样式、JavaScript 逻辑和 CSV 或 JSON 数据文件组成的一个完整文件包。浏览器打开这个文件包后，所有的页面渲染和交互逻辑都在用户的电脑或手机上完成。它不需要任何后端服务器来运行。这意味着你们可以使用完全免费的托管平台来发布作品，零成本，零运维。

我们先来看第一个部署方案，GitHub Pages。这是全球开发者社区中最经典、最广泛使用的静态站点托管方案。
第一步，在 GitHub 上创建一个公开仓库。
第二步，将你的整个项目文件夹推送到 main 分支。确保 `index.html` 在仓库的根目录，不要嵌套在子文件夹里。
第三步，进入仓库的 Settings 页面，在 Pages 选项中，将 Source 设置为 main 分支的根目录。
第四步，等待一到两分钟自动构建。
第五步，访问你的在线链接。

> *   **Text**: "Vercel：一键部署的现代替代方案"

第二个方案是 Vercel。如果你觉得 GitHub Pages 的配置流程还是太繁琐，Vercel 提供了一个更加无脑的现代部署体验。它的操作简单到只有三步：用你的 GitHub 账号一键登录 Vercel 官网，选择 Import Project，指向你的 GitHub 仓库。Vercel 会自动检测你的项目，并在几十秒内完成构建。

Vercel 的三大优势：
第一，自动 HTTPS 加密。为交互页面提供专业的安全锁。
第二，全球 CDN。用户无论在哪个半球都能秒开。
第三，CI/CD（持续部署）。每次 `git push`，几十秒后线上项目就自动更新了。

但在你点下那个 Deploy 按钮之前，请严格走一遍这份部署前自检清单。六项，每一项都不可跳过。
第一，所有资源路径必须是相对路径。绝对不能出现 `file:///C:/Users/` 这样的本地绝对路径。
第二，`index.html` 文件必须在仓库的根目录下。
第三，你的 CSV 和 JSON 数据文件必须和代码一起上传到仓库里。
第四，在部署前先用 `npx serve .` 在本地启动一个临时服务器来预览。
第五，打开 Console 检查是否有 404 或 CORS 错误。
第六，用手机打开本地预览链接做一次基本的可读性测试。

> [CASE STUDY]
> **Exp8: 部署翻车三部曲**
> 每个学期最后我都会目睹的三大灾难：学生甲，本地路径写死，上线全白屏；学生乙，忘记传 `lib` 库，图表完全不渲染；学生丙，文件名带中文和空格，路径解析崩溃。每一个只用三十秒能修好的错误，到了 Deadline 前都会变成三十小时的崩溃。

部署不仅是技术流程，更是一次公开的知识产权宣告。你的 `README.md` 是别人了解你的窗口。必须包含：

2. 数据来源声明（必须标注授权！）。
3. 技术栈。
4. 团队分工。

> **任务说明**：
> 这 30 分钟是你们项目的"发射窗口"。请各团队执行以下完整流程：
> 1. **强制自检**：确认项目结构符合 Module 4 的**六项部署前自检清单**（相对路径、根目录入口、数据就位）。
> 2. **代码提交**：使用 `git push` 将最终版本的代码推送到 GitHub 的 main 分支。
> 3. **云端部署（推荐 Vercel）**：
>    - 登录 Vercel，选择 Import GitHub Project
>    - 保持默认配置，点击 Deploy
>    - 或者选择 GitHub Pages 方式配置 Pages 源
> 4. **跨端验证**：获取公网 URL 后，必须在**至少两台不同的设备（如你的手机和队友的电脑）**上打开并测试交互，防止本地缓存的蒙蔽。
> 5. **完善文档**：在项目仓库根目录补充或修改 `README.md`，添加项目在线 URL、技术栈说明和团队贡献表。
> 6. **最终归档**：将你们的在线 URL 填入班级共享协作文档。
> 
> **教师巡场重点**：重点捕捉并解决同学部署中的 404/白屏问题（多为路径大小写错误或混合内容 HTTP/HTTPS 拦截）。
