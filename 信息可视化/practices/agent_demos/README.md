# Agent 教学演示 (Demos) 撰写与设计指南

本文档汇总了《信息可视化》课程中所有 Agent 教学演示（Demos）的设计经验、目录规范以及提示词（Prompt）撰写规则。后续新增任何实验或项目演示时，请严格遵守本指南，以确保教学体验的一致性与科学性。

## 1. 核心设计理念

面向非计算机专业（如数字媒体艺术设计）的学生，我们的演示设计必须遵循以下核心原则：
- **认知减负**：绝对避免在给学生的指令中暴露底层技术细节（如 CDN 引入方式、DOM 挂载、`d3.transition` 生命周期等），而是将所有的技术约束包装为**自然语言的视觉与动效描述**。
- **“大白话”优先**：使用极简的日常语言下达指令，让学生明白“只需描述你想要什么样子”，大模型就能帮你写代码。
- **理论渗透**：虽然弱化了代码细节，但**必须保留并强化教授的可视化核心理论**。在进阶演示中，要求大模型使用 Tamara Munzner 的理论（Task Abstraction, Marks & Channels, Effectiveness）来证明其图表设计的合理性。

## 2. 文件夹结构规范

每个 Demo 都必须是一个独立的、可直接发给学生的闭环项目包。标准的目录结构如下：

```text
agent_demos/<项目名称>/
├── data/
│   └── xxx.csv                     <-- 必须是清洗后、可直接读取的结构化数据
├── agent_instruction.md / GUIDE.md <-- 包含“大白话指令”的演示话术本
└── index.html (可选)                <-- 预留好 <div id="chart"> 的空脚手架（可选，视难度而定）
```

## 3. 提示词 (Prompt) 撰写规则

在撰写 `agent_instruction.md` 或 `GUIDE.md` 时，发送给 Agent 的提示词应遵循以下经验：

### 3.1 把“技术语言”翻译成“视觉要求”
以往我们为了防错，会在 Prompt 中写大量 API 限制，现在统一改为描述最终画面：
- ❌ `使用 d3.transition() 控制 Enter/Update/Exit 同步` ➡️ ✅ `动画过渡必须平滑，条形图变动要有流畅的上下移动穿插（类似赛跑）。`
- ❌ `使用 Plot.dodgeY 处理碰撞` ➡️ ✅ `使用圆形图标表示数据点，请自动错开防止重叠。`
- ❌ `preserveAspectRatio: "xMidYMin slice" 和 r: 20` ➡️ ✅ `把图片裁剪为圆形小头像，保持比例不要拉伸人脸。`

### 3.2 跨域 (CORS) 报错的统一口径
所有涉及读取本地 `data/` 目录的 Demo，都会遇到 CORS 跨域拦截问题。在指南中向学生解释时，强制使用以下记忆点口径：
- **`file:///` (直接双击)** = 浏览器的**“防盗隔离模式”**，网页被关禁闭，严禁读取旁边的文件。
- **Live Server (`127.0.0.1`)** = 在电脑上开了一个**“本地服务台”**，有了正规前台交接数据，浏览器安全放行。

## 4. 标准化的演示流派 (Workflows)

对于每一个 Demo，我们建议在教学时拆分为两条路径编写 Prompt，以便老师在课上分层次演示：

### 路径一：效率流（一键复刻）
**目的**：向学生展示 Agent 的执行力。
**指令模板**：
> “请读取 `data/xxx.csv`，使用 D3.js（或 Observable Plot）为我生成一个 **[图表名称]**。X轴表示[维度]，Y轴表示[维度]。视觉要求是：[大白话描述排版和动效]。”

### 路径二：启发流（与大模型结对探索）
**目的**：向学生展示如何与 Agent 沟通，培养“分析设计”思维。
**分步指令模板**：
1. **先找洞察**：“请读取这份数据，你能想到哪些有意思的分析视角（Task Abstraction）？请给我 3 个图表方案。”
2. **定案并强制使用理论**：“我选方案 X。在写代码前，请用 Tamara Munzner 的理论向我解释你的设计：你的 Marks（标记）是什么？用了哪些 Channels（通道）？依据有效性（Effectiveness）原则，为什么这么选？解释完后再输出单文件 HTML 代码。”

---
*注：本指南基于 `d3-bar-chart-race` 和 `plot-image-dodge` 的重构经验总结得出。后续 Agent 在接手新 Demo 时，请务必将其作为首要对齐标准。*
