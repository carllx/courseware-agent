# W03_08_Tidy_Data与数据重塑

## 知识来源与定位
- 理论基础：Hadley Wickham (2014) "Tidy Data"
- 实践方法：AI 辅助数据建模与 Prompt 工程
- 与教材的映射：本书（Munzner）Chapter 3 中 **Derive（派生）** 操作在真实数据工程中的具体落地。

## 核心知识提取

### 1. 为什么需要 Tidy Data？
真实世界的数据往往是为了"人类方便阅读"或"方便录入"而设计的（例如：带有复杂合并单元格、多层表头的 Excel 报表）。但这种结构对于算法、编程语言和可视化工具来说是无法解析的灾难。
数据清洗的核心不是写代码的苦工，而是**语义理解的过程**。你必须先搞清楚"到底什么是一个变量、什么是一个观测"，才能决定数据的形状。

### 2. Tidy Data 三原则 (Wickham, 2014)
Hadley Wickham 在其开创性论文中定义了"整洁数据"（Tidy Data）的绝对标准：
1. **每个变量独立成一列 (Each variable forms a column)**。
2. **每个观测值独立成一行 (Each observation forms a row)**。
3. **每种观测单元独立成一表 (Each type of observational unit forms a table)**。

### 3. 宽数据 vs 长数据 (Wide vs Long)
- **宽数据 (Wide Data)**：
  - **特征**：人类友好，适合视觉阅读扫描。常包含合并单元格、多层表头、数据列名其实是值（如"2019年"、"2020年"）。
  - **缺陷**：机器/AI 难以解析，因为属性（Attributes）和条目（Items）被混淆在了一起。
- **长数据 (Long/Tidy Data)**：
  - **特征**：机器友好，线性、无歧义。每一行都是一个独立的观测事件，列名是纯粹的变量名。
  - **优势**：可以直接导入 ECharts、Tableau 等可视化工具进行维度拆解。

### 4. 五种常见脏数据形态 (Anti-patterns)
| 脏数据问题 | 表现示例 | 重塑/修复方向 |
|:---|:---|:---|
| **1. 列头是值而非变量名** | 列名为 "2018", "2019", "2020"，里面填着 GDP 数据 | 宽转长（Melt / Pivot Longer）。新建 Year 列和 GDP 列。 |
| **2. 多个变量挤在一列** | 一列写着 "北京-海淀"，混合了城市和行政区 | 拆分列（Separate）。拆为 City 列和 District 列。 |
| **3. 变量同时存于行和列** | 复杂的问卷交叉表或带有总计行的 Excel 表 | 结构重塑（Reshape），通常需要先抹平表头，再过滤掉非数据行。 |
| **4. 多种观测单元混在一表** | 订单明细表里不仅有商品信息，还冗余了客户的年龄和性别 | 拆表并规范化（Normalize）。分为订单表和客户表，通过 ID 关联。 |
| **5. 同一观测单元分散多表** | 按照月份分成 12 个 Excel 文件（如"1月销售.csv", "2月..."） | 纵向合并（Bind / Concat）。 |

### 5. AI 辅助数据清洗工作流 (AI-Assisted Workflow)
对于 DMA 学生（非专业程序员），不需要手写复杂的 Python `pandas.melt()` 代码，而是作为**数据架构师**，用自然语言指挥 AI（如 ChatGPT/Claude）完成数据重塑。

#### 5.1 结构化 Prompt 三要素
1. **输入描述 (Input Context)**：精确描述原始数据的形状、格式和现有问题。
   - *示例："这是一份 2010-2020 年含有合并单元格的人口宽表，列名是年份。"*
2. **目标形状 (Target Shape)**：用领域词汇（Tidy Data 术语）描述期望的结构。
   - *示例："请将其展平为 CSV 长数据格式（Tidy Data），要求只有 Year, Region, Population 三列。"*
3. **约束条件 (Constraints)**：明确过滤规则和数据质量要求。
   - *示例："去除所有含有 '总计' 或 'Summary' 字段的行，只保留真实的量化观测数据。"*

#### 5.2 迭代式对话策略 (Iterative Refinement)
- **轮次 1**：描述数据现状 + 给出目标结构 → AI 输出初步的转换代码或转换后的数据。
- **轮次 2**：检查异常值（如空值、格式错乱） + 补充约束 → AI 修正脚本。
- **轮次 3**：验证 Tidy 格式 → 导入可视化工具检验。
