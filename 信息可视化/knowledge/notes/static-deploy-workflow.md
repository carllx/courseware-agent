# 全链路静态部署策略

## 认知目标
学生能将本地的 HTML+CSS+JS+数据文件包部署到公网，理解静态站点托管的核心原理，并掌握至少一种零成本发布路径。

## 核心概念

### 为什么必须部署？
- **作品不上线 = 作品不存在**：数字媒体艺术的最终归宿是被"看见"，本地文件夹无法被分享和引用。
- 部署是"最后一公里"，但绝大多数设计学生在此止步 → 作品集只有截图，没有活的交互链接。
- 上线后可获得永久 URL，嵌入简历/作品集/社交媒体。

### 静态站点 vs 动态站点
| 维度 | 静态站点 | 动态站点 |
|:---|:---|:---|
| 构成 | 纯 HTML/CSS/JS + 数据文件 | 需要后端服务器（Node/Python/PHP） |
| 托管成本 | 免费（GitHub Pages / Vercel / Netlify） | 需要付费云服务器 |
| 适用场景 | 数据可视化单页/Scrollytelling 长页 | 用户登录/数据库读写/实时数据 |
| 我们的项目 | ✅ 完全适用 | ❌ 不需要 |

> 本课程所有项目均为**纯前端静态页面**：HTML 骨架 + CSS 样式 + JS 逻辑 + CSV/JSON 数据。无需任何后端。

### GitHub Pages 部署流程
1. **创建 GitHub 仓库**（Public）
2. **上传文件**：将整个项目文件夹推送到 `main` 分支
3. **Settings → Pages**：选择 Source = `main` / root
4. **等待 1-2 分钟**：GitHub 自动构建并生成 `https://<username>.github.io/<repo>/`
5. **验证**：检查首页加载、数据文件路径是否正确

**常见陷阱**：
- 文件路径使用 **相对路径**，不要用 `C:\Users\...` 这样的绝对路径
- `index.html` 必须在根目录，不能嵌套在子文件夹里
- CSV/JSON 数据文件必须一起上传，不能遗漏
- 大小写敏感：`Data.csv` ≠ `data.csv`

### Vercel 部署流程（替代方案）
1. **vercel.com** 注册（GitHub 账号一键登录）
2. **Import Project** → 选择 GitHub 仓库
3. **自动检测**：Vercel 识别为静态站点并部署
4. **自定义域名**：可绑定自有域名（可选）

**优势**：自动 HTTPS、全球 CDN、每次 push 自动重新部署（CI/CD）。

### 部署前自检清单
- [ ] 所有资源路径为相对路径？
- [ ] `index.html` 在根目录？
- [ ] 数据文件 (CSV/JSON) 已包含在仓库中？
- [ ] 在本地用 `npx serve .` 或 VS Code Live Server 预览无报错？
- [ ] 控制台无 404/CORS 错误？
- [ ] 移动端基本可读？（非强制，但加分）

## 反面案例
- 学生A 本地路径写死 `file:///C:/Users/xxx/data.csv` → 部署后数据加载全部失败
- 学生B 忘记上传 `lib/` 文件夹 → D3.js 引用 404，图表完全不渲染
- 学生C 文件名含中文空格 → GitHub Pages 路径解析失败

## 教学价值
现代数据创作者的基本素养不是"写代码"，而是"让作品活在公网上"。部署是从"学生作业"到"专业作品"的分水岭。
