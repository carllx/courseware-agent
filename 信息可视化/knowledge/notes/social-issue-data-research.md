# 社会议题数据调研方法论 (Social Issue Data Research Methodology)

> **来源**: 《信息可视化设计》第六章 社会焦点整合信息设计 + 课程整合

## 核心认知目标

掌握面向社会/文化/生态议题的数据调研策略，能够在公开数据平台定位数据源、评估数据可用性，并利用 AI 辅助快速完成数据预处理。

## 社会焦点选题三原则

### 1. 公共价值优先
- 项目不应仅仅是个人日记本式的数据叙事
- 应涉及：文化遗产保护、生态危机、公共卫生、弱势群体关怀、科技科普
- **DMA 专业定位**: 利用前沿技术挖掘不可见的社会裂痕，呈现人文关怀

### 2. 数据可获取性
- 有热情但无数据 = 空中楼阁
- 必须在项目立项阶段即验证硬核数据源是否存在
- **反面案例**: "我想做全球变暖的可视化"但没有具体的数据集 → 最终只能用虚构数据

### 3. 认知边界控制
- 宏大议题必须收窄到可操作的子问题
- 例："十四五核心技术" → 聚焦"植物生物育种"或"深海探测"的具体切面

## 公开数据平台清单

| 平台 | 数据类型 | 适用场景 |
|:---|:---|:---|
| Kaggle | 多领域结构化数据集 | 快速原型验证、机器学习预处理 |
| 联合国数据库 (data.un.org) | 全球发展指标 | SDGs、人口、健康、教育 |
| 世界银行 (data.worldbank.org) | 经济/社会/环境指标 | 跨国比较、时序趋势 |
| 中国政府开放数据 (data.gov.cn) | 国内政策/经济/环境 | 国内议题调研 |
| NASA Open Data | 地球科学/气象/天文 | 生态环境、气候变化 |
| WHO Data | 全球卫生统计 | 公共卫生议题 |
| GitHub Awesome Public Datasets | 各类汇总索引 | 快速发现新数据源 |

## AI 辅助数据预处理工作流

### 阶段一：数据探索
1. 下载原始 CSV/JSON
2. 丢给 AI："阅读这个数据集，告诉我有几列、几行、数据类型分布、缺失值比例"
3. AI 输出数据画像 → 判断是否匹配项目需求

### 阶段二：Tidy 化
1. 定义目标变量（Key）和度量值（Value）
2. Prompt: "将宽表转长表，保留 [国家, 年份] 为 Key，[指标名, 指标值] 为 Value"
3. 处理缺失值、异常值、编码不一致

### 阶段三：子集提取
1. 按项目聚焦点过滤数据
2. 生成适合目标图表类型的 JSON 子集
3. 验证：数据量是否在前端渲染能力范围内

## "十四五"核心技术案例拆解

教材第六章展示了 11 组学生作品，涵盖：
- 生物育种（植物基因编辑交互网站）
- 免疫与疫苗（3D 人体免疫系统科普）
- 火星探测（着陆过程数据可视化）
- 深海探测（载人潜水器对比信息图）
- 海水稻种植（IP 形象 + Processing 生成设计）
- 空天科技 - 太空碎片（展览信息设计）
- 芯片制造（ECharts 动态图表 + 立体图形）
- 可燃冰探测（多源数据融合展示）
- 基因检测（3D 建模 + 信息可视化图表）
- 智能网联汽车（交互网页 + 科普动画）
- 核能源（H5 交互问答 + 信息科普）

### 共性设计策略
1. **调研先行**: 每组先做系统的信息架构思维导图
2. **多媒介融合**: 静态展板 + 动态视频 + 交互网页
3. **科普化表达**: 将专业术语转化为视觉隐喻和卡通化表达
4. **数据可视化**: 核心数据用 ECharts/花火等工具生成动态图表
5. **受众定位明确**: 每组都有清晰的目标人群定义

## 自然语言工程分层策略

面对宏大项目，不能一次性向 AI 提出所有需求。应当分层拆解：

1. **数据层**: 先让 AI 生成干净的 JSON/CSV
2. **组件层**: 再让 AI 生成孤立的静态可视化组件（D3/ECharts 单图表）
3. **外壳层**: 建立干净的空 HTML 外壳并插入 ScrollTrigger
4. **集成层**: 将组件放入外壳，打通交互 API

> **反面**: "帮我写个关于全球变暖的网络滚动叙事系统" → 幻觉代码、不可控产出

## Critique 互评方法论

### 互评聚焦维度
1. **嵌套模型合规**: 四层是否都有对应策略？有无跳层？
2. **数据断档检测**: 逻辑栈中是否有某个节点缺乏数据支撑？
3. **通道编码审查**: 映射选择是否有歧义？色阶是否合理？
4. **可行性评估**: 技术栈是否能在剩余课时内完成？

### 互评流程
1. 将自然语言逻辑栈挂在共享屏幕
2. 同学按"挑刺"心态逐层审查
3. 记录关键质疑点 → 作为迭代改进输入
