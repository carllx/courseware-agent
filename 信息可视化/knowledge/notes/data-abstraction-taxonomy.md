# 数据抽象分类体系 (Data Abstraction Taxonomy)

> 来源：Munzner Ch2 "What: Data Abstraction"
> 认知目标：理解数据类型、数据集类型和属性类型的完整分类框架

## 核心概念

数据抽象是可视化设计的第一步——在动手画任何图之前，你必须先回答"我的数据是什么？"。Munzner 将这个问题拆解为三层：

### 层级一：五种基本数据类型 (Data Types)

| 类型 | 定义 | 例子 |
|:---|:---|:---|
| Item（项） | 离散的个体实体 | 表中的一行、网络中的节点 |
| Attribute（属性） | 可测量/观察/记录的性质 | 薪资、温度、蛋白表达 |
| Link（链接） | 项之间的关系 | 社交网络中的好友关系 |
| Position（位置） | 2D/3D 空间坐标 | 经纬度、医学扫描坐标 |
| Grid（网格） | 连续数据的采样策略 | 均匀网格、非均匀网格 |

### 层级二：四种基本数据集类型 (Dataset Types)

1. **表 (Tables)**：行=项，列=属性，交叉=值。分简单平表和多维表。
2. **网络 (Networks)**：节点+链接。特例：树（无环，每个子节点只有一个父节点）。
3. **场 (Fields)**：基于空间网格采样的连续数据。标量场/向量场/张量场。
4. **几何 (Geometry)**：仅含空间位置信息的形状数据。

> **关键区分**：表和网络是**离散数据**（有限个体），场是**连续数据**（需要插值）。
> 这个区分直接决定了后续的编码选择。

### 层级三：属性类型 (Attribute Types)

```
属性类型
├── 分类型 (Categorical) ← 只能判断"同/异"，如水果名称、电影类型
└── 有序型 (Ordered)
    ├── 序数型 (Ordinal) ← 有顺序但不能做算术，如 T恤尺码 S < M < L
    └── 量化型 (Quantitative) ← 支持算术比较，如身高 68-42=26 英寸
```

有序属性的方向：
- **顺序型 (Sequential)**：从最小到最大的单调范围
- **发散型 (Diverging)**：从零点向两个方向延伸（如海拔 = 山高 + 海深）
- **周期型 (Cyclic)**：值会回绕到起点（如一天24小时、一周7天）

## Key vs Value 语义

| 语义角色 | 定义 | 别名 |
|:---|:---|:---|
| Key（键） | 用于检索的索引属性 | 自变量、独立变量、维度 |
| Value（值） | 被检索的度量属性 | 因变量、依赖变量、度量 |

- **平表**：一个键（行号），多个值属性
- **多维表**：多个键组合唯一标识一个项（如 基因 × 时间点 → 活性值）
- **场**：空间位置作为量化键

> ⚠️ **反面教训**：邮政编码 100001 看起来像数字，但它是分类型——对两个邮编做加法毫无意义！
> 语义(semantics)和类型(types)是交叉正交的，不能仅从外观推断。

## 教学锚点

- **DMA 学生易犯错误**：把所有数字都当量化型处理，忽略了"编号≠数量"的区分
- **实操对接**：当向 AI 描述数据时，必须同时说明数据类型 + 语义角色 + 属性类型，否则 AI 无法正确建模
