# 任务抽象框架 (Task Abstraction Framework)

> 来源：Munzner Ch3 "Why: Task Abstraction"
> 认知目标：掌握 Analyze-Search-Query 三层行为框架，理解 Derive 的战略价值

## 为什么要做任务抽象？

用户总是用领域特定语言描述需求：
- 流行病学家："对比 ICU 插管超过一个月的患者与一周内住院患者的预后"
- 生物学家："看看 LL-37 处理过的组织样本与未处理的是否吻合"

**翻译后**：两个任务本质相同——"比较两组之间的值"。

任务抽象的目的，是用一套**通用词汇**（动词=行为，名词=目标）来剥离领域术语，让设计决策可以跨领域复用。

## 三层行为框架 (Actions)

### 高层：Analyze（分析意图）

| 类型 | 含义 | 典型场景 |
|:---|:---|:---|
| **Consume → Discover** | 发现未知知识（生成/验证假设） | 探索性数据分析 |
| **Consume → Present** | 传递已知信息（讲故事） | 新闻信息图、汇报演示 |
| **Consume → Enjoy** | 休闲兴趣驱动 | 名字流行度工具 |
| **Produce → Annotate** | 给可视化元素加标注 | 圈出聚类并标签 |
| **Produce → Record** | 保存可视化制品 | 截图、参数存档 |
| **Produce → Derive** | 基于现有数据创造新数据 | 派生属性、类型转换 |

### 中层：Search（搜索策略）

| | 目标已知 | 目标未知 |
|:---|:---|:---|
| **位置已知** | Lookup（查找） | Browse（浏览） |
| **位置未知** | Locate（定位） | Explore（探索） |

### 低层：Query（查询范围）

- **Identify**：查询单个目标（如：加州的选举结果是什么？）
- **Compare**：比较多个目标（如：加州和得州的选举结果对比）
- **Summarize**：概览全部目标（如：全国多少州支持候选人 A？）

## 目标 (Targets)

| 目标类别 | 适用数据 | 示例 |
|:---|:---|:---|
| Trends / Outliers / Features | 全部数据 | 趋势、异常值、特征结构 |
| Distribution / Extremes | 单属性 | 值的分布、最大最小值 |
| Dependency / Correlation / Similarity | 多属性 | 属性间依赖/相关/相似关系 |
| Topology / Paths | 网络数据 | 网络拓扑结构、节点间路径 |
| Shape | 空间数据 | 几何形状理解 |

## Derive（派生）的战略价值

**核心洞见**：不要只画你拿到的数据——思考"什么才是该展示的东西"，用一系列转换从原始数据创造出那个东西，然后画它。

经典案例：
- **贸易平衡**：原始属性(进口, 出口) → 派生属性(差值) → 直接编码差值曲线
- **Strahler 数**：计算树节点的重要性 → 过滤掉边缘节点 → 50万节点树只画5000个关键骨架
- **流体力学**：原始空间场 → 派生出涡度/熵/焓等属性 → 在派生空间中发现隐藏结构

> ⚠️ **反面**：如果直接画原始数据而不做任何 Derive，复杂数据集几乎不可能产生有意义的洞察。
>「数据抽象是设计者的主动选择，而非数据本身的被动承载。」
