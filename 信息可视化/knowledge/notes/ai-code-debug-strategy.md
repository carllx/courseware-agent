# AI 辅助代码排错策略

**知识节点**: `ai-code-debug-strategy`
**认知目标**: 掌握在 Vibe Coding 工作流中，当 AI 生成的可视化代码出错时，系统化排错的方法论和结构化 Prompt 技巧

---

## 1. 为什么 AI 代码需要排错？

在 Vibe Coding 范式中，代码生成的速度极快，但准确率并非 100%。根据实践经验，AI 生成的前端可视化代码在以下场景中错误率显著偏高：

- **D3.js 代码**：坐标系/比例尺/数据绑定的组合复杂度高，约 40-60% 的首次生成需要修正
- **跨框架配合**：当同一页面混合使用 ECharts + D3 + 自定义 CSS 时
- **非标准图表形态**：水滴、气泡轨迹、不规则多边形等超出常规模板库的形态

核心认知：**AI 不怕你给它报错，它怕你给它无效信息。**

## 2. 三层排错漏斗

### Layer 1: Console 信息精确复制

这是最基础但也最被忽略的一步。当页面空白或图表变形时：

1. 打开浏览器开发者工具（F12 → Console）
2. **原样复制**红色错误信息的**前 3 行**
3. 将错误文本粘贴到 AI 对话框中

**反面**：千万不要只写"代码报错了"或者"图画不出来"。这等于去医院跟医生说"我不舒服"——医生无法开药。

### Layer 2: 上下文定位法

当 Console 没有明确报错（常见于"画出来了但位置不对"），使用结构化描述：

```
问题描述模板：
1. 预期行为：[我希望柱状图从底部向上生长，X 轴显示月份]
2. 实际行为：[柱状图从顶部向下悬挂，X 轴标签被截断]
3. 可疑区域：[我怀疑是 yScale 的 range 设置方向反了]
4. 附加代码：[贴出 scale 定义和 rect 绑定的代码段]
```

### Layer 3: 最小可复现示例 (MRE)

当前两层无法解决问题时，使用削减策略：

1. 将数据缩减为 3-5 行
2. 删除所有装饰性样式（tooltip, animation, theme）
3. 只保留核心的"数据→画布→标记"管线
4. 将这个精简版本发送给 AI

**原理**：大模型的注意力窗口有限。代码越长，它越容易"看走眼"。把几百行代码精简到 30 行，命中率翻倍。

## 3. D3 排错检查清单

当 AI 生成的 D3 代码不工作时，按照以下顺序排查：

| 排查顺序 | 检查项 | 具体操作 |
|:---|:---|:---|
| ① | SVG 容器是否可见 | 检查 width/height 是否 > 0，检查 CSS 有无 `display: none` |
| ② | 数据是否正确加载 | 在 `d3.csv()` 回调中 `console.log(data)` 确认结构 |
| ③ | Scale 的 domain/range | `console.log(scale.domain(), scale.range())` 确认范围合理 |
| ④ | 数据绑定是否成功 | 检查 `selectAll().data()` 后的 enter selection 长度 |
| ⑤ | 坐标是否越界 | 检查 `attr("x")` 和 `attr("y")` 的返回值是否在画布范围内 |

## 4. ECharts 排错检查清单

| 排查顺序 | 检查项 | 具体操作 |
|:---|:---|:---|
| ① | 容器 DOM 是否存在 | 确认 `document.getElementById()` 不返回 null |
| ② | option 对象合法性 | 在 console 中 `JSON.stringify(option)` 检查格式 |
| ③ | 数据格式匹配 | series.data 是否为数组形式，而非嵌套对象 |
| ④ | CDN 加载 | 确认 ECharts 库文件加载成功（检查 Network 面板） |

## 5. 迭代修正 Prompt 的策略

向 AI 提交修正请求时的黄金法则：

- **锚定出错行号**："第 47 行的 `yScale.range()` 返回值为 `[0, NaN]`，请修正为……"
- **限定修改范围**："请只修改 Scale 相关的 3 行代码，其余部分保持不变"
- **附加测试条件**："修改后，第一个柱子的 y 坐标应约为 250px（屏幕中部）"

**反面**："不行，重新给我写一份完整代码"——这是最低效的排错方式。每次全量重写都会引入新的、不同的错误，形成无限循环。
