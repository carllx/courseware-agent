# 逐字稿复盘矫正 — 快捷指令集（v2）

> **使用方式**：每个指令块独立使用，复制粘贴到新对话中执行。
> **推荐顺序**：深度审查 → Quiz 补全 → 叙事拓展(可选) → 视觉全链路 → Audit 终验
> **架构**：三阶段流水线 — Phase A 内容手术 → Phase B 视觉装配 → Phase C 验收发布

## 📌 当前工作目标（每轮复盘开始前更新）

> **使用前必做**：将下方的 `{COURSE_WEEK_SRC}` 替换为实际路径后再复制。
> 例如 {COURSE_WEEK_SRC} = 课程/weeks/W XX_XXXXX/src

---

## ⚠️ 通用行动纪律（所有指令块默认继承）

以下 4 条纪律适用于下方所有指令块，无需每次重复粘贴：
1. **单步阻断与审批**：**逐个模块**执行。针对每一个模块，必须先输出诊断报告或修复计划，在遇到核心修改时停下来等待我的"批准指令"，才能执行后续修改操作。
2. **显式修改痕迹（防静默黑盒）**：执行文本修复时，**必须**优先使用你原生的文件编辑 API（`multi_replace_file_content` 等），**绝对禁止**擅自编写 Python 脚本或使用 `sed/cat` 终端命令静默修改源文件，以确保我在 IDE 中能直观看到 Diff 对比。
3. **全局状态机追踪**：在开始前，创建一个全局的 `task.md` 待办清单，详细追踪每一个模块的处理状态，每完成一步打一个 `[x]`。
4. **残留物管控**：任务中如需使用临时脚本（如诊断脚本），必须将脚本写入 `scratch/` 或 artifact 目录，**绝对禁止**将临时文件写入教学 `src/` 源码目录。

## Phase A — 内容手术（Text）

> **阶段目标**：所有涉及文字修改的工作在此阶段完成（审查 + 修复 + Quiz + 叙事），避免后续视觉步骤因文字变更而返工。

### 步骤一：全维度深度审查

> **合并了** /review + /memory_optimize + Quiz 诊断。只读一次脚本，一次性产出所有维度的统一诊断报告。


```
/review + /memory_optimize + Quiz 诊断. 
制定详尽的任务和计划，为 
[{COURSE_WEEK_SRC}] == `交互产品开发/weeks/W04_MVP_Hypothesis/src` 
目录下的每一个教学模块，**逐个模块**执行全维度深度审查。

每个模块按以下**三阶段**执行（禁止跳步）：

**阶段 1 — 自动化扫描（机器先行）**
在人工阅读之前，必须先跑以下 3 个脚本获取量化基线：
- `validate_script_length.py --module-breakdown`：字数/视觉密度/退化检测
- `generate_cheat_sheet.py "<脚本路径>" --diagnose`：IAR 段落推进 + 骨架链 + 锚词
- `validate_visual_text_sync.py`：Bullet Sync + Text 覆盖率

**阶段 2 — 宏观审查（先结构后细节）**
读取模块脚本，执行以下维度（可用 `--focus structure` 聚焦此阶段）：
1. **R1 Mayer 一致性**：扫描人文标签块的教学目标对齐
2. **R2 论证饱和度**：同一论证骨架 ≥3 次 → `[PATTERN_SATURATION]`
3. **R3 + M1 骨架逻辑与标题锚点**（合并）：H3 断言句检查 + 因果链测试 + 四字要旨测试 + 角色代入测试
4. **Rosenshine 检查点 + Quiz 缺口诊断**（合并）：计算相邻 ACTIVITY 间距，>3000 字标记 `[MISSING_CHECKPOINT]`，同时标注建议的 Quiz 插入位置

**阶段 3 — 微观审查（结构稳定后执行）**
对通过宏观审查的模块继续（可用 `--focus detail` 聚焦此阶段）：
5. **R4 PCK 三层诊断**：术语层/逻辑层/图式层
6. **R5 + M5 段落精简与负荷**（合并）：Plain Language + 段落物理负荷
7. **R5b LLM 隐性膨胀**：七子模式扫描 + 压缩比测试
8. **M2 + Deep Listen 冷热心流**（合并）：骨架冷热标注 + 论证多样性 + 费曼导演视角 + 记忆精度分层
9. **M3 过渡焊接**：禁忌过渡 + 逻辑因果桥检查
10. **M6 锚词故事线**：灵魂关键词提取 + 逻辑连贯性
11. **R6 事实快检**：理论归因 + 案例时效性

**产出**：每模块一份统一诊断报告（取代原来的 Review L1 + Memory 诊断 + Quiz 诊断三份独立报告）。

补充约束：
- **修复审批**：诊断报告呈交我审阅，批准后才可执行物理修改。
- **注意力分压**：如果单模块字数 >5000 字且诊断维度过多，可分两轮执行（`--focus structure` 先行 → `--focus detail` 后续），但**每轮都必须产出完整的分阶段报告**。
- 继承 ⚠️ 通用行动纪律全部 4 条。

```

### 步骤四：视觉全链路

> **合并了**视觉间隔诊断 + 教材匹配 + AI 文生图 + 真实素材采购。一条管线走完，避免跨对话丢失诊断上下文。
> **前置条件**：Phase A 的所有文字修改已完成。

```
针对当前工作区，为
[{COURSE_WEEK_SRC}] == `交互产品开发/weeks/W04_MVP_Hypothesis/src`
目录下的每一个教学模块，执行视觉素材的全链路诊断与补全。

按以下 **4 个子阶段**严格顺序执行：

**子阶段 4.1 — 物理层盘点 + 密度诊断**
- **绝对禁止**仅凭肉眼阅读来统计缺失素材。
- **第一步动作**：编写并执行一段 Python 扫描脚本（写入 `scratch/`，禁止写入 `src/`）：
  - 遍历 `src/` 目录下所有 `M*.md`，正则提取全部 `[VISUAL]` 块的 Slide ID、Scene、Asset 路径
  - 用 `os.path.exists()` 验证资产文件物理存在性，`< 15KB` 的视为空壳占位
  - 相邻 VISUAL 间距 >360 字的标记 `[VISUAL_GAP]`
- **产出**：《未就绪资产清单》+ 《视觉间隔缺口清单》

**子阶段 4.2 — 教材库优先匹配**
- 检查 `knowledge/textbook/` 是否存在已转换教材。若无 → 跳过。
- 按 `/sync_textbook_visuals` 工作流逐图审阅，将匹配项标记为 `textbook` 并执行迁移。
- 已匹配的 Slide **不再进入后续生成流程**。

**子阶段 4.3 — 资产分类 + 审批触发**
将子阶段 4.1 的未就绪清单按 Scene 强制分为两类：
- **【A类：需 AI 生成】**：抽象模型、概念隐喻、理论图表底图
- **【B类：需真实素材】**：真实案例、APP 截图、人物照片、视频切片。**禁止用 AI 文生图替代。**
- 输出含 A/B 分类的 Implementation Plan 供我审阅。
- ⚠️ **门禁点**：必须等待我的明确批准。

**子阶段 4.4 — 执行生成与采购**
批准后，对 **A 类**执行：
- **风格防呆检查（不可跳过）**：生图之前必须读取 `course.yaml` 的 `visual_system` + `rule_visual_generation.md` + 对应 `theme_*.yaml`。**未完成读取禁止开始生图。**
- 批量生成，>30 张分批并发防限流。
- 生成后落盘 + Markdown 链接注入。
对 **B 类**执行：
- 引导使用 `/source_images` 或 `/source_videos` 工作流逐条处理。
- 如 B 类数量较多，整理为候选确认清单供我审批后批量下载。

补充约束：
- **防堆叠碰撞检测**：新 `[VISUAL]` 块插入前，必须检查双向间距 ≥80 字叙事文本。详见 `rule_visual_placement.md`。
- **资产路径合规**：产物必须写入周次级 `public/` 目录。详见 `rule_asset_placement_guard.md`。
- 继承 ⚠️ 通用行动纪律全部 4 条。
```
