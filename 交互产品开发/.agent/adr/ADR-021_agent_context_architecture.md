# ADR-021: Agent 上下文架构——解决 Token 溢出连锁问题

> **状态**: Phase 1 已实施 ✅ / Phase 2-3 待启动  
> **日期**: 2026-03-06  
> **决策方**: 课程工作区 Agent + 教务材料 Agent + 用户联合评审  
> **关联**: MSG-021, ADR-020 (模块字数预算)

---

## 问题描述

W01 脚本审计修复中连续触发 Token 溢出（204K > 200K 限制），根因是 **Agent 驱动课程开发架构与 LLM 上下文窗口之间的系统性矛盾**。

核心数据：
- W01 脚本 83KB + `course.yaml` 全量 51KB = 134KB，已占 200K 预算的 67%
- `/audit --deep` 场景的最差组合达 ~190KB+，加上对话历史即溢出
- W02-W14 完成写作扩展后（预计 40-70KB/份），溢出将变为常态

## 决策

采用 **组合式渐进架构**，分 4 阶段实施：

### Phase 1：YAML 运行时按需提取（立即实施）

| 项 | 内容 |
|:--|:--|
| **做什么** | 创建 `extract_week.py` 脚本，运行时从 `course.yaml` 精确提取指定周的 section 输出到 stdout |
| **Token 降幅** | -46KB（51KB → ~2-5KB/周） |
| **教务端影响** | 零。`course.yaml` 原文件不动，无派生文件，不存在同步问题 |
| **新工件** | 仅 1 个脚本：`extract_week.py`（使用 PyYAML `safe_load`） |
| **优势** | 零同步开销、100% 数据一致性（单一数据源）、无 14 个派生文件需维护 |

### Phase 2：脚本分层视图（中期）

| 项 | 内容 |
|:--|:--|
| **做什么** | 每份脚本自动生成模块级摘要文件 `script_summaries/W{N}_summary.md` |
| **Token 降幅** | -50~60KB（83KB → 20-30KB） |
| **保真要求** | 保留所有交叉引用锚点、过渡段首句、案例名称 |
| **新工件** | `scripts/script_summaries/` 目录 + `generate_summary.py` 脚本 |

### Phase 3：审计子任务并行（中期）

| 项 | 内容 |
|:--|:--|
| **做什么** | `/audit` Standard 拆为 Part A-E 五个独立子 Agent 任务 |
| **Token 降幅** | -30%（每个子任务 ~100KB） |
| **新工件** | `audit.md` 工作流增加子任务编排逻辑 |

### Phase 4：知识库 RAG（远期暂缓）

暂缓。待知识库扩展至 200+ 条目时启用。

## 效果预估

| 场景 | 当前 | Phase 1 | Phase 1+2 | Phase 1+2+3 |
|:--|:--|:--|:--|:--|
| `/audit` Standard (W01) | ~145KB | **~100KB** ✅ | ~55KB ✅ | ~40KB/子 ✅ |
| `/write` (W01) | ~120KB | **~75KB** ✅ | ~45KB ✅ | ~45KB ✅ |
| `/audit --deep` (W01) | **~190KB** ⛔ | **~145KB** ✅ | ~100KB ✅ | ~65KB/子 ✅ |

> **结论**：仅 Phase 1 即可解决当前溢出。Phase 2-3 为 W02-W14 扩展提供长期余量。

## 方案否决记录

| 被否决方案 | 原因 |
|:--|:--|
| 直接拆分 `course.yaml` 原文件 | 教务端生成器依赖完整 YAML 跨周引用，拆开导致生成器崩溃 |
| 静态派生 14 个周级 YAML + 同步脚本 | 引入不必要的同步维护层，增加数据不一致风险。运行时提取方案效果相同且零开销 |
| 按模块拆分脚本文件 | 模块间存在叙事弧线和交叉引用，拆开丧失全局叙事视野 |
| 全栈 RAG 替代所有加载 | 当前知识库体量 ROI 不高（72 条目），引入向量 DB 复杂性过大 |
| 仅依赖更大上下文窗口模型 | 模型升级不可控，且更大窗口≠更好的"中间信息"召回 |

## 迁移计划

### Phase 1 迁移步骤（预计 1 个对话周期）

1. 创建 `extract_week.py`（PyYAML），支持 `--week N` 参数，输出 calendar[N] + objectives 子集
2. 验证提取输出的正确性：对比 W01-W14 的提取结果与原文件
3. 修改 `/write` 和 `/audit` 工作流：将「加载 course.yaml 全文」改为「`run_command: python extract_week.py --week N`」
4. 教务端零影响——`course.yaml` 原文件不变，生成器无需回归测试
