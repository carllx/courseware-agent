# AI 代码生成的约束边界

> **来源**: 综合调研 — TechRadar, Dark Reading, Keywords Studios, Red Hat, Medium 等 (2024-2025)
> **关联**: W09 Module 3

## 核心论点

AI 代码生成工具（v0, Cursor, Copilot 等）**不是万能的代码工厂**。它们有明确的能力边界和系统性失败模式。设计师/开发者必须理解这些边界，才能在 Vibe Coding 工作流中有效协作而非盲目依赖。

## 六大约束边界

### 1. 可靠性陷阱 (Reliability Trap)

- 2024 年数据：36% 的开发者报告 AI 生成代码的可靠性问题
- Copilot 使用者的代码 Bug 率比非使用者**高 41%**
- "AI 债务 (AI Debt)"：快速部署的 AI 代码产生的隐性审查与优化成本，蚕食了初始效率收益

### 2. 安全盲区 (Security Blind Spots)

- 2024-2025 研究：48%-59% 的 AI 生成代码片段含有安全漏洞
- AI 倾向于让代码"能跑"，而非"安全"
- 约 40% 的 AI 代码嵌入了不安全默认值和配置错误
- **对设计师的启示**：AI 生成的前端代码可能包含 XSS 注入点、未消毒的输入处理

### 3. 上下文盲区 (Context Blindness)

- AI 生成的代码在**孤立环境下工作正常**，但集成到大型系统时可能失败
- "幻觉 (Hallucination)"：AI 可能建议不存在的包名或错误的 API 调用
- **对设计师的启示**：不要指望 AI 理解你整个项目的架构，每次交互只是局部对话

### 4. "差不多对" 陷阱 (The "Almost Right" Trap)

- AI 生成的代码可能**编译通过但逻辑错误**
- 调试这类代码比从头编写更耗时
- 细微逻辑错误只在生产环境或边界条件下暴露
- **对设计师的启示**：生成物必须逐一测试，不能因为"看起来对"就发布

### 5. 架构性债务 (Architectural Debt)

- Vibe Coding 擅长生成**孤立组件**，但拙于构建**连贯系统**
- 生成代码常缺乏结构、测试和长期可维护性
- 产出"意大利面逻辑 (Spaghetti Logic)"——函数纠缠、职责不清
- **对设计师的启示**：AI 能帮你画出单个页面，但"页面之间怎么连"需要你自己设计

### 6. 功能闪烁 (Functionality Flickering)

- 当 Prompt 中有未指定的细节时，AI 会**自行填充但不一致**
- 同一个元素在不同生成轮次中行为可能不同
- **对设计师的启示**：Prompt 越精确，闪烁越少；模糊的"帮我做个按钮"会得到每次不同的按钮

## 人机职责边界矩阵

| 维度 | AI 擅长 | 人类必须做 |
|:---|:---|:---|
| **组件生成** | 单个 UI 组件的代码实现 | 组件间的关系和一致性 |
| **样式实现** | 将 Token 值转化为 CSS | 视觉审美判断和品牌一致性 |
| **状态管理** | 简单状态切换 | 复杂业务逻辑和边界条件 |
| **响应式** | 基础断点适配 | 极端尺寸和异常内容适配 |
| **可访问性** | 基础 ARIA 标签 | 语义正确性和键盘导航完整性 |
| **测试** | 单元测试模板 | 集成测试和真实场景验收 |

## 设计师的"检修清单"

每次 AI 生成代码后，设计师必须逐项检查：

1. ☐ **视觉保真度** — 生成结果与设计稿是否吻合？间距/颜色/字体有没有偏差？
2. ☐ **状态完整性** — 所有状态变体（空态/加载/错误/禁用）都有吗？
3. ☐ **响应式适配** — 缩放到最小/最大宽度时有没有溢出或断裂？
4. ☐ **交互一致性** — hover/click/focus 的行为和设计稿一致吗？
5. ☐ **代码可读性** — 变量名和组件名有语义吗？还是一堆 div1/div2？
6. ☐ **无幻觉** — 有没有引入不存在的依赖包或 API？

## 教学定位

在本课程的DMA学生群体中，**不要求学生具备修复 AI 代码 Bug 的能力**，但**必须具备识别和描述 Bug 的能力**。这决定了 W09 的教学重心是：

- ✅ 教：如何发现生成物中的视觉偏差、状态遗漏、交互断裂
- ✅ 教：如何用结构化语言向 AI 描述修复方向
- ❌ 不教：如何手动修改 React/CSS 源代码
