# UX 闭环故事叙事框架：前后旅程对比的叙事心法

**适用单元**: W14 — 数据复盘与作品库凝练  
**核心主题**: 如何将"测试→修复"的迭代过程，转化为一个有说服力的设计故事

---

## 一、为什么"前后对比"不够

初学者最常犯的错误是：做一张「Before / After」截图对比图，然后说"我修复了问题"。

这不是故事，这是档案。  
一个好的 UX 闭环叙事，必须回答三个问题：

1. **为什么是这个问题**？（发现路径与数据依据）
2. **你是怎么决定这么改的**？（设计决策逻辑）
3. **改了之后发生了什么**？（可量化的结果，哪怕是定性的反应）

---

## 二、叙事框架：三幕结构

参考好莱坞的三幕剧将你的设计旅程压缩成一个紧凑的故事弧线：

### 第一幕：铺设冲突（The Problem）
- 用**一句话**描述你的用户和他们的核心障碍
- 展示**研究证据**：Think-Aloud 的关键引语 + 严重度数据
- 关键工具：**用户旅程地图（Journey Map）的"情绪低谷"标注**

> 示例：「在测试中，5 名参与者中有 4 人无法在 30 秒内找到'收藏'入口，且均在该节点停止出声，皱眉」

### 第二幕：设计挣扎（The Process）
- 展示**你真实的思考过程**，包括被放弃的方案
- 解释关键的**设计决策权衡**（为什么选 A 而非 B）
- 关键工具：**草图/迭代截图的时间线展示**，不要只放最终版

> 错误示范：「我重新设计了导航栏」  
> 正确示范：「我考虑了三种方案：(1) 增加标签文字、(2) 改变图标位置、(3) 引入底部 Tab 导航。因为测试数据显示用户不是找不到图标，而是不确定图标含义，所以选择了方案一配合 Tooltip。」

### 第三幕：闭环结果（The Result）
- 展示**修复后的设计**（不只截图，要有交互录屏）
- 提供**可量化的改善数据**：任务完成率 / 错误次数 / SUS 分变化
- 最重要的：用一句话说明**你从这次迭代中学到了什么**

## 三、前后用户旅程对比图（Before/After Journey Map）

不是做两张图放在一起，而是做一张**双层旅程图**：

```
旅程阶段     | 打开应用 | 浏览内容 | 收藏商品 | 查看愿望单
─────────────┼─────────┼──────────┼──────────┼──────────
Before 情绪  |  😊      |  😐      |  😤      |  ✗ 放弃
After  情绪  |  😊      |  😊      |  😊      |  ✓ 完成
─────────────┼─────────┼──────────┼──────────┼──────────
修复点标注   |         |          | [图标加] |
              |         |          | [标签文字]|
```

这张图传递的核心信息：**设计干预，改变了情绪弧线的走势**。

---

## 四、叙事的度：精确胜过感人

在评估与复盘语境下，好的叙事必须"**精确**"而不是"**感人**"：

- ✅ 「修复后，任务 B（收藏商品）的完成率从 60% 提升至 100%」
- ✅ 「4 名测试参与者主动提到导航变得'清晰多了'」
- ❌ 「用户体验得到了很大的提升」（无量纲描述，毫无信息量）
