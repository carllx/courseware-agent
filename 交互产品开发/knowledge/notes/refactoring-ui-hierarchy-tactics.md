# 视觉层级实战策略 (Refactoring UI: Hierarchy Tactics)

> 来源: Refactoring UI (Wathan & Schoger, 2018) — ch09-ch13

## 1. 反向弱化强调 (Emphasize by De-emphasizing)

当主要元素不够突出时，不要继续加强它——**弱化与之竞争的元素**。

- 导航栏中激活项不够突出？→ 给非激活项更浅的颜色，让它们退到背景里
- 侧边栏与主内容区争夺注意力？→ 去掉侧边栏的背景色，让内容直接坐在页面背景上

核心洞察：强调是相对的，弱化竞争者 = 强调目标。

## 2. 标签后置原则 (Labels Are a Last Resort)

展示数据时，**标签不应是默认选择**：

1. **格式自解释**: `janedoe@example.com` 不需要"邮箱："标签；`$19.99` 不需要"价格："标签
2. **上下文自解释**: 员工目录中姓名下方的"Customer Support"，不需要"部门："前缀
3. **合并标签与数据**: "库存: 12" → "还剩 12 件"；"卧室: 3" → "3 间卧室"
4. **标签必须时降级处理**: 缩小字号、降低对比度、减轻字重——标签是支撑内容，数据才是主角
5. **例外——信息密集页**: 当用户在扫描标签而非数据时（如产品规格页），可强调标签

## 3. 视觉层级 ≠ 文档层级 (Separate Visual from Document Hierarchy)

- HTML 的 h1-h6 是**语义层级**，不等于**视觉层级**
- 页面标题（如"管理账户"）通常是**标签性质**——不应像 h1 默认样式那样巨大
- 内容才是焦点，标题应该小而低调
- 极端情况：标题在标记中保留（无障碍），但视觉上完全隐藏

原则：**选择元素基于语义，样式基于视觉层级需求。**

## 4. 权重与对比的跷跷板 (Balance Weight and Contrast)

粗体文字强调的本质是**表面积增大**。这一关系延伸到图标等元素：

- **图标太"重"→ 降低对比度**: 实心图标覆盖面积大，放在文字旁会抢戏。给图标更浅的颜色来平衡
- **边框太"轻"→ 增加宽度**: 1px 柔色边框太微弱？加宽到 2px 而非加深颜色

权重 ↔ 对比度是可互换的杠杆。

## 5. 语义让位层级 (Semantics Are Secondary)

按钮设计不能只看语义（主要/危险/成功），必须同时考虑**层级**：

- **主要操作**: 实心高对比背景 — 视觉最突出
- **次要操作**: 描边样式或低对比背景 — 清晰但不抢眼
- **三级操作**: 纯文本链接样式 — 可发现但不打扰

特别注意：**危险操作 ≠ 自动红色大按钮**。如果删除不是主要操作，应给它次要/三级处理，在确认步骤中才升级为主要样式。
