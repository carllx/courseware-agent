# Refactoring UI: 布局与间距系统

## 来源
Refactoring UI (Wathan & Schoger, 2018) — Layout and Spacing 章节 (ch14-19)

## 核心策略

### 1. 从"过多留白"开始，然后删减
- 多数设计师的习惯是给元素"最少够看"的间距。这导致界面拥挤。
- 正确做法：先给大量留白，再逐步收紧至舒适。
- 原因：独立看"太多"的间距，放到完整界面里往往恰到好处。
- 密集界面（如仪表盘）是例外，但应作为**有意识的决策**而非默认。

### 2. 建立间距与尺寸系统（Spacing System）
- **严禁**逐像素微调。应建立一套预定义的尺寸刻度。
- 线性等比（如"全部 4px 倍数"）不够用——小尺寸差异跨度大（12→16px = 33%），大尺寸差异跨度小（500→520px = 4%）。
- 推荐策略：以 **16px** 为基础值（浏览器默认字号），按几何级数扩展。相邻值之间差距 ≥ 25%。
- 实用刻度示例：4, 8, 12, 16, 24, 32, 48, 64, 96, 128

### 3. 不必填满整个屏幕
- 拥有 1400px 的屏幕不代表你的内容必须铺满 1400px。
- 如果内容只需要 600px，就用 600px。留白不是浪费，拉伸才是。
- 每个区域独立——导航栏全宽不意味着内容区也必须全宽。
- 实操：先设计 ~400px 手机端，再扩展到大屏。

### 4. 栅格不是宗教（Grids are Overrated）
- 12 列栅格是快捷工具，但不应盲从。
- 核心问题：栅格用**百分比**定义宽度，但很多元素应该用**固定宽度**。
  - 典型案例：侧边栏应固定 250px，主内容区才用剩余空间弹性扩展。
  - 如果侧边栏用 25% 栅格，屏幕变大时被拉宽反而浪费空间。
- 正确做法：给组件**它需要的宽度**（通常 `max-width`），仅在必要时收缩。

### 5. 相对尺寸不可依赖（Relative Sizing Doesn't Scale）
- 标题不应永远是正文的 2.5 倍——桌面端 2.5em 到手机端会变得过大。
- 大屏上大元素收缩速度应快于小元素——不同尺寸间的差距在小屏上应更小。
- 按钮的 padding 也不应等比缩放——大按钮需要更慷慨的 padding 才能"感觉大"。

### 6. 消除歧义间距（Avoid Ambiguous Spacing）
- 当分组元素间没有可视分隔（边框/背景色）时，间距是唯一的分组暗示。
- 表单的 label 下方间距 = input 下方间距 → 用户分不清 label 属于哪个 input。
- 规则：**组内间距 < 组间间距**。格式塔亲密性原则（Proximity）在此生效。

## 与 W06 课程的关联

这些策略构成了"从容器到组件"的设计约束层——学生在 Figma Auto Layout 中搭建响应式框架时，必须遵循间距系统和固定/弹性混合策略，才能生成可交付给 AI 编码工具的规范化设计。
