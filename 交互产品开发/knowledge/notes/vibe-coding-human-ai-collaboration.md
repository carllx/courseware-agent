# Vibe Coding: 人机协同架构法

> **来源**: 综合调研 — UX Tigers, LogRocket, UX Planet, Medium 等 (2024-2025)
> **关联**: W09 Module 1-2

## 核心概念

**Vibe Coding** 由 AI 研究者 Andrej Karpathy 于 2025 年初提出：开发者用自然语言描述期望结果（"vibe"），AI 负责生成绝大部分代码。其本质是**人机职责的重新分配**——人类从"写代码"转向"描述意图"。

## 工作流架构

### 经典 Vibe Coding 流程

1. **意图表达 (Intent Expression)** — 用结构化自然语言描述界面需求
2. **AI 生成 (Generation)** — 工具自动生成代码/组件
3. **即时预览 (Preview)** — 实时查看生成结果
4. **迭代修正 (Iteration)** — 用自然语言指示修改方向
5. **人工精修 (Refinement)** — 设计师/开发者介入细节调整

### 核心工具链

| 工具 | 定位 | 核心能力 |
|:---|:---|:---|
| **v0 (Vercel)** | UI 组件生成器 | 从自然语言生成 React + shadcn/ui 组件；已升级为 "agentic AI builder"，可自主规划、调试、构建全栈应用 |
| **Cursor AI** | AI 编码助手 | 接管 v0 生成的代码，修复错误、添加功能（API 集成、状态管理）、执行终端命令 |
| **CodeGeeX** | 国产代码助手 | 面向 VSCode/JetBrains 的多语言代码生成；适合国内教学场景 |

### v0 + Cursor 协同流

```
设计师意图 → v0 生成初始视图壳层 → Cursor 精修交互逻辑 → 部署预览
     ↑_____________ 迭代对话 ________________↓
```

## 对设计师角色的重塑

### 传统 vs Vibe Coding

| 维度 | 传统工作流 | Vibe Coding 工作流 |
|:---|:---|:---|
| 设计师输出 | 静态设计稿 + 标注 | 结构化 Prompt + Design Tokens |
| 开发者输入 | 手动解读设计稿 | AI 解读 Prompt |
| 迭代速度 | 天/周 | 分钟/小时 |
| 关键技能 | 工具操作 (Figma) | 意图表达 + 系统思维 |

### 设计师的新职责

- **不再**：逐像素标注、手动编写 CSS、反复与开发沟通标注细节
- **转向**：定义设计系统的逻辑规则、塑造 AI 对品牌决策的理解、设计"系统的系统"而非单个页面

## 与课程 Exp3 的对接

本课程 Exp3 的核心任务是：通过 v0 生成应用初始视图壳层。学生需要：

1. 将 Exp2 产出的 Design Tokens 和状态机转化为结构化 Prompt
2. 通过 v0 生成初始界面代码
3. 评估生成质量并迭代

> **关键约束**：DMA（数字媒体艺术）学生不具备系统性编程背景。Vibe Coding 的价值在于让他们**跨越前端工程门槛**，但必须同时建立对 AI 生成物的批判性审视能力。
