# Exp3 收尾兜底策略 (Demo Fallback Strategy)

> **来源**: Web 调研综合 (mixed-fidelity demo strategies, Figma fallback, 2024-2025) + Ch12 Construction
> **适用周次**: W11 逻辑排障与兜底策略

## 核心问题：AI 生成的代码跑不通了，怎么办？

在 Exp3（AI 原型与创意动效生成）收尾阶段，学生通过 v0/Cursor 生成的前端代码可能出现"状态断裂"——即部分页面可交互，部分页面崩溃或空白。这是 Vibe Coding 的常见结果。

**核心原则：Exp3 验收的是体验完整性，不是代码完美性。**

## 三级降级方案 (3-Level Degradation)

### Level 1：AI 自查修复 (10-15 min/bug)
- 使用 Read → Explain → Fix 三步法（见 `llm-code-reading-debugging.md`）
- 适用条件：错误信息明确、问题局部化、AI 3 轮内能修好
- **止损线**: 单个 bug 超过 15 分钟未解决 → 立即降级到 L2

### Level 2：Figma 热补丁 (Figma Hot Patch)
- **操作**: 在 Figma 中重建该"断裂状态"对应的页面，用高保真静态画面替代崩溃的代码页面
- **串联方式**: 在可交互的代码部分嵌入链接/按钮，点击后跳转到 Figma 原型的对应 Frame
- **优势**: 保持整体叙事流畅，评审者感知到完整的用户旅程
- **适用条件**: 断裂点 ≤ 3 个，且前后页面的代码部分正常

### Level 3：混合保真演示 (Mixed-Fidelity Demo)
- **操作**: 完全放弃试图让代码串联，改为"代码可交互部分 + Figma 原型串联不可交互部分"的**演示剧本**
- **演示结构**: 
  1. 用可工作的代码展示核心交互（真实操作）
  2. 切换到 Figma 原型展示其余状态（说明"这部分在设计中"）
  3. 整体用用户旅程叙事线串联
- **适用条件**: 代码断裂严重（>3 处）、或涉及跨页面状态管理崩溃

## 状态断裂修复操作指引

### Step 1: 状态审计
1. 打开你的应用状态流转图（W05 Exp2 产出）
2. 逐一测试每个状态转换：点击、输入、跳转
3. 标记三种状态：✅ 正常 / ⚠️ 异常但可用 / ❌ 崩溃

### Step 2: 断裂分类
| 断裂类型 | 表现 | 推荐降级 |
|:--|:--|:--|
| **路由断裂** | 点击跳转 → 白屏或 404 | L2: Figma 替换目标页 |
| **数据断裂** | 页面能打开但数据为空/乱码 | L1: AI 修复 fetch 逻辑 |
| **样式断裂** | 布局严重错乱不可用 | L1: AI 修复 CSS → 失败则 L2 |
| **交互断裂** | 按钮/动效不响应 | L1: AI 修复 → 失败则 L2 |
| **全局崩溃** | 整个应用无法启动 | L3: 切换到纯 Figma 演示 |

### Step 3: 修复或替换
按"影响面从大到小"排序处理：先修全局问题，再修局部问题。

### Step 4: 演示排练
- 在修复/替换完成后，**完整走一遍用户旅程**
- 记录每次切换点（代码→Figma→代码）的过渡话术
- 预备对评审者说明的"设计意图"——不是道歉，而是展示你的设计思维

## 心态调节

> **原型不是产品。** 你的 Exp3 产出是用来**验证设计假设**的工具，不是要交付到应用商店的软件。能用代码展示的用代码，不能的用 Figma——重要的是你的**设计决策**和**用户体验叙事**，不是代码能不能跑。
