# AI 驱动动效生成与 Prompt 工程

> **来源**: Web 调研（Vercel v0 文档 / 社区实践）
> **适用周次**: W10

## 1. v0 动效组件生成能力

Vercel v0 可以通过自然语言 Prompt 生成包含动画的 React 组件：

- **核心技术栈**: React + Tailwind CSS + shadcn/ui
- **动画库支持**: `framer-motion`（声明式组件动画）、`react-three-fiber`（3D 场景）
- **生成范围**: 按钮微交互、滚动动画、页面转场、粒子效果、加载状态

## 2. Prompt 工程最佳实践

### 2.1 明确指定动画库

```
❌ "创建一个有动画效果的卡片"
✅ "创建一个卡片组件，使用 framer-motion 实现：
    - 进入时从下方 fade-in + slide-up（spring 弹性,stiffness:100）
    - 悬停时轻微放大（scale:1.03）和阴影加深
    - 点击时缩小反馈（scale:0.98,duration:100ms）"
```

### 2.2 描述状态而非实现

```
❌ "设置 translateY 从 20px 到 0"
✅ "卡片从页面底部温柔浮入视野，像气泡一样带一点弹性"
```

### 2.3 约束边界

```
✅ "动画时长不超过 300ms，使用 ease-out 缓动，
    支持 prefers-reduced-motion 降级"
```

### 2.4 组合生成

```
✅ "为一个音乐播放器页面生成以下动效组件：
    1. 播放按钮：点击时从 ▶ 形变为 ⏸，带 morph 过渡
    2. 进度条：实时跟随播放进度，拖动时有弹性反馈
    3. 封面：播放时缓慢旋转（linear,20s/圈），暂停时停止"
```

## 3. 设计师 ← → AI 的协作边界

| 环节 | 设计师负责 | AI 代码助手负责 |
|:--|:--|:--|
| **动效意图** | 定义"为什么动"——用户在这里需要什么反馈 | — |
| **参数约束** | 定义时长范围、缓动类型、无障碍降级 | — |
| **代码生成** | — | 根据 Prompt 输出可运行代码 |
| **调优** | 观察效果、微调参数、判断是否过度 | 响应迭代 Prompt |
| **品质把关** | 检查帧率/性能/可及性 | — |

> **核心原则**: AI 生成的是初稿代码，设计师的工作是**编排与约束**——决定哪些地方"值得动"、哪些地方"不许动"。
