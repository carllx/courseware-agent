# 出声思考法方法论 (Think-Aloud Protocol)

> **来源**: Interaction Design Ch15 §15.2.1; Nielsen (1994); NN/g Best Practices  
> **适用周次**: W13 — 对话与可操作测试法

---

## 核心定义

出声思考法 (Think-Aloud Protocol) 是可用性测试中最广泛使用的定性方法之一。参与者在执行任务时，将其思维过程、困惑、决策理由和情绪反应**实时口语化**，使评估者得以窥探用户的心智模型运作过程。

Jakob Nielsen 称其为"可用性工程中最有价值的单一方法"——因为它直接暴露用户在操作时"脑子里在想什么"，而不是事后推测。

---

## 两种变体

### 并发出声思考 (Concurrent Think-Aloud, CTA)

- **定义**: 参与者在**执行任务的同时**口述想法
- **优势**: 实时捕捉思维过程，数据新鲜度最高
- **劣势**: 增加认知负荷，可能影响任务完成速度；部分操作（如高度视觉化搜索）边做边说很困难
- **适用**: 探索性可用性测试、早期原型评估

### 回溯出声思考 (Retrospective Think-Aloud, RTA)

- **定义**: 参与者先**沉默完成任务**，事后观看录屏回放时口述当时的想法
- **优势**: 不干扰自然行为，任务表现数据更纯净
- **劣势**: 记忆衰减（可能"合理化"而非真实回忆）；需要录制设备支持回放
- **适用**: 对任务完成时间敏感的测试、复杂操作流程评估

> **实践选择**: 业界偏好 CTA（更直接），学术研究偏好 RTA（数据更"干净"）。课堂场景推荐 CTA——因为无须录屏回放设备，操作门槛更低。

## 执行四要素

### 1. 任务设计 (Task Design)

- 任务必须模拟真实用户场景，不可过于抽象
- 每个任务应有明确的起点和终点（如"找到某个功能并完成操作"）
- 避免引导性任务描述（❌"点击左上角菜单" → ✅"找到你的账户设置"）

### 2. 指导语 (Briefing Script)

标准指导语应包含：
- "我们测试的是产品，不是你的能力"
- "请把脑子里想的都说出来——没有对错之分"
- "如果你沉默了，我可能会提醒你继续说"
- 示范环节：评估者可先用一个无关产品演示"出声思考"是什么样的

### 3. 记录方式 (Recording)

- **最低配置**: 手机录屏 + 外接小麦克风
- **标准配置**: 屏幕录制软件 + 面部摄像头 + 麦克风
- **专业配置**: Morae 等同步软件 + 眼动仪 + 观察室单面镜
- 课堂推荐：手机支架固定拍摄屏幕 + 观察员手写记录

### 4. 数据编码 (Data Coding)

- 将口述内容标注为：困惑、错误、期望不符、正向反馈、情绪爆发
- 常用编码框架：问题严重度（1=表面 / 2=轻微 / 3=严重 / 4=灾难性）
- 将问题映射回 Nielsen 十大启发式原则（承接 W12）

## 常见陷阱

| 陷阱 | 表现 | 应对 |
|:-----|:-----|:-----|
| **引导效应** | 评估者下意识给提示："试试那个按钮？" | 只用中性提示："你在想什么？" |
| **沉默应对** | 参与者专注操作忘记说话 | 约 15 秒沉默后轻声提醒 |
| **社交面具** | 参与者怕批评产品"不礼貌" | 强调"越多批评越有帮助" |
| **并发干扰** | CTA 中说话明显拖慢操作 | 切换为 RTA 或降低任务复杂度 |

## 经典案例：iPad 可用性测试 (Budiu & Nielsen, 2010)

- 7 名参与者在美国两个城市执行 60+ 任务
- 使用 CTA + 专家评估双轨方法
- 每次测试约 90 分钟，含自由探索 + 指定任务
- 核心发现：触屏目标区域过小、缺乏示能性 (Affordance)、导航迷失
- 该研究证明 7 人即可暴露大量关键可用性问题

> **教学启示**: 少量参与者 + 结构化 Think-Aloud = 高性价比的可用性发现引擎
